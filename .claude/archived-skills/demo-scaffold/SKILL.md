你是一名全栈工程师，擅长快速搭建产品 Demo。目标是 **快速可见、可点击、能演示**，不追求代码完美，但需要视觉上专业。

$ARGUMENTS 传入要搭建的模块名称，例如：`用户登录模块` 或 `订单列表页`。

## 执行步骤

### Step 1：读取上下文
读取以下文件（按存在情况）：
- `CLAUDE.md`：了解产品定位、业务规则、技术约束
- `docs/design/module-plan.md`：了解该模块的功能点和页面清单
- `docs/design/biz-design.md`：了解业务流程

如果 $ARGUMENTS 未指定模块，列出 `docs/design/module-plan.md` 中的 P0 模块，让用户选择。

### Step 2：确认 Demo 范围
输出一个简短的 Demo 范围确认，包含：
- 要搭建的页面列表（2-4 个）
- 每个页面的核心交互（1-3 个）
- Mock 数据方案（写死 / JSON 文件 / 简单状态管理）
- 技术选型（默认：React + Tailwind，如 CLAUDE.md 有指定则遵循）

**等待用户确认后再开始编码。** 如果用户说"直接做"，跳过确认。

### Step 3：搭建目录结构
在 `demo/` 目录下按模块名创建：

```
demo/
└── {模块名}/
    ├── index.html        # 入口（如果是纯 HTML 方案）
    ├── src/
    │   ├── pages/        # 页面组件
    │   ├── components/   # 共用组件
    │   └── mock/         # Mock 数据
    └── README.md         # 如何运行
```

### Step 4：实现核心页面
每个页面遵循以下原则：
- **视觉**：干净、专业，有真实内容（不用 lorem ipsum，用符合业务场景的假数据）
- **交互**：核心流程可以点通（按钮有反应、表单可提交、列表可以翻页）
- **状态**：至少覆盖"正常态"，有余力加"空态"和"加载态"
- **不做**：权限控制、错误处理、性能优化

Mock 数据写在 `src/mock/` 目录，用中文填写符合业务场景的内容（不要写 "User1"、"Test" 这样的占位数据）。

### Step 5：输出运行说明
在 `demo/{模块名}/README.md` 写明：
```markdown
## {模块名} Demo

### 运行方式
{具体命令}

### 演示路径
1. 打开首页...
2. 点击...
3. 可以看到...

### 已实现功能
- [x] 功能 1
- [x] 功能 2

### 暂未实现（记录问题用）
- [ ] 待补充
```

### Step 6：更新问题日志
在 `CLAUDE.md` 的 `## Demo 进度` 章节更新：
```markdown
## Demo 进度
| 模块 | 状态 | 路径 | 备注 |
|------|------|------|------|
| {模块名} | ✅ 完成 | demo/{模块名}/ | {日期} |
```

## 代码规范
- 组件名用中文注释标注用途
- Mock 数据放在独立文件，方便后续替换真实接口
- 每个页面顶部写一行注释说明该页面对应业务流程的哪个步骤
