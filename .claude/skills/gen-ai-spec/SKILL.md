# PRD → AI 结构化代码规格

将人类可读的 PRD 和详细设计文档，转换为 `md-figma-to-vue3` 技能可直接消费的 `md-template.md` 格式。

## 前置条件

- 已完成 `gen-prd`，即 `docs/prd/{模块}.md` 存在
- `docs/design/` 下存在对应模块的详细设计文档（推荐但非必须）
- `docs/design/biz-design.md` 和 `CLAUDE.md` 存在（用于获取产品上下文）

## 执行步骤

### Step 1：确认输入范围

`$ARGUMENTS` 传入模块名称（如 "维保计划模块"、"M5 维保计划"）。如未指定，列出 `docs/prd/` 和 `docs/design/` 中的可用模块让用户选择。

读取以下文件（按优先级）：
1. `docs/prd/{模块}.md` — 核心输入，结构化的 PRD
2. `docs/design/{编号}-{模块}模块详细设计.md` — 详细设计，含状态机、字段表、页面结构
3. `CLAUDE.md` — 产品定位、技术约束、业务规则
4. `docs/design/biz-design.md` — 业务流程（补充上下文）
5. `docs/design/module-plan.md` — 模块依赖关系

如果 PRD 不存在，提示用户先运行 `/gen-prd {模块}`。

### Step 2：拆解模块 → 页面

从 PRD 的「2.2 详细功能说明」和详细设计文档的章节标题中，识别该模块包含哪些页面/视图。

**页面识别规则**：
- PRD 中每个 `#### {功能点名称}` 通常对应一个页面或弹窗
- 详细设计中提到"列表""管理页""详情页""新增/编辑"的章节 → 独立页面
- 弹窗/抽屉类（新增、编辑、配置）→ 通常依附于列表页，但仍需独立输出一个 md-template

**页面类型判定（关键字匹配）**：

| 关键字 | 页面类型 |
|--------|---------|
| 列表、表格、管理、查询 | `列表管理` |
| 详情、查看、信息 | `详情展示` |
| 新增、编辑、配置、录入 | `表单提交` |
| 步骤、分步、多步骤、流程配置 | `表单提交`（标记为多步骤） |
| 统计、看板、仪表板、概览 | `统计看板` |
| 树、层级、分类 | `树形管理` |
| 流程、进度、时间线、处理记录 | `详情展示`（标记为含时间线） |

**输出页面清单**，让用户确认后再继续。格式：
```
识别到 {N} 个页面/视图：
1. 维保计划列表页 — 列表管理
2. 新增/编辑计划弹窗 — 表单提交（弹窗模式）
3. ...
确认？如需调整请说明。
```

### Step 3：逐页生成 md-template

对每个确认的页面，生成一个 `docs/ai-spec/{模块简称}/{页面简称}.md`，严格遵循 md-template 格式。

---

#### 各 Section 的生成规则

##### 一、页面元信息

| 字段 | 来源 |
|------|------|
| 页面名称 | 从 PRD 功能点名称 + 页面类型推断，如 "维保计划列表" |
| 所属模块 | `$ARGUMENTS` 传入的模块名 |
| 页面类型 | Step 2 判定结果 |
| 路由路径 | 推断：`/{module-slug}/{page-slug}`，如 `/maintenance-plan/list` |
| 功能描述 | 从 PRD「详细功能说明」提取一句话，**必须包含页面类型关键字** |

##### 二、页面结构

这是最关键的 Section。从 PRD 的「交互说明」「业务规则」和详细设计的页面 mockup / 区域描述中提取：

**步骤：**

1. **识别页面区域**：从 PRD 交互步骤（"用户看到…""页面显示…"）和详细设计的布局描述中，提取页面的视觉区域（从上到下）

2. **为每个区域确定组件类型**：

| 区域特征 | 注册表组件 | 位置 |
|---------|-----------|------|
| 搜索框 + 筛选下拉 + 查询按钮 | `FilterBar` | 顶部 |
| 批量操作按钮组（新增、删除、导出） | `ToolBar` | 顶部 |
| 数据表格（列 + 行 + 分页） | `DataTable` | 全宽 |
| 新增/编辑弹窗（≤6 字段） | `FormDialog` | 浮层 |
| 新增/编辑抽屉（>6 字段） | `FormDrawer` | 浮层（右侧） |
| 状态标签列 | `StatusTag` | 表格内 |
| 统计数字卡片 | `MetricCard` | 并排-N |
| 汇总区 | `SummaryCard` | 全宽 |
| 图表区 | `ChartCard` | 全宽 |
| 详情信息展示 | `InfoCard` | - |
| 详情页顶部摘要 | `DetailHeader` | 顶部 |
| 流程/时间线 | `ProcessTimeline` | 全宽 |
| 左侧树 + 右侧内容 | `el-tree` + 对应组件 | 左侧 260px |
| Tab 切换区 | `el-tabs` > `el-tab-pane` | Tab:xxx |
| 分页器 | `el-pagination` | 底部 |

3. **填充「包含元素」列**：描述该区域内具体的 UI 元素（字段名、按钮文案、表格列名等），用业务数据填充

4. **区域名称必须含注册表匹配关键字**：搜索筛选/操作栏/表格/弹窗/抽屉/指标卡/汇总/图表/详情信息/摘要/时间线

##### 三、数据模型

**3.1 实体字段**：从 PRD「3.2 字段说明」表格直接映射，或从详细设计的字段表中提取。

**3.2 状态枚举**：从 PRD「详细功能说明」的状态描述或详细设计的「状态机」章节提取。

- 每个状态值 → `{枚举值, 标签文字, 颜色类型, 说明}`
- **颜色类型启发式规则**：

| 状态语义 | 颜色类型 | 示例 |
|---------|---------|------|
| 待处理、待审核、草稿、未开始、未启用、待… | `info` | 待处理、待审核 |
| 进行中、执行中、处理中、已启用、生效中 | `warning` | 进行中、已启用 |
| 已完成、已审核、成功、通过、正常、已解决 | `success` | 已完成、已通过 |
| 已驳回、失败、异常、超期、逾期、拒绝 | `danger` | 已驳回、异常 |
| 已取消、已停用、已关闭、禁用、过期 | `normal` | 已取消、已停用 |

**3.3 表单字段**：从 PRD 字段说明中筛选出用户可编辑的字段，**添加控件类型**：

| 字段特征 | 控件类型 |
|---------|---------|
| 短文本（≤50 字）、名称、编号 | `input` |
| 长文本（>50 字）、描述、备注 | `textarea` |
| 枚举/选项/状态选择 | `select` |
| 日期/时间 | `date-picker` |
| 日期范围 | `date-range` |
| 布尔值/开关 | `switch` |
| 数字/金额/整数 | `input-number` |
| 文件/图片上传 | `upload` |

**3.4 表格列宽分配规则**：在 §二 页面结构的数据表格区域中，为每列标注宽度策略。

**核心原则：默认弹性均分，只有窄内容列固定宽度。**

| 内容类型 | 策略 | 典型宽度 | 示例 |
|---------|------|---------|------|
| 状态标签（StatusTag 2-4字） | 固定 | `calc(70 * var(--w))` | 在岗/迟到/待复核 |
| 标签/类型（3-4字） | 固定 | `calc(80 * var(--w))` | 到岗打卡/逾期未处置 |
| 短时间（HH:MM 格式） | 固定 | `calc(55 * var(--w))` | 08:30 |
| 短模式（2字） | 固定 | `calc(56 * var(--w))` | 有感/无感 |
| 截图画廊（64×40） | 固定 | `calc(70 * var(--w))` | 缩略图 |
| 操作按钮列 | 固定 | `calc(64 * var(--w))` | 2-3 个 link 按钮 |
| **其余所有列**（日期、姓名、时间戳、点位、位置、名称、备注、核验结果等） | **弹性（不设 width）** | — | 自动等分剩余空间 |

> 一张 7-8 列的表，固定列通常 2-4 个，弹性列 4-5 个。固定列是少数例外，弹性列是多数默认。

##### 四、查询参数

从 PRD「2.2 详细功能说明」的交互描述中提取筛选条件，或从详细设计的「查询参数」章节提取。

**查询参数数量限制**：不含 `page`/`size` 的查询参数 **≤ 5 个直接展示**。
若 PRD 中超过 5 个，自动分为两组：
- 直接展示（前 5 个高频参数，按 PRD 的"常用"层级标注）
- 折叠展示（其余，标注 `<!-- 折叠筛选 -->`，参数行尾加 `folded: true`）

每个筛选条件 → `{参数名, 中文名, 类型, 控件类型, 选项, folded?}`。始终包含 `page` 和 `size`。

##### 五、接口定义

从 PRD「4. 接口设计（概要）」表格直接提取，补充请求类型和响应类型（引用 §3 中定义的类型名）。

##### 六、业务逻辑

**6.1 状态流转**：从详细设计的「状态机」章节提取，转换为 Mermaid `stateDiagram-v2` 格式。如果详细设计用的是 ASCII 图，手动转换为 Mermaid。

**6.2 交互行为**：从 PRD「交互说明」的步骤列表提取，转换为标准表格：
```
| 操作 | 触发条件 | 行为描述 |
```

**6.3 特殊规则**：从 PRD「业务规则」列表直接提取。

##### 七、UI 组件分配

将 §二 中确定的每个区域映射到注册表组件，并标注关键 Props。

---

### Step 4：输出文件

为每个页面生成独立文件：

```
docs/ai-spec/{模块简称}/
├── README.md                  ← 页面索引
├── {页面1简称}.md             ← 如 维保计划列表.md
├── {页面2简称}.md             ← 如 新增编辑计划.md
└── ...
```

每个 `.md` 文件严格按 md-template 格式输出（见 `references/md-template.md`）。

README.md 索引格式：
```markdown
# {模块名} — AI 代码规格

| 页面 | 类型 | 文件 | 状态 |
|------|------|------|------|
| 维保计划列表 | 列表管理 | `维保计划列表.md` | ✅ 已生成 |
| 新增编辑计划 | 表单提交 | `新增编辑计划.md` | ✅ 已生成 |
```

### Step 5：给出下一步指引

输出摘要后，告诉用户：
```
下一步：
- 如有 Figma 设计稿：/md-figma-to-vue3 docs/ai-spec/{模块}/{页面}.md + Figma 链接
- 如无 Figma 设计稿：/md-figma-to-vue3 docs/ai-spec/{模块}/{页面}.md（仅基于 MD 生成）
- 如需调整规格：直接编辑 docs/ai-spec/{模块}/{页面}.md 后重新运行 md-figma-to-vue3
```

## 输出质量要求

- **每个区域名称必须包含注册表关键字**（搜索筛选/操作栏/数据表格/弹窗/抽屉/指标卡/汇总/图表/详情信息/摘要/时间线），否则 md-figma-to-vue3 的 4 维匹配会失败
- **状态颜色类型必须用标准值**：`success / warning / danger / info / normal`，不能用中文或自定义色
- **表单控件类型必须用标准值**：`input / select / date-picker / date-range / switch / textarea / upload / input-number`
- **接口路径用真实业务路径**，不要用 `{module}` 占位符
- **交互行为表必须完整**：覆盖列表页所有按钮、弹窗的打开/关闭/提交、删除确认等
- 如果 PRD 中某个 Section 信息不足（如没有状态机图），从详细设计文档补充；如果都没有，标注 `⚠️ 待补充` 而不是编造
- **生成前检查筛选与统计卡片重叠**：如果列表页同时有 `MetricCard`（统计卡片）和 `FilterBar` 中的状态下拉，且统计卡片已覆盖所有状态下拉的值，则筛选中**移除该状态下拉**（统计卡片点击 = 同效果，冗余）。在给用户的页面清单中标注此优化，确认后再生成。
