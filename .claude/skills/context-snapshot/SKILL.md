---
name: context-snapshot
description: 在长对话或跨 session 前，将当前工作状态压缩为结构化快照，写入 CLAUDE.md，确保下次 session 能快速恢复上下文。在每个工作阶段结束时使用。
when_to_use: 用户说"保存进度"、"记录一下当前状态"、"我要关掉了"、"下次继续"时使用。也可在 /compact 之前主动调用。
---

你是一名注重信息管理的产品经理，擅长将复杂的工作状态提炼为简洁、可恢复的快照。

## 执行步骤

### Step 1：盘点当前状态
读取以下内容：
- 当前对话的工作记录（在上下文中）
- `CLAUDE.md` 现有内容
- `docs/design/` 目录文件列表
- `docs/issues/` 目录文件列表
- `demo/` 目录结构

### Step 2：生成工作快照
输出以下结构的快照内容：

```markdown
## 工作快照
> 更新时间：{日期时间}

### 当前阶段
{Phase 1 业务设计 / Phase 2 Demo 开发 / Phase 3 问题完善 / Phase 4 文档输出}

### 已完成的工作
- [x] {已完成事项 1}（文档：{路径}）
- [x] {已完成事项 2}

### 进行中的工作
- [ ] {正在进行的事项}（下一步：{具体要做什么}）

### 待处理问题
（来自走查报告的未解决问题）
| 问题 | 模块 | 优先级 | 来源文件 |
|------|------|--------|---------|
| {问题描述} | {模块} | P0 | {文件路径} |

### 关键决策记录
（本 session 中做出的重要设计决策）
- **{决策标题}**：{决策内容}

### 下次开始的建议动作
1. {具体操作，如：运行 /update-spec 处理订单模块的 3 个 P0 问题}
2. {具体操作}

### 文件索引
| 文件 | 状态 | 说明 |
|------|------|------|
| `docs/design/biz-design.md` | ✅ 完整 | 业务设计文档 |
| `docs/design/module-plan.md` | ✅ 完整 | 模块规划 |
| `demo/用户模块/` | ✅ 完成 | 已走查 |
| `demo/订单模块/` | 🔧 开发中 | 50% 完成 |
| `docs/prd/` | ⏳ 未开始 | 待生成 |
```

### Step 3：更新 CLAUDE.md
将快照内容写入 `CLAUDE.md` 的 `## 工作快照` 章节（覆盖旧快照）。

`CLAUDE.md` 的完整结构应为：
```markdown
# {项目名} - 产品设计工作区

## 产品定位
{一句话}

## 业务设计
{关键规则，简洁版}

## 模块清单
{模块 + 优先级 + 状态}

## Demo 进度
{进度表格}

## 工作快照
{本次快照内容}
```

### Step 4：输出恢复提示
输出一段"下次如何快速恢复"的提示：

```
✅ 快照已保存到 CLAUDE.md

下次开始新 session 时，Claude Code 会自动读取 CLAUDE.md。
你可以直接说："继续上次的工作"，Claude 会根据快照告诉你应该从哪里开始。

或者直接运行：
- /update-spec 处理未解决的问题
- /demo-scaffold {下一个模块名} 继续 Demo 开发
- /gen-prd 生成已完善模块的 PRD
```
