# 增量修改引擎

你有某个业务域的设计文档变更了，需要把变更同步到已生成的代码中。你只修改受影响的代码，不动其他文件。

$ARGUMENTS 传入要更新的域名，例如：
- `维保管理`：对比该域 design.md 的变更
- `维保管理 "新增季度筛选"`：指明具体变更内容

---

## 核心原则

1. **设计文档是唯一锚点**：对比 design.md 变更 → 代码，不依赖聊天记忆
2. **先报告后执行**：必须让用户看到影响分析，确认再改
3. **最小修改**：只改受影响的文件和行，不动无关代码
4. **破坏性变更必标注**：删除字段、改表结构、改路由路径 → ⚠️ 标记

---

## 执行步骤

### Step 1：识别变更

1. 读取 `docs/{域名}/design.md`
2. 对比变更来源（按优先级）：
   - `git diff docs/{域名}/design.md`（最精确）
   - design.md 末尾的变更记录（§7）
   - 用户传入的变更描述（$ARGUMENTS）
3. 提取变更摘要，标注影响哪些 section

```
检测到以下变更：
§3 页面清单：新增"季度看板"页面
§4 数据模型：Plan 表新增 quarter 字段
§5 业务规则：新增"每季度最多 3 个计划"
```

### Step 2：影响分析

遍历该域相关的所有代码文件，判定每项变更的影响：

| 设计变更 | 影响文件 | 类型 | 风险 |
|---------|---------|------|------|
| Plan 表新增 quarter 字段 | `src/types/maintenance.ts` | 修改 | 低 |
| | `server/prisma/schema.prisma` | 修改 | 低 |
| | `src/api/adapters/maintenance-dao.ts` | 修改 | 低 |
| 新增"季度看板"页面 | `src/views/maintenance/QuarterBoard.vue` | 新增 | 低 |
| | `src/router/index.ts` | 修改 | 低 |
| 新增"每季度最多 3 个"规则 | `server/src/services/maintenance.service.ts` | 修改 | 中 |

**风险定义**：
- 🔴 高 = 破坏性变更（删字段/改表结构/改路由），可能影响已有数据或调用方
- 🟡 中 = 逻辑变更（新增校验规则、改业务逻辑）
- 🟢 低 = 新增内容（加字段/加页面/加接口），不影响已有功能

### Step 3：输出影响报告

**等待用户确认**。格式：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📐 {域名} 设计变更 → 代码影响报告
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

变更摘要：{一句话}

影响文件 {N} 个：
  🟢 新增 {X} 个 | 🟡 修改 {Y} 个 | 🔴 破坏性 {Z} 个

{逐文件列出}

⚠️ 破坏性变更需要确认：
  {如无破坏性变更，写"无"}

确认执行？如有调整请说明。
```

### Step 4：执行修改

用户确认后，逐个文件增量修改：

- **新增文件**：按 `/generate` 的模板生成，保持与已有代码风格一致
- **修改文件**：用 Edit 工具精确替换，不重写整个文件
- **TypeScript 类型**：新增字段加在接口末尾（保持兼容）
- **Prisma Schema**：新增字段用 `@default` 或标记 `?`（可选），避免破坏现有数据
- **路由**：在路由数组中追加，不动已有路由

### Step 5：验证

```
- npm run build (TypeScript 编译)
- 如有后端变更：cd server && npx prisma db push
- 列出修改摘要供用户 review
```

## 特殊场景处理

### 破坏性变更

如果变更涉及删除字段、改表结构、改路由路径：
1. 在影响报告中用 🔴 高亮
2. 列出受影响的已有数据和调用方
3. 提供迁移方案（如"建议先标记 deprecated，下一版本再删除"）
4. **必须用户明确确认**才能执行

### 跨域影响

如果变更影响多个业务域（如公共类型定义），扩展到全项目扫描，不只限于当前域。

### 只改了文案/说明

如果 design.md 只改了 §1、§2 等描述性内容，没有涉及数据/接口/页面：
```
✅ 检测到仅文档文案变更，不影响代码，无需修改。
```

## 与 /generate 的关系

| 场景 | 用哪个 |
|------|--------|
| 该域没有任何代码 | `/generate`（从零生成） |
| 已有代码，设计文档小改 | `/update`（增量修改） |
| 已有代码，设计文档大改（>50% 内容变化） | `/generate`（建议重新生成，成本更低） |
| 从 light 升级到 standard | `/generate --depth=standard --incremental` |
