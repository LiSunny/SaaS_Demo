# 工单详情抽屉 — 设计文档

---

## 一、页面元信息

| 项目 | 内容 |
|------|------|
| 页面名称 | `工单详情抽屉` / `工单详情页` |
| 所属模块 | `工单监控` |
| 页面类型 | `详情展示` |
| 路由路径 | 抽屉无独立路由；完整详情页 `/workflow/order/:id` |

### 功能描述

`工单运行时的详情展示，包含：`

- **抽屉模式**：从右侧滑出（720px），展示标题栏（StatusTag + 工单编号）、基本信息（左右两列 Grid）、SLA 指标分析（仅已关闭工单）、流转时间线（StatusTag 三态 + 点击展开/折叠操作记录）、底部操作栏（取消/改派）。
- **独立详情页**：`/workflow/order/:id`，已关闭工单通过基本信息区域的"查看完整工单 →"按钮进入。全宽布局，面包屑导航 + 返回，展示内容与抽屉相同。

## 二、页面结构

### 抽屉布局（从上到下）

```
┌─ 标题栏 ──────────────────────────────────────────────────────┐
│ [[StatusTag]] 工单详情 — WO2026XXXXX                           │
├─ 基本信息（flex-shrink: 0）────────────────────────────────────┤
│  ┌─ 左列 ─────────────────┐  ┌─ 右列 ───────────────────┐     │
│  │ 工单编号 / 模板名称      │  │ 发起人 / 创建时间         │     │
│  │ 优先级 / 实例状态        │  │ 当前进度 / 当前处理人     │     │
│  │ SLA状态                 │  │  [查看完整工单 →](仅已关闭)│     │
│  └────────────────────────┘  └────────────────────────────┘     │
├─ SLA指标分析（仅 status === 'closed'）flex-shrink: 0 ─────────┤
│  TTR响应 │ TTS解决 │ 总耗时    +  时限配置行                    │
├─ 流转时间线（flex: 1, overflow-y: auto）───────────────────────┤
│  [[已完成]] ③1 发起节点  张三  2026-01-01 10:00                │
│    └ 张三 创建工单  2026-01-01 10:00                           │
│  ┏[[进行中]] ③2 执行节点  李四  进行中┓ ← 蓝色高亮             │
│  ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛                          │
│  [[待处理]] ③3 确认节点  王五               ← 置灰              │
├─ 底部操作栏（status !== 'closed' 时）flex-shrink: 0 ──────────┤
│                              [取消工单]  [强制改派]             │
└────────────────────────────────────────────────────────────────┘
```

### 独立详情页布局

与抽屉内容一致，全宽展示。顶部面包屑（`← 返回 工单监控 / 工单详情`）+ 标题行（StatusTag + 工单编号）。

### 区域清单

| # | 区域名称 | 展示条件 | 说明 |
|---|---------|---------|------|
| 1 | 标题栏 | 始终 | `[{StatusTag}] 工单详情 — {orderNo}` |
| 2 | 基本信息 | 始终 | 左右两列 CSS Grid（1fr 1fr），标签 80px 定宽。字段共 9 个，左列 5 右列 4。已关闭工单额外显示"查看完整工单 →"按钮 |
| 3 | SLA 指标分析 | `status === 'closed'` | 三列指标卡片：TTR 响应 / TTS 解决 / 总耗时，每项含达标状态标记。底部行显示时限配置 |
| 4 | 流转时间线 | 始终 | 完整节点链路，按 order 正序。节点三态：已完成(绿)/进行中(蓝高亮)/待处理(灰置)。点击行展开/折叠操作记录 |
| 5 | 底部操作栏 | `status !== 'closed'` | [取消工单](danger) + [强制改派](default) |
| 6 | 取消确认弹窗 | 触发 | `el-dialog` width=480px，含提示 + 取消原因(textarea, 必填, ≤200字) |
| 7 | 改派弹窗 | 触发 | `el-dialog` width=520px，含 PersonSelector + 原因(textarea, 必填, ≤200字) |

## 三、数据模型

### 3.1 实体字段（WorkOrderDetail）

继承 `WorkOrderItem`（见 `工单监控列表.md` §3.1）所有字段，额外包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `nodes` | `WorkOrderNode[]` | 节点链路列表，按节点序号 `order` 升序排列 |
| `records` | `WorkOrderRecord[]` | 处理记录列表，按时间 `createdAt` 倒序排列 |

关键显示字段摘要：

| 字段 | 数据来源 | 显示位置 |
|------|---------|---------|
| 工单编号 | `orderNo` | 标题栏 + 基本信息 |
| 模板名称 | `templateName` (含版本号) | 基本信息 |
| 优先级 | `priority` | 基本信息（StatusTag） |
| 发起人 | `creatorName` / `createdAt` | 基本信息（分两行显示） |
| 当前状态 | `status` | 标题栏(StatusTag) + 基本信息(StatusTag) |
| 当前进度 | `currentNodeIndex` / `totalNodes` | 基本信息 |
| 当前处理人 | `currentAssigneeName` | 基本信息 |
| SLA | `sla` 子对象 | 基本信息（圆点+状态文案+剩余时间） + SLA 指标卡片（仅已关闭） |

### 3.2 节点链路（WorkOrderNode）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `number` | 节点 ID |
| `name` | `string` | 节点名称（如"执行节点"） |
| `type` | `string` | 节点类型：`start` / `assign` / `execute` / `confirm` / `close` / `condition` / `external` |
| `status` | `NodeStatus` | 节点状态 |
| `assigneeName` | `string \| null` | 节点处理人姓名 |
| `completedAt` | `string \| null` | 节点完成时间 |
| `order` | `number` | 节点序号，从 1 开始 |

### 3.3 处理记录（WorkOrderRecord）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `number` | 记录 ID |
| `action` | `string` | 操作名称（如"创建工单""接单""指派""提交结果""通过""驳回"） |
| `operatorName` | `string` | 操作人姓名 |
| `operatorOrgName` | `string \| null` | 操作人所属企业 |
| `content` | `string` | 操作内容描述 |
| `createdAt` | `string` | 操作时间 |

### 3.4 节点状态枚举（NodeStatus）与 StatusTag 映射

| 枚举值 | StatusTag `type` | 语义色 | 标签文字 | 时间线显示 |
|--------|-----------------|--------|---------|-----------|
| `completed` | `success` | 绿色 `#059669` | 已完成 | 正常白底 + 完成时间 |
| `in_progress` | `info` | 蓝色 `#3678E3` | 进行中 | **高亮边框 + accent10 背景** |
| `pending` | `normal` | 灰色 `#364153` | 待处理 | 置灰 `opacity: 0.4`，无时间无记录 |

> 注意：`pending` 在模板列表 + 节点时间线两个上下文中含义不同。后者通过映射为 `node_pending` 传入 StatusTag，避免与"待生效"混淆。

### 3.5 实例状态枚举（InstanceStatus）

同 `工单监控列表.md` §3.2。

## 四、接口定义

| 接口名称 | 方法 | 路径 | 请求类型 | 响应类型 |
|---------|------|------|---------|---------|
| 获取工单详情 | `GET` | `/api/v1/work-order/instances/:id` | — | `WorkOrderDetail` |
| 取消工单 | `POST` | `/api/v1/work-order/instances/:id/cancel` | `{ reason: string }` | `{ id, orderNo, status, closedAt, closedBy }` |
| 强制改派 | `POST` | `/api/v1/work-order/instances/:id/reassign` | `{ targetUserId: number }` | `{ id, orderNo, currentAssigneeName }` |

## 五、业务逻辑

### 5.1 交互行为

| 操作 | 触发条件 | 行为描述 |
|------|---------|---------|
| 打开抽屉 | 点击列表页工单编号或"详情"按钮 | 调用 `GET /api/v1/work-order/instances/:id` 获取详情，FormDrawer 从右侧滑出(720px)。标题栏显示 `[{statusTag}] 工单详情 — {orderNo}` |
| 关闭抽屉 | 点击 ✕、遮罩层或 ESC | 抽屉滑出。取消/改派操作完成后同时关闭抽屉并刷新列表 |
| 查看基本信息 | 抽屉打开 | 两列 Grid 渲染工单核心属性。左右分列，标签 80px 定宽。已关闭工单显示"查看完整工单 →"按钮 |
| 查看完成工单详情 | 点击"查看完整工单 →" | 跳转 `/workflow/order/:id` 独立详情页，面包屑 + 返回按钮，全宽布局展示完整信息 |
| 查看流转时间线 | 抽屉打开 | 完整节点链路按 order 正序。每个节点显示 StatusTag（语义色）+ 序号 + 名称 + 负责人 + 时间。`condition` 和 `external` 节点不显示 |
| 展开/折叠操作记录 | 点击非待处理节点行 | 整行可点击，无展开按钮文字。点击切换该节点下操作记录的显隐 |
| 查看 SLA 指标 | `status === 'closed'` | 基本信息与时间线之间插入 SLA 指标分析卡片。三列指标：TTR 响应时间、TTS 解决时间、总耗时，每项含达标/超时标记。底部行显示时限配置 |
| 取消工单 1：点击按钮 | 非已关闭 + 平台运营方 | 底部显示[取消工单](danger) |
| 取消工单 2：确认弹窗 | 点击[取消工单] | FormDialog 弹出，提示 + 取消原因(必填, max 200字)。空值时确认按钮 disabled |
| 取消工单 3：提交 | 确认 | POST 取消接口，成功后关闭弹窗+抽屉，刷新列表，追加操作日志 |
| 强制改派 1：点击按钮 | (待接单\|处置中) + 平台运营方 | 底部显示[强制改派](default) |
| 强制改派 2：选择人员 | 点击[强制改派] | FormDialog 弹出，PersonSelector(限定本企业或关联企业) + 改派原因(必填, max 200字) |
| 强制改派 3：提交 | 确认 | POST 改派接口，成功后更新抽屉内当前处理人信息，SLA 继续计时不重置，追加操作日志 |
| 已关闭工单 | `status === closed` | 底部操作栏完全不渲染，显示 SLA 指标卡片 |

### 5.2 特殊规则

- **已关闭工单只读**：底部操作栏隐藏，显示 SLA 指标分析 + 查看完整工单入口
- **查看完整工单**：已关闭工单点击"查看完整工单 →"跳转独立详情页 `/workflow/order/:id`
- **基本信息两列**：左列工单信息（工单编号、模板名称、优先级、实例状态、SLA状态），右列人员信息（发起人、创建时间、当前进度、当前处理人）
- **时间线三态**：已完成(绿，success)、进行中(蓝高亮，info + accent 边框/背景)、待处理(灰，opacity 0.4、无时间无记录)
- **时间线展开/折叠**：无按钮文字，点击已完成/进行中节点行即可切换。待处理节点不可点击
- **取消必须填原因**：必填校验，空值时确认按钮 disabled
- **取消不触发归档**：进入"已关闭"但不执行关闭节点的归档回调和通知逻辑
- **改派后 SLA 继续累计**：不重置 TTR/TTS 计时
- **操作日志**：取消和改派成功后，系统自动追加操作记录
- 数据权限：根据当前登录角色过滤可见字段（参见 PRD §1.3）

## 六、UI 组件分配

| 页面区域 | 实现组件 | 关键说明 |
|---------|---------|---------|
| 抽屉容器 | `el-drawer` | `size`="720px"，`direction`="rtl" |
| 基本信息卡片 | CSS Grid `.info-grid-2col` | `grid-template-columns: 1fr 1fr`，标签 80px 定宽。左右列之间 `border-right` 分隔 |

| 流转时间线 | 自定义 `.timeline-list` | StatusTag(小尺寸) 渲染节点状态，三态 CSS class（`tl-completed`/`tl-in_progress`/`tl-pending`）。点击行 toggle 操作记录显隐 |
| 底部操作栏 | `.drawer-actions` | `flex-shrink: 0`，`v-if="status !== 'closed'"` |
| 取消确认弹窗 | `el-dialog` | width="480px" |
| 改派弹窗 | `el-dialog` | width="520px" |
| 人员选择器 | `PersonSelector` | 现有组件 `@/components/business/PersonSelector.vue` |
| 状态标签 | `StatusTag` | 新增节点状态映射：`completed`(success 绿)、`in_progress`(info 蓝)、`node_pending`(normal 灰) |
| 独立详情页 | `WorkOrderDetail.vue` | 路由 `/workflow/order/:id`，面包屑导航，复用抽屉所有展示逻辑 |
