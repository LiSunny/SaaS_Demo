
# 页面2：流程模板配置页 — 设计文档
## 一、页面元信息
| 项目 | 内容 |
| --- | --- |
| 页面名称 | 流程模板配置页 |
| 所属模块 | 工作流编排 |
| 页面类型 | 表单提交 |
| 路由路径 | `/workflow/template/config/:id?` |


### 功能描述
流程模板的多步骤配置页面，包含基础设置、表单设计、流程设计三个步骤，支持新增模板和编辑已有模板。

---

## 二、页面结构
### 多步骤配置页布局（三步流程）

页面采用"面包屑置顶 + 工作栏卡片 + 工作区卡片"三层结构，无独立底部栏。

| # | 区域名称 | 位置 | 注册表组件 | 包含元素 |
| --- | --- | --- | --- | --- |
| 1 | 面包屑行 | 顶部 | 自定义 | 返回列表按钮 + `el-breadcrumb`（工作流管理 > 流程模板 > 模板名称），独立一行，最小高度 |
| 2 | 工具栏卡片 | 顶部 | 自定义 | 圆角卡片，横向布局：中间 `el-steps` 步骤指示器（三步）**居中显示**；左右两侧 flex 行，左侧模板名称 + 工单说明（`form.description`）**垂直排列**，右侧操作按钮。按钮按**模式**区分：**查看模式**显示"上一步、下一步"（纯导航）；**编辑模式**显示"保存草稿、上一步、下一步/发布"（按钮按步骤显隐） |
| 3 | 工作区卡片 | 中部 | `el-card` | 圆角卡片包裹步骤内容（基础设置 / 表单设计 / 流程设计），`flex:1` + `overflow:auto`。**查看模式下所有表单字段 disabled** |

> 点击下一步校验表单内容，至少要有2个组件才行

### 步骤3：流程设计
| # | 区域名称 | 位置 | 注册表组件 | 包含元素 |
| --- | --- | --- | --- | --- |
| 1 | 流程可视化区 | 中部 flex | 自定义 `FlowDesigner` | 线性节点链：预置"开始"节点 → "结束"节点，两节点间显示向下的箭头连线 + "+" 圆形按钮；节点卡片展示类型图标 + 名称，悬浮显示删除按钮（节点总数 ≤ 2 时隐藏），**所有节点（含开始/结束）点击选中高亮，开始、结束节点不可删除** → 右侧 NodePropertyPanel 显示该节点属性 |
| 2 | 节点属性面板 | 右侧 548px | 自定义 `NodePropertyPanel`，顶部 `el-tabs` 分为两个 Tab：<br>**Tab1「节点设置」**：节点名称（必填）、指派策略（assign / confirm 节点：静态指定 / 动态表单字段 单选切换；静态：PersonSelector 选人+多人模式；动态：选表单字段）、操作按钮（confirm 节点）、条件表达式（condition 节点）、SLA 覆盖、消息通知<br>**Tab2「字段权限」**：所有节点均显示（含开始/结束节点）；列出步骤2设计的全部表单字段，每行三态 radio（🔒隐藏 / 👁只读 / ✏️可编辑）；默认规则——发起节点字段对本节点默认可编辑、对其他节点默认只读；未显式配置默认为只读；开始节点可点击选中并在右侧配置其字段权限（发起工单时可填哪些字段） |

> 注：流程设计参考 Figma 设计稿（node-id=4413:11633）交互模式，采用"预置节点 + 节点间 '+' 插入 + 悬浮删除 + 点击右侧配置"的方式，不依赖拖拽或第三方流程设计器。
> 进入页面默认选中第一个节点

## 三、数据模型
### 3.1 模板完整详情（TemplateDetail）
| 字段名 | 中文名 | 类型 | 说明 |
| --- | --- | --- | --- |
| `id` | 模板ID | `number` | — |
| `baseInfo` | 基础设置 | `TemplateBase` | 见下方 |
| `formSchema` | 表单设计 | `FormSchema` | 整个模板的表单 JSON Schema（可分段按节点） |
| `flowDefinition` | 流程定义 | `FlowDefinition` | 节点列表、连线、流转规则 |


**TemplateBase**:

```typescript
{
  name: string;
  code?: string;
  description?: string;
  initiatorScope: 'all' | 'specified';  // 谁可发起
  initiatorUserIds?: number[];           // 指定人员ID
  slaPriority: 'urgent' | 'normal' | 'low';
  defaultTtrMinutes?: number;
  defaultTtsMinutes?: number;
  amberThreshold: number;                // 黄灯阈值百分比，默认80
}
```

**FormSchema**:

```typescript
{
  // 按节点ID分组，key为节点ID（开始节点也视为一个节点）
  [nodeId: string]: {
    fields: Array<{
      id: string;
      type: string;           // input, textarea, radio, checkbox, date, upload, etc.
      label: string;
      required: boolean;
      source: 'manual' | 'auto' | 'inherited' | 'callback';
      defaultValue?: any;
      validationRules?: object;
      options?: Array<{ value: string; label: string }>;  // 选项列表（select/radio 等类型使用）
      // 布局相关
      span?: number;
    }>;
  };
}
```

**FlowDefinition**:

```typescript
{
  nodes: Array<{
    id: string;
    type: 'start' | 'assign' | 'execute' | 'confirm' | 'close' | 'condition' | 'external';
    name: string;
    // 指派策略（assign / confirm 节点共用）
    assignSource?: 'static' | 'dynamic';  // 指派来源：静态指定 / 动态表单字段，默认 static
    assignConfig?: {                      // 静态指派配置（assignSource='static' 时生效）
      strategy: 'position' | 'user' | 'role' | 'dept' | 'external';
      targetIds: number[];
      multipleMode: 'anyone' | 'each';   // 任一接单 / 每人处理
    };
    dynamicAssignFieldId?: string;        // 动态指派绑定的表单字段ID（assignSource='dynamic' 时生效，对应 formSchema 中的字段）
    slaLimits?: {                         // 可覆盖模板级SLA
      ttrMinutes?: number;
      ttsMinutes?: number;
      amberThreshold?: number;
    };
    actions?: Array<{                     // confirm节点或自定义节点
      name: string;                       // 按钮文字，如”通过””驳回”
      targetNodeId: string;
      conditionExpression?: string;       // 条件分支表达式（v2）
    }>;
    conditionExpression?: string;         // condition节点表达式
    formFields?: FieldPermission[];       // 该节点关联的表单字段权限列表
  }>;
  FieldPermission: {
    fieldId: string;       // 关联的表单字段ID
    mode: 'hidden' | 'readonly' | 'editable';  // 三态权限：隐藏 / 只读 / 可编辑，默认 'readonly'
  };
  edges: Array<{
    from: string;
    to: string;
    condition?: string;        // 条件边（如 from confirm 节点，基于 action）
  }>;
}
```

## 六、业务逻辑
### 6.1 状态流转（模板配置内部）
配置页不直接操作模板状态，草稿保存时模板状态保持“待生效”；点击“发布”后调用发布接口，状态变为“执行中”。

### 6.2 交互行为
| 操作 | 触发条件 | 行为描述 |
| --- | --- | --- |
| **查看模式** | 路由携带 `?mode=view` | 步骤 1 表单全部字段 disabled；工具栏仅显示"返回、上一步、下一步"按钮，上一步/下一步不触发校验、不保存；三个步骤均可自由切换浏览 |
| **编辑模式** | 路由无 mode 参数或 `?mode=edit` | 表单可编辑；工具栏显示完整按钮（取消、保存草稿、上一步、下一步/发布） |
| 下一步 | 编辑模式点击 [下一步] | 校验当前步骤必填项，通过后进入下一步；步骤3（流程设计）进入时自动校验流程完整性 |
| 上一步 | 点击 [上一步] | 返回上一步，保留已填写内容（查看模式下无校验） |
| 保存草稿 | 编辑模式点击 [保存草稿] | 调用保存接口，不改变状态（待生效），提示“已保存草稿” |
| 发布 | 编辑模式最后一步点击 [发布] | 先整体校验模板（基础信息完整、表单字段引用正确、流程图无悬空节点、SLA配置合理），通过后调用发布接口，成功后跳转列表页 |
| 取消 | 编辑模式点击 [取消] | 弹出确认框“内容未保存，是否离开？”，确认后跳转列表页 |
| 返回 | 查看模式点击 [返回] | 直接返回列表页，不弹出确认框 |
| 拖拽组件（表单设计） | 从左侧组件库拖拽到画布 | 生成新字段，可编辑属性 |
| 插入节点（流程设计） | 点击节点间 [+] 按钮 → 弹窗选类型 | 在箭头连线的当前位置插入新节点，新节点默认名称为类型中文名；开始节点和结束节点始终位于首尾，不可删除、不可通过弹窗添加 |
| 删除节点（流程设计） | 悬浮节点卡片 → 点击右上角 × | 删除节点，节点总数 ≤ 2 时隐藏删除按钮（保留开始+结束）；删除后两侧节点自动连线 |
| 配置节点 | 点击节点卡片 | 右侧属性面板显示该节点配置（节点名称、指派策略、表单字段权限、SLA覆盖、消息通知），点击”保存”按钮更新节点属性 |


### 6.3 特殊规则
+ 开始节点必须存在且只有一个，出度为1（指向第一个任务/审批节点）
+ 关闭节点必须存在且只有一个，入度至少为1
+ 每个确认/审批节点必须配置至少两个操作按钮（如“通过”“驳回”），并指定目标节点
+ 条件分支节点必须配置条件表达式，且每个分支必须指向有效节点
+ assign / confirm 节点指派来源为静态时，必须配置指派人员（通过 PersonSelector 选择），否则校验不通过
+ assign / confirm 节点指派来源为动态时，必须指定 dynamicAssignFieldId，且该字段必须在步骤 2 表单中存在
+ 若 assign 节点配置了多人模式为”任一人接单”，则 TTR 按任务进入公海池的时间计算
+ 表单设计中的字段可被流程设计中的节点引用，若某字段未被任何节点引用，保存时警告
+ 字段来源为 `inherited` 时，必须指定上游节点及字段名（在属性面板中提供选择器）
+ 字段权限三态默认规则：发起节点字段默认为"可编辑"；其他节点对非本节点新增字段默认为"只读"；未显式配置的字段默认为"只读"
+ 隐藏字段不在运行时渲染；只读字段 disabled 但回填已有值；可编辑字段正常交互
