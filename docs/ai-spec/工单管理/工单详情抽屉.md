### 2.2 区域定义

| # | 区域名称 | 位置 | 说明 |
| --- | --- | --- | --- |
| 1 | 页面头部 | 顶部 | 工单图标 + 优先级 Tag + 标题 + 编号/模板/发起人 + 上一条/下一条按钮 |
| 2 | 流程进度 | 左栏顶部 | 动态渲染模板 `flowDefinition.nodes`（过滤 `condition`/`external`），横向步骤指示器 |

### 2.3 已关闭状态

已关闭工单保持简化布局：基本信息 + SLA 指标卡片 + 全部节点只读展示。不显示右栏流转记录（内容已在节点区块中展示）。

## 三、数据模型

### 3.1 关键 computed

```typescript
// 1. 流程进度步骤 — 动态来自模板流程定义
const progressSteps = computed(() => {
  const flowNodes = store.templateDetail?.flowDefinition.nodes || []
  // 过滤不产生独立步骤的节点类型
  return flowNodes.filter(n => n.type !== 'condition' && n.type !== 'external')
})

// 2. 当前节点（运行时）
const currentNode = computed(() =>
  store.detail?.nodes.find(n => n.status === 'in_progress')
)

// 3. 当前节点的流程定义（含权限配置）
const currentFlowNode = computed(() =>
  store.templateDetail?.flowDefinition.nodes.find(
    n => n.id === String(currentNode.value?.id)
  )
)

// 4. 只读区字段 — 聚合已完成节点提交数据，过滤掉 editable/hidden
const readonlyFormItems = computed(() => {
  const records = store.detail?.nodeRecords || []
  const permFields = currentFlowNode.value?.formFields || []
  // 取所有已完成节点的 formSchema 字段
  // 排除 mode === 'editable' 和 mode === 'hidden' 的字段
  // 返回 { label, value, type } 用于渲染
})

// 5. 可编辑区字段 — 当前节点权限为 editable 的字段
const editableFormFields = computed(() => {
  const schema = store.templateDetail?.formSchema
  const nodeId = String(currentNode.value?.id)
  const allFields = schema?.[nodeId]?.fields || []
  const permFields = currentFlowNode.value?.formFields || []
  
  return allFields.filter(f => {
    const perm = permFields.find(p => p.fieldId === f.id)
    return perm?.mode === 'editable'
  })
})

// 6. 流转记录
const flowRecords = computed(() =>
  store.detail?.records || []
)
```

### 3.2 流程进度渲染规则

```
遍历 progressSteps（flowDefinition.nodes，按模板定义顺序）:
  对每个 flowNode:
    从 detail.nodes 查找对应运行时节点状态
    状态决定视觉:
      completed  → 蓝色边框 + 蓝色数字 + 蓝色文字
      in_progress → 蓝色边框 + 蓝色数字 + 蓝色文字（可加脉冲动画）
      pending    → 灰色边框 + 灰色数字 + 灰色文字
      skipped    → 灰色 + 删除线
  步骤间用连接线连接
  点击步骤 → 滚动到对应节点区块（只读区或操作区）
```

### 3.3 只读区字段判断

```
只读区展示的字段 = 满足以下任一条件:
  1. 已完成节点 nodeRecords 中有数据的字段（聚合展示最新值）
  2. 且不在当前节点权限中标记为 editable 或 hidden
  
即: fieldId NOT IN (currentFlowNode.formFields 中 mode='editable' 或 mode='hidden' 的 fieldId)
   AND fieldId IN (nodeRecords 中有值的字段)

渲染方式:
  - label + value（灰色背景圆角块）
  - upload 类型显示缩略图
  - 按 nodeRecords 提交顺序展示（先提交的先展示）
```

### 3.4 操作区字段判断

```
操作区展示的字段 = currentFlowNode.formFields 中 mode='editable' 的字段
  → 从 formSchema[currentNode.id].fields 获取完整字段定义
  → 传入 DynamicForm: fields + permissions(editable) + initialData
```

## 五、业务逻辑

### 5.1 页面初始化

```
1. onMounted → store.openDetail(route.params.id)
   ├── getWorkOrderDetail(id) → WorkOrderDetail
   │     含 nodes, records, nodeRecords, formData, branchDecisions
   │
   └── getTemplateDetail(templateId) → TemplateDetail
         含 formSchema, flowDefinition (nodes + formFields 权限)

2. 判断工单状态:
   未关闭 (status !== 'closed'):
     → 渲染双栏布局
     → 计算 progressSteps / readonlyFormItems / editableFormFields / flowRecords
   已关闭 (status === 'closed'):
     → 渲染简化布局（基本信息 + SLA 指标 + 全部节点只读）
```

### 5.2 提交处置

```
1. DynamicForm.validate()
2. DynamicForm.getFormData()
3. store.submitForm(id, formData)
4. 刷新详情数据
```

### 5.3 审核操作

```
1. 用户点击"通过"/"驳回"
2. store.executeNodeAction(id, action)
3. 刷新详情数据（当前节点可能变化）
```

### 5.4 按钮权限规则（2026-06-08 确定）

按钮按**作用域**分离为两层：

**工单级操作（底部栏）**：

| 按钮 | 显示条件 | 理由 |
|------|---------|------|
| 取消工单 | `status !== 'closed'` | 没关闭就能取消 |
| 强制改派 | `status === 'active' && currentAssigneeId != null` | 有人在干活才能"改派" |

**节点级操作（节点卡片）**：

| 按钮 | 显示条件 | 理由 |
|------|---------|------|
| 接单 | assign 节点 + `assignConfig.multipleMode === 'anyone'` + 无人认领 | 多人抢单才需认领 |
| 通过/驳回 | confirm 节点 + `flowNode.actions` 配置 | 已有逻辑 |

### 5.5 特殊规则

- **流程进度不能写死**：步骤数量和名称来自 `templateDetail.flowDefinition.nodes`（过滤 `condition`/`external`）
- **只读区字段动态聚合**：随着流程推进，只读区字段越来越多（新节点提交后，其字段在下个节点变为只读）
- **流转记录仅显示已发生**：`detail.records` 按时间倒序，不含未来节点
- **已关闭工单**：不显示双栏布局，回到简化只读模式 + SLA 指标
- **响应式**：屏幕宽度 < 1280px 时，右栏流转记录可折叠或移至左栏下方
