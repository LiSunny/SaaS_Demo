# 工单详情抽屉 — AI 代码规格

> 本文档描述工单详情抽屉的完整改造方案。将现有全页面式「WorkOrderDetail.vue」改为 el-drawer 抽屉模式。

---

## 一、页面元信息

| 项目 | 内容 |
| --- | --- |
| 页面名称 | 工单详情抽屉 |
| 所属模块 | 工单管理 |
| 页面类型 | 详情展示 + 表单提交（el-drawer 抽屉模式，右侧 860px） |

## 三、数据模型

### 3.1 节点时间数据（buildDetail 增强）

当前 `buildDetail` 中 `WorkOrderNode` 已包含 `completedAt`，需新增 `startedAt` 字段：

```typescript
export interface WorkOrderNode {
  id: number
  name: string
  type: string
  status: NodeStatus
  assigneeName: string | null
  startedAt: string | null    // ← 新增
  completedAt: string | null
  order: number
}
```

### 3.2 时间线显示规则

| 节点状态 | 显示 |
|---------|------|
| completed | 处理人 · 已完成；☐ 开始时间；☑ 完成时间 |
| in_progress | 处理人 · 进行中；☐ 开始时间 |
| pending | 处理人 · 待处理；— |

### 3.3 DynamicForm 状态判断

```typescript
// 是否只读
isReadonly = order.status === 'closed'  // 已关闭 → 全部只读
  || order.currentAssigneeId !== currentUserId  // 当前用户不是处理人 → 只读

// 是否显示操作按钮
showActions = order.status !== 'closed'
  && order.currentAssigneeId === currentUserId
```

## 六、业务逻辑

### 6.1 页面初始化

```
1. store.openDetail(id)
   ├── getWorkOrderDetail(id) → WorkOrderDetail
   │     含 currentNodeId, templateId, formData, nodes(含 startedAt)
   │
   └── getTemplateDetail(templateId) → TemplateDetail
         含 formSchema, flowDefinition, nodes.formFields

2. 查找当前节点:
   const currentNode = flowDefinition.nodes.find(n => n.id === currentNodeId)
   const fields = formSchema[currentNodeId]?.fields || []
   const permissions = currentNode?.formFields || []

3. 渲染:
   左侧: detail.nodes → 时间线（含 startedAt/completedAt）
   右侧: DynamicForm(:fields, :permissions, :initialData=formData, :readonly)
```

### 6.2 提交处置

```
1. 校验 dynamicFormRef.validate()
2. 收集 dynamicFormRef.getFormData()
3. 调用 submitNodeAction(id, { nodeId, formData })
4. 刷新详情
```

### 6.3 特殊规则

- **已关闭工单**：DynamicForm `readonly=true`，操作按钮隐藏。SLA 耗时指标在表单下方展示。
- **非处理人查看**：DynamicForm `readonly=true`，操作按钮隐藏。
- **标题栏无面包屑无返回按钮**：关闭通过 drawer 自带的 X / 遮罩 / esc。
- **基本信息不含处理人和当前进度**：这些信息已集成在左侧时间线每个节点中。
- **时间线节点按 order 排序**，当前节点高亮（蓝色边框）。
