# 新增/编辑岗位 — 设计文档

---

## 一、页面元信息

| 项目 | 内容 |
|------|------|
| 页面名称 | `新增/编辑岗位` |
| 所属模块 | `用户管理` |
| 页面类型 | `表单提交` |
| 路由路径 | — （弹窗模式，依附于 `/admin/positions` 列表页） |

### 功能描述

平台管理员新增或编辑内置岗位的表单提交弹窗。新增时填写岗位名称（自动生成 Key）、岗位说明和数据范围；编辑时 Key 只读。内置岗位创建后全平台所有企业可见可用。

---

## 二、页面结构

### 表单提交页布局（弹窗模式）

| # | 区域名称 | 位置 | 注册表组件 | 包含元素 |
|---|---------|------|-----------|---------|
| 1 | 弹窗标题 | 顶部 | `el-dialog` header | "新增内置岗位" / "编辑内置岗位" |
| 2 | 表单区 | 全宽 | `el-form` | 新增模式 4 字段：岗位名称(input) + 岗位Key(input, 自动生成可手动改) + 岗位说明(textarea) + 数据范围(select)。编辑模式 Key 只读 |
| 3 | 提交按钮栏 | 底部 | `el-button` group | 保存(primary, loading) + 取消 |

## 三、数据模型

### 3.1 表单字段（PositionForm）

| 字段名 | 中文名 | 类型 | 必填 | 控件类型 | 校验规则 | 说明 |
|--------|--------|------|------|---------|---------|------|
| `name` | 岗位名称 | `string` | 是 | `input` | `required`, `max: 20` | 如"消防安全管理人" |
| `key` | 岗位Key | `string` | 是 | `input` | `required`, `pattern: /^[a-z][a-z0-9-]*$/`, `max: 40`，全局唯一 | 唯一标识，新增时可自动生成也可手动修改，编辑时只读 |
| `description` | 岗位说明 | `string` | 否 | `textarea` | `max: 200` | 描述岗位职责，在岗位选择器中展示给企业管理员 |
| `dataScope` | 数据范围 | `string` | 是 | `select` | `required` | 下拉选项，见 §3.2 |

### 3.2 数据范围下拉选项

| 值 | 标签 | 说明 | 适用场景 |
|------|------|------|---------|
| `self` | 本企业 | 仅查看本企业数据 | 物业方岗位（消防安全责任人/管理人/消控值班员/企业管理员） |
| `assigned` | 分配给我的 | 仅查看分配给当前用户的数据 | 执行层岗位（维保工程师） |
| `service` | 本服务商项目 | 查看本服务商项目数据 | 服务方管理岗位（项目负责人/技术负责人） |
| `all` | 全量（管辖范围） | 查看管辖范围内全量数据 | 监管方岗位（安全监管员） |
| `platform` | 全平台 | 跨所有企业，无过滤 | 平台管理员 |

> 下拉选项需同时展示标签和说明文字，帮助平台管理员理解每个数据范围的含义。

## 六、业务逻辑

### 6.1 交互行为

| 操作 | 触发条件 | 行为描述 |
|------|---------|---------|
| 打开新增弹窗 | 点击列表页 [新增岗位] 按钮 | 弹窗打开，表单清空，岗位名称输入框自动聚焦。标题显示"新增内置岗位" |
| 打开编辑弹窗 | 点击列表页行操作 [编辑] | 弹窗打开，回填已有数据（名称/Key/说明/数据范围）。Key 字段变为只读。标题显示"编辑内置岗位" |
| Key 自动生成 | 名称输入框 blur（新增模式） | 将岗位名称转为拼音 slug（小写字母+连字符），自动填充到 Key 字段。如"消防安全管理人" → `fire-safety-manager`。用户可手动修改 |
| Key 手动修改 | 用户在 Key 输入框输入（新增模式） | 覆盖自动生成值。不再随名称变化联动 |
| 提交 | 点击 [保存] | 前端校验表单 → 根据模式调用 POST 或 PUT → 成功后 ElMessage 提示"创建成功"/"修改成功" → 关闭弹窗 → 刷新列表 |
| Key 重复 | 后端返回 409 | ElMessage.error("岗位 Key 已存在，请修改")，不关闭弹窗 |
| 取消 | 点击 [取消] / 弹窗外区域 / Esc | 关闭弹窗，不保存 |

### 6.2 特殊规则

- 新增模式下 Key 自动生成逻辑：名称 → 拼音 slug（小写字母+连字符）。示例："消防安全管理人" → `fire-safety-manager`，"平台管理员" → `platform-admin`
- Key 仅允许小写字母、数字、连字符，必须以字母开头
- 编辑模式下 Key 不可修改——避免权限配置引用断裂。如需修改 Key，只能删除重建
- 新增岗位后自动初始化空权限配置（所有模块/操作默认关闭）
- 岗位名称也可以修改（不影响权限配置，权限配置按 Key 关联）

## 七、UI 组件分配

| 页面区域 | 注册表组件 | 关键 Props / 自定义说明 |
|---------|-----------|----------------------|
| 弹窗容器 | `FormDialog` | title 按模式切换，width=520px，destroy-on-close，:close-on-click-modal="false" |
| 岗位名称字段 | `el-input` | placeholder="请输入岗位名称"，maxlength=20，@blur="autoGenerateKey"（仅新增模式） |
| 岗位Key字段 | `el-input` | placeholder="自动生成或手动输入"，新增时 :disabled="false"，编辑时 :disabled="true"。mono 字体。前置提示文字 "platform:" |
| 岗位说明字段 | `el-input` | type="textarea"，:rows="3"，placeholder="描述岗位职责，分配岗位时企业管理员可见"，maxlength=200，show-word-limit |
| 数据范围字段 | `el-select` | placeholder="请选择数据范围"，每个 `<el-option>` 含 label（标签）和 description（说明文字）两行 |
| 提交按钮 | `el-button` | type="primary"，:loading="submitting" |
