## 一、结论

1. 新增一级菜单「巡查检查」，作为独立分组（`NAV_GROUPS` 由 9 个分组增至 10 个，位置在「隐患排查治理」与「协同工作」之间），visibleTo = `unit`。
2. 子菜单名称与层级按平台运行时菜单实测结果 1:1 复制，菜单名一律用平台原文：首页、任务监控（巡查任务）、项目配置、点位管理、计划管理（消防巡查）、异常处置、巡查报表、通知提醒。平台「使用手册」为外链项，按需求不纳入本仓库菜单。

4. 现有「安全管理 › 巡查检查」节点（`unit-patrol`）及其两条死路由（`/unit/patrol/tasks`、`/unit/patrol/locations`）由新分组接管，路径不变。
5. 实体 7 个：巡查内容、点位、计划、任务、巡查记录、异常、通知。状态枚举 12 个（任务 6 + 异常 6）。
6. 分 3 批交付：菜单骨架（占位页，已完成）→ 4 个核心页真实实现 → 报表与通知。

### 2.4 状态枚举

任务状态（6）：待执行、执行中、已完成、预期未完成、逾期完成、取消。

| 状态 | 定义（文档原文要点） |
|------|----------------------|
| 待执行 | 已创建与分配，未到计划执行时间，或责任人未启动 |
| 执行中 | 责任人已启动，按计划现场巡检，未提交结果 |
| 已完成 | 计划截止时间内完成全部操作并提交结果 |
| 预期未完成 | 已到执行截止时间，责任人未完成 |
| 逾期完成 | 超过计划截止时间后完成并提交 |
| 取消 | 因计划调整、点位停用、任务重复终止，不纳入考核 |

异常状态（6）：待处理、处理中、暂停处理、待确认、已完成、已取消。

异常流转：发现异常上报 → 判断是否需要处理 → 发起工单 → 接收工单 → 维修并上报结果 → 可即时修复则确认处理完成 → 合格关闭工单 / 不合格退回；不可即时修复则挂起。

### 2.5 业务链路（三阶段）

| 阶段 | 动作 | 产出实体 |
|------|------|----------|
| 准备 | 制定检查内容 → 明确检查点位 → 创建检查计划 | 巡查内容、点位、计划 |
| 执行 | 接收检查任务 → 点位检查记录 → 异常信息上报 | 任务、巡查记录、异常 |
| 归档 | 检查记录归档 → 异常情况跟踪 → 统计分析优化 | 巡查记录、异常、报表、通知 |

移动端执行链路 7 步：查看任务 → 执行任务 → 扫描标签 → 查看点位 → 录入检查结果。

1. 侧栏「巡查检查」为独立一级分组，8 个二级项、2 个三级项，与平台菜单逐项对应（§3.2 表全部命中，使用手册除外）。
2. 8 个路由全部可访问，控制台无 `未登记到 ROUTE_TO_NAV_KEY` 告警。
3. 旧路径 `/unit/patrol/tasks`、`/unit/patrol/locations` 行为不变。
4. 安全管理与单位设置两个分组内不再出现巡查相关节点。
5. 工作台「巡查检查」快捷入口可直达 `/unit/patrol`。
6. 第 2/3 批真实页面落地后，每个页面可从页面自身数据复算其表格行数与状态枚举数（任务 6 态、异常 6 态）。
