# 工单管理 产品需求文档

> 版本：v3.0 | 日期：2026-06-16 | 状态：基于 Figma 设计稿整合
>
> 本文档合并了原「流程编排」「工单管理」「工单监控」三份 PRD，覆盖工单管理域的**设计时（流程模板配置）** 与**运行时（工单发起/监控/详情/处置）** 全生命周期。

## 1. 背景与目标

### 1.1 业务背景

本平台是一个消防安全管理协作平台，连接维保公司（服务商）、业主单位（物业方）和监管方（应急管理局）。工单管理是整个平台的**流程中枢**，承载"任务流转与处置闭环"核心能力。

**四方协同模型**：

| 租户方 | 典型角色 | 工单职责 |
|--------|---------|---------|
| 物业管理有限公司（物业方） | 消防安全管理人、消控值班员、消防安全责任人 | 发起工单、核查验收、SLA 监督 |
| 消防技术服务公司（服务方） | 维保工程师、项目负责人、技术负责人 | 接单处置、团队管理、技术审核 |
| 应急管理局安全管理中心（监管方） | 安全监管员 | 督办发起、核查验收、监管报告 |
| 平台运营方 | 平台管理员 | 流程模板配置、全局参数、全平台干预 |

### 1.2 模块定位

工单管理的本质是一个**可泛化的流程编排框架 + 工单全生命周期管理系统**，支撑以下典型场景：

- **工单场景**：设备维修工单从发起到关闭的全生命周期管理
- **督办场景**：监管方向预警方下达督办，跨企业流转
- **审批场景**：报告审核、合同确认等需要审批节点的流程

工单管理分为两大视角：

| 视角 | 入口 | 用户 | 数据范围 | 信息密度 |
|------|------|------|---------|---------|
| **我的工单**（个人视角） | 工作台 | 消防安全管理人、消控值班员、维保工程师 | 我发起的 + 指派给我的 | 低（无统计卡片） |
| **工单监控**（管理视角） | `/system/monitor` | 消防安全责任人、项目负责人、技术负责人、安全监管员 | 按岗位全量过滤 | 高（统计卡片 + SLA 预警） |

### 1.3 适用范围

| 角色 | 可见范围 | 可执行操作 |
|------|---------|-----------|
| 平台管理员 | 全部模板 + 全平台工单 | 模板 CRUD、强制改派、取消工单 |
| 业务人员 | 已发布模板 | 按模板创建工单实例 |
| 服务商管理员 | 本企业模板 + 本企业工单 | 内部指派、查看 |
| 服务商执行人 | 分配给自己或本企业公海池的工单 | 接单、执行、提交 |
| 业主单位 | 本企业发起的工单 | 查看进度、确认/驳回 |

## 2. 核心概念

| 概念 | 说明 | 举例 |
|------|------|------|
| **模板 (Template)** | 流程蓝图，定义节点和流转规则 | "远程值守告警处置模板" |
| **节点 (Node)** | 流程中的一个步骤 | "现场处置" |
| **字段 (Field)** | 节点上需填写/展示的数据项，支持 8 种类型 | "故障描述"、"现场照片" |
| **字段权限 (FieldPermission)** | 每字段在每节点的三态控制：`hidden` / `readonly` / `editable` | 执行节点对"设备名称"设为只读 |
| **实例 (Instance)** | 按模板创建的一次具体运行 | "WO20260601-001" |
| **任务 (Task)** | 某个节点分配给某人的待办 | "李四需要执行的维修任务" |
| **流转规则 (Transition)** | 节点间的跳转条件 | "通过→关闭，驳回→执行" |
| **nodeRecords** | 每个节点提交的表单数据记录 | 用于只读区回溯展示 |
| **formData** | 所有节点已填值的聚合快照 | 用于 DynamicForm 回填 |

## 3. 设计时：流程编排

> 流程编排是工单系统的**设计时基础设施**——管理员在此定义模板（节点、表单、流转规则、SLA），业务人员按模板创建并执行工单。

### 3.1 模板列表

页面位于侧栏「系统管理 > 工单管理 > 工单配置 > 列表」。

**页面布局**：

```
┌──────────────────────────────────────────────┐
│  帮助 Banner（可折叠）                         │
│  "什么是流程编排配置？" + 三步使用说明          │
├──────────────────────────────────────────────┤
│  [名称] [状态▾] [周期▾] [查询]    [+ 新建工作流] │
├──────────────────────────────────────────────┤
│  数据表格（7 列）                              │
│  状态 │ 模版编号 │ 模版名称 │ 模版概览 │ 创建人 │ 更新时│ 操作  │
│                                            │
├──────────────────────────────────────────────┤
│  共 N 条记录  第 1/N 页          分页器        │
└──────────────────────────────────────────────┘
```

**筛选条件**：名称（输入框）+ 状态（下拉：全部/待生效/执行中/已停用/已过期）+ 周期（下拉）+ 查询按钮（无重置按钮）

**表格列定义**：

| 列名 | 说明 | 排序 |
|------|------|------|
| 状态 | StatusTag：执行中(绿) / 待生效(蓝) / 已停用(黄) / 已过期(灰) | — |
| 模版编号 | 自动生成，格式 `MB-YYYYMMDD-NNNN` | ✅ |
| 模版名称 | — | — |
| 模版概览 | `**N** 节点 · **M** 字段`，数字蓝色高亮 | ✅ |
| 创建人 | 可为人员或部门/岗位名称 | — |
| 最近更新时间 | `YYYY-MM-DD HH:mm` | ✅ |
| 操作 | 预览 · 编辑 · 删除 · 开关 toggle · 复制（5 个图标，固定右侧） | — |

**模板管理功能**：

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 模板列表 | 按名称/状态查询、分页展示 | P0 |
| 新建模板 | "新建工作流"按钮（outlined primary，+图标），跳转配置页 | P0 |
| 编辑模板 | 修改已有模板，生成新版本 | P0 |
| 删除模板 | 删除未启用模板，进行中实例关联时禁止删除 | P0 |
| 发布模板 | 模板从"待生效"发布为"执行中" | P0 |
| 停用/启用 | Switch toggle 控制 | P0 |
| 复制模板 | 基于现有模板创建副本 | P1 |

> **注意**：Figma 设计无多选框列、无批量删除按钮、无重置按钮。操作列含 5 个图标按钮。

### 3.2 模板配置（三步向导）

页面采用"面包屑 + 工具栏卡片 + 工作区卡片"三层结构。

**工具栏卡片布局**：

```
┌──────────────────────────────────────────────────────┐
│ [返回列表]  模板名称 + 工单说明    ① ② ③    [取消] [下一步] │
│              (左侧垂直排列)      步骤指示器  (右侧操作按钮)    │
└──────────────────────────────────────────────────────┘
```

步骤指示器为自定义编号圆圈（①②③），当前步骤蓝色高亮 + 4px 蓝线下划线。按钮按步骤显隐：步骤 1 显示「取消 + 下一步」，步骤 2-3 显示「上一步 + 下一步/发布」。

#### 步骤 1：基础设置

| 配置项 | 控件 | 说明 |
|--------|------|------|
| 模板名称* | `el-input` | 必填 |
| 工单说明 | `el-input` | 模板说明文字 |
| 谁可发起工单 | 下拉选择器 | PersonSelector 弹窗选择 |

**SLA 配置**（模板级，**2×2 四档优先级独立卡片**）：

| 优先级 | 卡片头部颜色 | 配置项 |
|--------|------------|--------|
| 紧急 | 红色 `rgba(220,38,38,0.1)` | 响应时限(分钟) + 解决时限(分钟)，各带帮助图标 |
| 高 | 橙色 `rgba(217,119,6,0.1)` | 同上 |
| 普通 | 黄色 `rgba(202,138,4,0.1)` | 同上 |
| 低 | 蓝色 `rgba(54,120,227,0.1)` | 同上 |

> 说明文字："如果发起流程时选择此优先级，则按此时限监测"。每卡片独立配置 TTR 和 TTS，互不影响。

#### 步骤 2：表单设计

**三栏布局**：

| 区域 | 宽度 | 内容 |
|------|------|------|
| 组件面板（左） | 332px | 基础组件 6 种（输入框/多行输入框/单选框/选择器/日期/上传）+ 业务组件 3 种（事件信息/异常信息/隐患信息） |
| 画布区（中） | flex:1 | 表单实时预览，支持拖拽排序、删除、复制 |
| 属性面板（右） | 332px | 选中组件的属性配置：字段名称、标签位置、必填、宽度、校验规则、默认值、字段来源（手动/自动/继承/回调） |

#### 步骤 3：流程设计

**两栏布局**：

| 区域 | 宽度 | 内容 |
|------|------|------|
| 流程可视化区（左） | flex:1 | 线性节点链：预置"开始"→"结束"节点，节点间箭头连线 + "⊕"圆形按钮插入节点 |
| 节点属性面板（右） | 548px | 按节点类型显示不同 Tab，详见 §3.3 |

节点卡片样式：圆角边框卡片，含类型图标（56×56px）+ 节点名称（粗体）+ 描述文字。悬浮显示删除按钮（总节点数 ≤ 2 时隐藏）。点击选中高亮 → 右侧属性面板联动。

插入节点弹窗：点击节点间"⊕"按钮 → 网格展示 5 种可选节点类型（指派/执行/审批/条件判断/跨企业协同）。开始和结束节点不在弹窗中（已预置且唯一）。

### 3.3 节点属性面板

右侧 548px，**按节点类型区分 Tab 数量和内容**：

#### Tab「节点信息」

| 配置项 | 控件 | 适用节点 |
|--------|------|---------|
| 节点名称* | 文本输入框 | 全部 |

#### Tab「表单权限」

所有节点均显示。列出步骤 2 的全部表单字段，每行三态 radio（🔒隐藏 / 👁只读 / ✏️可编辑）。默认规则：

| 节点类型 | 不属于本节点的字段 | 属于本节点的字段 |
|---------|-----------------|----------------|
| 发起 (start) | 只读 | 可编辑 |

| 执行 (execute) | 只读 | 可编辑 |
| 确认 (confirm) | 只读 | 可编辑 |
| 关闭 (close) | 只读 | — |

#### Tab「超时配置」

> 仅执行 (execute)、指派 (assign)、确认 (confirm) 节点显示。

| 配置项 | 控件 | 说明 |
|--------|------|------|
| 节点完成时限 | 下拉选择器 | 单一完成时限（如"15分钟"） |

### 3.4 节点类型定义

| 类型 | 标识 | 核心能力 | 优先级 |
|------|------|---------|--------|
| 发起 | `start` | 手动录入/自动填充/外部回调。预置且唯一，不可删除 | P0 |
| 指派 | `assign` | 指派处理人 + 接单确认（可选）。assignSource: static / dynamic | P0 |
| 执行 | `execute` | 表单填写/到场校验/采集证据。assignSource: static / dynamic | P0 |
| 确认 | `confirm` | 通过/驳回。assignSource: static / dynamic / initiator | P0 |
| 条件判断 | `condition` | 基于上一节点状态自动分支（正常→继续 / 超时→升级），含回流机制 | P0 |
| 跨企业协同 | `external` | 零配置，目标企业由运行时上下文动态确定，内部含子流程节点链 | P1 |
| 关闭 | `close` | 归档/回调通知。预置且唯一，不可删除 | P0 |

### 3.5 指派策略

指派策略为**三选一 radio**（`assignSource`），**不同节点类型的可选项不同**：

| 指派来源 | 适用节点 | 配置方式 |
|----------|---------|---------|
| **静态指派** (`static`) | assign, execute, confirm | PersonSelector 选人/岗位/部门/角色 + 多人模式（任一人接单 / 每人独立任务） |
| **动态表单字段** (`dynamic`) | assign, execute, confirm | 下拉选择步骤 2 中类型为"人员选择器"的表单字段 |
| **指派给发起人** (`initiator`) | **仅 confirm** | 无需额外配置，运行时自动取工单发起人 |

> **关键约束**：`指派给发起人` 仅确认 (confirm) 节点可用。指派 (assign) 节点和执行 (execute) 节点不支持此模式。
>
> **跨企业限制**：跨企业协同节点下的人员选择仅支持按平台级岗位选择人员。

**多人模式**（仅 `static` + 目标为多人时生效）：

| multipleMode | 含义 | 接单动作 | 任务状态路径 |
|-------------|------|---------|------------|
| `anyone` | 任一人接单（抢单），先接先得 | 有 — 需主动抢单 | 待指派 → 待接单 → 处置中 |
| `each` | 每人各自生成独立任务 | 无 — 直接下发 | 待指派 → 处置中 |

## 4. 运行时：工单生命周期

### 4.1 实例状态机

实例遵循三态标准化：**草稿（draft） → 进行中（active） → 已关闭（closed）**。

```
    创建实例        提交              所有节点完成
  ──────────→ 草稿 ────→ 进行中 ──────────────→ 已关闭
                   │         │                      ↑
                   │   取消   │     取消             │
                   └─────────┴──────────────────────┘
```

| 实例状态 | 含义 | 内部任务可能处于 |
|---------|------|----------------|
| **草稿** | 实例已创建但未提交 | 无任务 |
| **进行中** | 实例已提交，节点任务正在流转 | 待指派 / 待接单 / 处置中 / 验收中 |
| **已关闭** | 实例结束（正常完成或取消） | 无活跃任务 |

> 具体进度由当前节点名称和已完成步骤数 / 总步骤数体现。驳回是任务级别的操作，实例状态始终停留在"进行中"。取消后进入"已关闭"但不触发归档与回调逻辑。

### 4.2 工单发起

**入口**：工作台「发起工单」Widget（弹窗模式）。

**交互流程**：
1. 点击发起 → 弹窗打开，展示可用模板卡片列表（2×2 网格，显示名称+节点数）
2. 选中模板 → 表单区展开
3. 优先级选择（紧急/高/普通/低，默认普通）+ 工单标题（必填）+ 备注（选填）
4. DynamicForm 渲染发起节点的可编辑字段
5. 保存草稿 / 立即发起

**业务规则**：
- 仅展示"执行中"状态的模板
- 未选模板时"确认发起"按钮 disabled
- 工单编号系统自动生成（`WOYYYYMMDD-NNN`）
- 创建后状态为"草稿"

### 4.3 工单监控

**入口**：侧栏「工单监控」独立页面 `/system/monitor`。

**页面布局**：

```
┌──────────────────────────────────────────────┐
│  统计卡片行                                    │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐         │
│  │全部  │ │草稿  │ │进行中│ │已关闭│         │
│  │ 128  │ │  3   │ │  83  │ │  42  │         │
│  └──────┘ └──────┘ └──────┘ └──────┘         │
├──────────────────────────────────────────────┤
│  筛选栏                                       │
│  [关键词] [SLA状态▾] [优先级▾] [日期范围▾]      │
├──────────────────────────────────────────────┤
│  数据表格                                     │
│  状态 │ SLA │ 编号 │ 标题 │ 优先级 │ 进度 │ 时间 │ 预览│
├──────────────────────────────────────────────┤
│  分页器                                       │
└──────────────────────────────────────────────┘
```

**统计卡片**：全部 / 草稿 / 进行中 / 已关闭，点击卡片快速筛选。由后端 stats 接口驱动，零值正常显示。

**列表字段**：

| 列名 | 说明 |
|------|------|
| 工单状态 | StatusTag：草稿 / 进行中 / 已关闭 |
| SLA 状态 | 🟢正常 / 🟡预警(≥80%) / 🔴超时，Tooltip 展示详情 |
| 工单编号 | 点击进入详情 |
| 工单标题 | — |
| 优先级 | 紧急/高/普通/低 |
| 流程进度 | `当前步骤/总步骤` |
| 当前节点 | 当前节点名称，已关闭显示"—" |
| 发起时间 | `YYYY-MM-DD HH:mm` |
| 操作 | "详情"按钮 |

**筛选条件**：关键词搜索（工单编号/发起人）+ SLA 状态 + 优先级 + 日期范围。实例状态筛选由统计卡片覆盖，不单独设置下拉。

**数据权限**：物业看本企业、服务商看分配、监管看全量。超时工单置顶显示。

### 4.4 工单详情与处置

**入口**：独立页面 `/system/order/:id`。

**双栏布局**：

```
┌─ 页面头部：优先级Tag + 工单标题 + 编号/模板/发起人 ──────────────┐
│  [强制转派] [取消工单] [手动关闭]                               │
├─────────────────────────────────────┬──────────────────────────┤
│  左栏 (flex-1)                       │  右栏 (361px)             │
│  ┌─ 流程进度 ────────────────────┐  │  ┌─ 流转记录 ──────────┐  │
```

## 5. SLA 管理

### 5.1 模板级 SLA

四档优先级独立卡片（2×2 网格），每卡片含 TTR + TTS 输入。详见 §3.2 步骤 1。

### 5.2 节点级超时配置

执行/指派/确认节点独立"超时配置"Tab，含节点完成时限 + 超时前警告 + 通知渠道。详见 §3.3。

### 5.3 SLA 计时模型

```
TTR（响应时限）: 任务到达 → 接单         ← 衡量响应速度
TTS（解决时限）: 接单     → 关闭         ← 衡量端到端时效

有指派环节：  任务到达 → 待指派 → 待接单 → 处置中 → ... → 关闭
              ────────────TTR────────────
                                     ───────────TTS───────────

无指派环节：  任务到达 ────────────→ 处置中 → ... → 关闭
              ────────────────TTS────────────────→
```

### 5.4 三色预警

| 状态 | 颜色 | 条件 | 含义 |
|------|------|------|------|
| 正常 | 🟢 绿色 | 进度 < 80% | 时间充裕 |
| 预警 | 🟡 黄色 | 80% ≤ 进度 < 100% | 即将超时 |
| 超时 | 🔴 红色 | 进度 ≥ 100% | 已超时 |

> 进度 = 已用时间 / SLA 时限。黄灯阈值由系统统一按 80% 计算。草稿和已关闭状态的工单不展示 SLA 状态（显示"—"）。驳回和转单不重置 TTS。

## 6. 动态表单渲染

### 6.1 字段权限三态

| mode | 运行时行为 | 视觉表现 |
|------|-----------|---------|
| `hidden` | 不渲染 | 不可见 |
| `readonly` | 控件 disabled，灰色背景，值回填 | 可见不可操作 |
| `editable` | 正常交互 | 正常输入控件 |

### 6.2 字段类型 → 控件映射

| 类型 | 控件 | disabled 行为 |
|------|------|--------------|
| `input` | `el-input` | 置灰不可输入 |
| `textarea` | `el-input type="textarea"` | 置灰不可输入 |
| `radio` | `el-radio-group` | 置灰不可切换 |
| `checkbox` | `el-checkbox-group` | 置灰不可勾选 |
| `select` | `el-select` | 置灰不可展开 |
| `date` | `el-date-picker` | 置灰不可选择 |
| `upload` | `el-upload` | 隐藏上传按钮 |
| `number` | `el-input-number` | 置灰不可增减 |

### 6.3 数据生命周期

```
发起节点（弹窗）
  填写 → 提交 → nodeRecords.push + formData 聚合

执行节点（详情页操作区）
  readonly 字段回填 formData 前值，editable 字段正常交互
  填写 → 提交 → nodeRecords.push + formData 合并

确认 → ... → 关闭（全部 readonly）
```

### 6.4 载体

| 节点 | 载体 | 端 |
|------|------|-----|
| 发起 | `el-dialog` | Web |
| 指派 | 详情页操作区 | Web |
| 执行 | 详情页操作区 | Web / 小程序 |
| 确认 | 详情页操作区 | Web |
| 关闭 | 详情页（只读） | Web |

## 10. v1 vs v2 分界

| 能力 | v1（已实现） | v2+（规划中） |
|------|------------|-------------|
| 节点类型 | start / assign / execute / confirm / close / condition / external | 会签、或签、子流程 |
| 流转模式 | 顺序 + 操作结果分支 + 前节点超时分支 | 表单字段分支、并行 |
| 指派策略 | 岗位/人员/部门/角色/发起人/动态表单字段 | 轮询、最少指派 |

## 11. 关键业务规则

1. **双计时（端到端）**：TTR（任务到达→接单）+ TTS（接单→关闭）。无指派时 TTR 不适用，TTS 起点下沉
2. **接单仅在必要时出现**：仅 `static` + `multipleMode='anyone'` + 多人目标时出现接单步骤
3. **确认节点极简化**：默认一键通过，驳回需填写原因（必填）
4. **转单仅管理员**：强制改派需填写原因留痕
5. **状态三态标准化**：草稿 → 进行中 → 已关闭，进度由当前节点名称和步骤数体现
6. **已关闭只读**：归档后不可修改
7. **三方权限隔离**：物业看本企业、服务商看分配、监管看全量
8. **模板独立版本**：已发布模板锁定，修改需新建版本
9. **字段权限默认**：发起节点字段默认可编辑，其他节点对非本节点字段默认只读
10. **指派给发起人仅确认节点**：assign/execute 节点不支持此模式
