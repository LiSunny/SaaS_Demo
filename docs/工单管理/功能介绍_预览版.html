一、工单系统是什么

工单系统是智能安全管控平台的流程中枢，承载"任务流转与处置闭环"：一件事从发起、处理、把关到办结，全程在系统里走完，每一步都有记录、有时限、有责任人。

它的本质是一套可配置的通用流程引擎——工单的类型、要填哪些信息、按什么路线流转，都不写死在系统里，而是由管理员通过"模板"自由定义。因此它既能支撑企业内部协作（发起人、执行人、验收人都在本企业），也能支撑跨企业协同（业主方、服务商、监管方围绕同一张工单协作）。

工单系统解决三个老问题：

老问题工单系统的解法
任务靠口头、微信派活，说过就忘一切流转在系统内完成，每一步谁做的、什么时候做的，系统自动记录
办没办、办到哪了说不清工单有明确状态和进度，发起人随时可查，管理者全局可见
处理没有时限，拖到没人记得双计时管控（见下文），临近超时自动预警，超时红线可见

二、一张图看懂运转

一张工单的完整生命线：

flowchart LR A[管理员配置模板] --> B[发起人填表发起] B --> C{需要认领?} C -- 放到岗位认领 --> D[接单] C -- 指定到人 --> E[执行人处置] D --> E E --> F[审批人把关] F -- 驳回 --> E F -- 通过 --> G[工单关闭归档]

图中的每个环节都是一次"交接"：系统把任务从一个人手里交到下一个人手里，并记下交接时间。整条链路对所有工单通用，不同场景只是参与方和填的内容不同。

两种典型应用场景：

企业内工单跨企业协同工单
参与方本企业内部岗位业主方 + 服务商 + 监管方
典型例子消控值班员发现故障，发起维修单派给本企业工程师，安全管理人验收物业把维保任务委托给维保公司；监管方对隐患整改发起督办
链路特点发起 → 指派 → 执行 → 验收，全在本企业内处置环节跨企业：服务商干完，业主验收；监管可督办

两个场景共用同一套流转规则：同样的状态、同样的双计时、同样的留痕。学会一种，另一种自然会用。

三、核心概念速览

模板与工单——模板是图纸，工单是一次任务。管理员先画好图纸（模板），发起人照着填一张单子（工单），系统照图纸把任务送到该到的人手里。一份图纸可以开出无数张单子。

画这张图纸，就是配置模板时要做两件事：

  • 表单设计——定"这张单子要填什么"。要填哪些框、哪些必填、填文字还是传照片，管理员预先画好，发起人照着框填就行，不用想该写什么。
  • 流程设计——定"这张单子按什么路线走"。先给谁办、再给谁审、不通过退回给谁，像画一张接力路线图；任务走到哪一步，系统就自动把单子送到那一步负责人面前。

一句话：表单设计管"填什么"，流程设计管"怎么流"，两者合起来就是一份完整模板。

流程由 5 种基础节点和 1 种跨企业节点组成——流程设计就是用这些"积木"拼出接力路线：

节点一句话说明
开始工单的起点，发起人在这里填表提交
指派把任务分给具体的人：可指定到人，也可放到岗位由人认领
执行干活的步骤：处理人填写处置结果、上传照片
审批把关的步骤：审批人查看结果后通过或驳回
条件判断岔路口：系统按情况自动分流（如按是否超时走不同路线）
跨企业协同跨企业场景专用：任务流转到协作方企业，对方企业内部自行接力处理，办完结果自动回流（如业主把维保任务交给维保公司，维保公司内部安排工程师处理，处理结果回到业主这边）
说明：开始、结束由系统自动生成，不用配置；普通工单只用前 5 种基础节点，跨企业协同工单才会用到"跨企业协同"节点。

优先级——发起工单时选择，分四档：紧急 / 高 / 普通 / 低。优先级决定这张工单的两张"秒表"走多快。

SLA 双计时——每张工单挂着两张秒表：

  • 响应秒表：从发起到有人开始处理。按下的答复快不快；
  • 解决秒表：从发起到最终办结。量的是整件事办完快不快。

两张表各有各的时限。用时达到时限的 80% 亮黄灯提醒，超过时限亮红灯并触发升级动作。驳回、转交不会让秒表归零——超时的工单不会因为重新派单而"洗白"。

三种状态——草稿 / 进行中 / 已关闭。这是工单的状态，描述"这件任务办到哪了"。注意与模板状态区分：模板也有自己的状态，描述"这个模板能不能用"（见《使用说明》第 8 章），两者不要混淆。

四、一张工单里都有谁（最佳实践示例）

任何一张工单都由五种职责构成。职责跟着工单走，不跟着人固定——同一个人在这张单里是发起人，在下张单里可能就是执行人。五种职责可以由本企业不同岗位担任，也可以分属不同企业：

职责干什么
发起人填单发起，跟踪进度，验收把关
执行人认领（按需）并处理任务，填结果、传照片
审批人对执行结果把关：通过或驳回
管理督办岗盯全局、盯超时，必要时强制改派、取消
平台配置员配置模板，定义工单类型与流转规则

两张真实走单示例，看五种职责如何接力：

示例一：企业内维修单（消控值班员发现烟感报故障）

1. 消控值班员在「我的发起」选"设备维修"模板，填故障现象，发起工单 —— 发起人

2. 系统按模板把任务派给维修班；工程师小王在「待办任务」接单，换下故障烟感，填处置结果、拍照上传 —— 执行人

3. 消防安全管理人在「待办任务」里核对更换照片与测试记录，确认正常，点击通过 —— 审批人

4. 期间安全责任人翻「工单监控」看进度，发现这张单临近响应时限，电话提醒了维修班 —— 管理督办岗

5. 一整天的维修任务能顺畅转起来，靠的是平台管理员提前配好"设备维修"模板：要填什么、走哪些环节 —— 平台配置员

示例二：跨企业维保单（物业把月度维保委托给维保公司）

1. 物业管理人选"维保任务"模板发起，填维保范围与期限 —— 发起人（业主方）

2. 任务通过跨企业协同节点流转到维保公司：对方管理员指派维保工程师，工程师现场保养设备、上传记录 —— 执行人（服务方）

3. 维保公司项目负责人先做内部技术审核，通过后结果自动回流到物业 —— 审批人（服务方先行把关）

4. 物业管理人核对保养记录与照片后验收通过，工单关闭 —— 发起人兼审批人（业主方）

5. 若任务超期未完成，监管方可在「工单监控」看到这张单的红灯，发起督办推动处理 —— 管理督办岗（监管方）

两个示例用的是同一套模板机制、同一套流转规则——区别只在模板怎么配、职责分给谁。

五、你该用哪个入口

工单相关的菜单共 5 个，按使用身份分两类：

类别菜单干什么用
管理功能流程设计配置工单模板：定义工单类型、表单字段、流转规则
管理功能工单监控看全量工单、盯 SLA 超时预警、强制改派等督办干预
普通用户我的发起发起工单，跟踪我发起的工单进展
普通用户待办任务轮到我处理的事都在这里：执行、审批都从此进入
普通用户我的已办我处理完的任务留档，随时回查

"想做什么 → 用哪个"速查：

  • 发起工单、看我发起的进度 → 我的发起
  • 处理任务、审批验收 → 待办任务
  • 回查我处理过的记录 → 我的已办
  • 看全局、盯超时、督办干预 → 工单监控（管理岗）
  • 新建或调整工单类型 → 流程设计（管理岗）
