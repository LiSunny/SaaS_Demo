## 编写思路

1. **一份文档、两层读者**：第一篇"功能介绍"给认识它的人（新用户 / 管理层，讲价值与全景）；第二篇"使用说明"给用它的人（讲步骤）。
2. **使用篇以工单流转链路为主线**：配置 → 发起 → 处置 → 验收 → 监控督办。角色是链路上的"站牌"，每章开头标注"谁能操作"。
3. **入口按身份二分，独立成章**：管理功能（流程设计 / 工单监控）vs 普通用户功能（我的发起 / 待办任务 / 我的已办），单独讲清"你该用哪个"。
4. **规则全部白话化 + 举例**：SLA 双计时 →"两张秒表"；接单 →"认领任务"。全文不出现字段 / 节点类型 / 状态机等术语。
5. **界面用词与系统一致**：菜单名、按钮名与系统完全相同；同名功能在两篇中叫法统一。
6. **图表用 mermaid**：通用流转全景图（场景无关）+ 两种应用场景对比表；操作步骤配界面截图位。

**每章统一结构**：这章解决什么 → 谁能操作 → 操作步骤（截图位）→ 注意事项。

**范围约定**：介绍篇覆盖完整能力蓝图（含规划中的归档 / 看板 / 通知 / 移动端 / 督办，标注"规划中"）；使用篇只写当前可操作的功能。

**口径基准**：菜单结构与界面用词以**实际开发版本**为准——工单相关菜单共 5 个：管理功能（流程设计、工单监控）+ 普通用户功能（我的发起、待办任务、我的已办）；POC 工程及 `docs/工单管理/` 设计文档仅作业务素材参考，有出入处以实际为准。

## 第一篇 功能介绍 — 认识工单系统

### 1. 工单系统是什么
- 定位：智能安全管控平台的流程中枢，承载"任务流转与处置闭环"
- 本质：一套可配置的通用流程引擎——工单类型、表单、流转规则都可按需定义，覆盖企业内协作与跨企业协同两类场景
- 解决的三个问题：任务流转靠口头微信、过程无留痕 / 责任与时限难追溯 / 跨部门跨企业协同低效
- 素材来源：biz-design §一 模块定位

### 2. 一张图看懂运转
- mermaid 通用流转全景图（场景无关）：配置模板 → 发起 → （按需接单）→ 处置 → 验收 → 关闭
- 两种应用场景对比：
  - **企业内工单**：发起人 / 执行人 / 验收人都在本企业（例：消控值班员发起维修单，派给本企业工程师，安全管理人验收）
  - **跨企业协同工单**：业主方发起 → 服务商处置 → 业主验收，监管方督办（例：商业街物业委托维保公司、监管督办整改）
- 两个场景共用同一套流转链路与规则，只是参与方和模板不同
- 素材来源：biz-design §二 + §三 + §4.4

### 3. 核心概念速览
- 模板与工单（模板是图纸，工单是一次任务）
- **流程由 5 种节点组成**（配置模板时自由搭积木）：
  - **开始**：工单的起点，发起人在这里填表提交
  - **指派**：把任务分给具体的人（可指定到人，也可放到岗位由人认领）
  - **执行**：干活的步骤，处理人填写处置结果、上传照片
  - **审批**：把关的步骤，审批人查看结果后通过或驳回
  - **条件判断**：岔路口，系统按情况自动分流（如按是否超时走不同路线）
  - 注：开始/结束由系统自动生成；跨企业协同节点在"跨企业协同工单"场景中使用（见 §2）
- 优先级（四档：紧急 / 高 / 普通 / 低）
- SLA 双计时："两张秒表"——响应时限 + 解决时限
- 三种状态：草稿 / 进行中 / 已关闭 —— 这是**工单**的状态，描述"这件任务办到哪了"；模板另有自己的状态（能不能用、有没有停用），见第 8 章，两者不要混淆
- 素材来源：biz-design §五 关键业务规则 + FlowDesigner 节点面板

### 4. 你该用哪个入口
- 工单相关菜单共 5 个，按使用者身份分两类：
  - **管理功能**（管理岗）：**流程设计**（配置工单模板：类型 / 表单 / 流转规则）、**工单监控**（全量工单、SLA 预警、督办干预）
  - **普通用户功能**：**我的发起**（我发起的工单与进度跟踪）、**待办任务**（轮到我处理的任务：执行 / 审批都在这里）、**我的已办**（我处理完的任务，随时回查）
- "想做什么 → 用哪个"速查表：
  - 发起工单 / 看我发起的进度 → **我的发起**
  - 处理任务、审批验收 → **待办任务**
  - 回查我处理过的记录 → **我的已办**
  - 看全局、盯超时、督办干预 → **工单监控**（管理岗）
  - 新建 / 调整工单类型 → **流程设计**（管理岗）
- 素材来源：实际系统菜单结构（注：POC 设计文档 §八 "我的工单 vs 工单监控"两视角口径与实际菜单有出入，以实际 5 菜单为准）

### 5. 谁在工单里做什么
- 按工单内职责划分（场景无关）：发起人 / 执行人 / 验收人 / 管理督办岗 / 平台配置员——任何一张工单都由这五种职责构成，可由企业内不同岗位担任，也可分属不同企业
- 两类场景的岗位映射示例：
  - 企业内：消控值班员（发起）→ 本企业工程师（执行）→ 消防安全管理人（验收）
  - 跨企业：物业管理人（发起）→ 维保工程师（执行）→ 物业验收 + 监管督办
- 平台管理员只管模板配置与全平台干预，不参与具体工单流转
- 素材来源：平台岗位设计.md §三 + biz-design §4.4

### 6. 能力蓝图（规划中的能力）
- 已上线：模板配置 / 发起 / 监控 / 详情处置 / SLA 预警
- 规划中（标注"规划中"）：归档导出 / 统计看板 / 消息通知（站内+语音+短信）/ 移动端小程序 / 监管督办父子工单
- 素材来源：biz-design §四 功能全景（4.4–4.7）

## 第二篇 使用说明 — 上手操作

### 7. 找到入口
- 登录后从侧栏导航进入：普通用户用「我的发起 / 待办任务 / 我的已办」；管理岗另有「流程设计 / 工单监控」
- 配导航位置示意图（5 个菜单在侧栏中的位置）

### 8. 配置工单模板（平台管理员）
- 「流程设计」→ 模板列表 → 三步配置：基础设置 → 表单设计 → 流程设计 → 发布
- 模板的状态与工单状态是两回事：模板状态描述"这个模板能不能用"——发布后可被发起，也可停用/启用；工单状态（草稿/进行中/已关闭）描述"某件任务办到哪了"
- 注意：模板发布并产生工单后锁定，修改需新建版本；进行中的工单按发起时的版本走完
- 素材来源：ai-spec/流程模板列表页 + 流程模板配置页

### 9. 发起一张工单（有发起权限的岗位）
- 「我的发起」→ 发起工单：选模板 → 填标题 / 优先级 / 备注 → 填发起信息 → 保存草稿 或 立即发起
- 注意：草稿不进入监控统计，发起后才开始计时
- 素材来源：ai-spec/发起工单（发起入口按实际系统「我的发起」调整）

### 10. 处置工单（执行人）
- 「待办任务」→ 找到分给自己的任务：什么时候需要先"接单"——只有需要认领的任务（多人指派）才出现接单按钮；指定到人的任务打开即可处理
- 填写处置结果（拍照留痕的场景如实填写）→ 提交后流转下一节点，任务移入「我的已办」
- 素材来源：ai-spec/工单详情页 + biz-design §五 规则 2

### 11. 验收与驳回（发起方 / 管理岗）
- 审批任务同样出现在「待办任务」：验收看什么——整改结果与照片、整改前后对比
- 一键通过 vs 需填验收意见（模板配置决定）；驳回必填原因，工单回到执行人重新处理
- 素材来源：biz-design §五 规则 3 + 用户旅程 2.1

### 12. 监控与督办（管理岗）
- 「工单监控」：统计卡片（全部 / 草稿 / 进行中 / 已关闭）+ 筛选（编号 / 优先级 / 超时状态 / 日期）
- SLA 三色：用时可观（黄，达 80%）/ 超时（红）→ 及时督办
- 管理动作：强制改派（需填原因）/ 取消工单 / 手动关闭
- 素材来源：ai-spec/工单监控列表 + WorkOrderMonitor 现状

### 13. 看懂工单详情页
- 左栏：流程步骤进度 + 已完成信息（只读）+ 当前节点操作区
- 右栏：流转记录时间线（每一步谁做的、什么时候、做了什么）
- 已关闭的工单全局只读，可查响应时长 / 解决时长
- 素材来源：ai-spec/工单详情页 + WorkOrderDetail 现状

### 14. 常见问题（可裁剪）
- 超时了会怎样？→ 黄灯预警 / 红灯升级动作
- 驳回后工单去哪了？→ 回到执行节点，重新处理后再次提交验收
- 为什么看不到某张工单？→ 数据范围：本企业 / 与我相关 / 分配给我（对应 §4 入口章节）
- 模板发布后还能改吗？→ 锁定，需新建版本；进行中的工单按发起时的版本走完
