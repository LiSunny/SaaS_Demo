# 工作台 产品需求文档

> 版本：v2.0 | 日期：2026-06-03 | 状态：草稿

## 1. 背景与目标

### 1.1 业务背景

AI 安全管理平台横向有 9 个业务域，但缺少统一的首页入口——用户登录后直接跳转到维保计划页，不同角色无法第一时间看到与自己相关的工作概览。同时，物业管理员发起工单需要进入监控页（监管视角），权限和数据范围均不匹配。

### 1.2 模块目标

- **聚合**：打破模块壁垒，在一个页面呈现跨模块的关键信息
- **提效**：物业管理员从登录到发起工单 ≤ 2 次点击
- **角色化**：不同角色看到不同的内容，数据按角色隔离
- **可定制**：用户可根据习惯调整组件布局

### 1.3 适用范围

| 角色 | 端 | 使用场景 |
|------|-----|---------|
| 物业管理员 | Web | 每日登录后查看本企业工单/维保概览，快捷发起工单 |
| 安全监管员 | Web | 登录后查看 SLA 概况、超时工单，快速定位督办目标 |
| 消防服务工程师 | Web（次要） | 登录后查看待接单/处置中工单统计 |

## 2. 用户场景与需求

### 2.1 物业管理员的一天

> 张三是 xxx 物业管理有限公司的安全负责人，每天早上登录平台。

| 时刻 | 行为 | 需求 |
|------|------|------|
| 08:30 | 打开平台 | 第一眼看到本企业的工单状态和维保进度 |
| 08:32 | 发现消防栓泵报修还没处理 | 点击"发起工单"，选模板、填优先级，提交 |

**核心诉求**：快速了解"我的企业发生了什么"，快速发起操作。不需要看全平台的数据，不需要看 SLA 指标。

### 2.2 安全监管员的一天

> 李四是 zzz 安全管理中心的监管员，负责监督辖区内消防安全。

| 时刻 | 行为 | 需求 |
|------|------|------|
| 09:00 | 打开平台 | 第一眼看到 SLA 概况——几单超时、几单预警 |
| 09:02 | 发现 3 单超时 | 点击超时工单进入详情，发起督办 |
| 09:30 | 查看整体趋势 | 切换到工单数据看板查看本月趋势 |

**核心诉求**：快速定位问题工单，监管全局服务质量。需要看全平台数据，核心关注 SLA。

### 2.3 消防服务工程师的一天

> 王五是 yyy 消防技术服务公司的工程师，主要在微信小程序上操作，Web 端偶尔登录。

| 时刻 | 行为 | 需求 |
|------|------|------|
| 08:00 | 打开小程序 | 看到今天有 5 个待接单工单 |

**核心诉求**：快速看到"分配给我的任务"。Web 端是辅助，主力在小程序。

## 3. 功能规格

### 3.1 功能清单

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F1 | 仪表盘框架 | P0 | 可编辑、可排序的通用仪表盘引擎 |
| F2 | 工作台页面 | P0 | 角色化首页，`/` 默认落地 |
| F3 | Widget 组件体系 | P0 | 四类核心 Widget + 占位机制 |
| F4 | 布局编辑与持久化 | P1 | 排序、添加、移除 Widget，存 localStorage |

### 3.2 仪表盘框架（F1）

工作台底层依赖可复用的仪表盘框架。同一套框架支撑工作台、工单数据看板、维保数据看板等所有仪表盘页面。

**核心能力**：
- CSS Grid 响应式布局（≥1440px 为 3 列，1024-1439px 为 2 列）
- Widget 通过全局注册表按需异步加载
- 查看模式 / 编辑模式切换
- 角色预设 + 用户个性化布局持久化（localStorage）

详见 [仪表盘框架设计](../design/仪表盘框架/框架设计.md)。

### 3.3 Widget 体系（F3）

工作台上的内容以 Widget（组件卡片）为基本单元。每个 Widget 是一个独立的 Vue 组件，自己负责数据获取和状态处理。

**Widget 分为四类**：

| 类别 | 职责 | 说明 |
|------|------|------|
| **导航类** | 快速跳转到各业务模块 | 应用快捷入口 |
| **动作类** | 触发 Dialog/流程 | 快捷操作入口（发起工单等） |
| **任务类** | 聚合待办事项 | 我的待办 |
| **通知类** | 展示系统消息 | 消息通知 |
| **概览类** | 展示模块关键数据 | 工单概览、SLA 概览、维保概览… |

**Widget 通用规范**：
- 每个 Widget 接收 `widgetId` 和 `config` props
- 必须处理 loading（骨架屏）、empty（空态）、error（重试）三态
- 异常隔离：一个 Widget 崩溃不影响其他 Widget
- 数据按角色隔离：物业管理员只看本企业数据，监管员看全量

### 3.4 跨模块聚合规则

工作台不存储业务数据，所有数据来自各业务模块的已有 API：

```
工作台
  ├── 工单管理 API  ──→ 工单概览、SLA 概览、我的待办
  ├── 维保管理 API  ──→ 维保概览（阶段 2）
  ├── 隐患管理 API  ──→ 隐患概览（阶段 2）
  └── 消息中心 API  ──→ 消息通知（阶段 2）
```

**聚合原则**：
- 工作台只读摘要，不增删改业务数据
- Widget 异步独立加载，互不阻塞
- 模块未就绪时，对应 Widget 显示占位或隐藏

### 3.5 角色数据隔离

| 角色 | 数据范围 | 实现方式 |
|------|---------|---------|
| 物业管理员 | 本企业数据 | API 调用时传 orgId |
| 安全监管员 | 全平台数据 | 无过滤 |
| 消防服务工程师 | 分配给我的 | API 调用时传 assigneeId |

## 4. 布局编辑（F4）

### 4.1 查看模式
- 顶部：页面标题 + `[编辑布局]` 按钮
- 内容：Widget 网格，正常渲染数据

### 4.2 编辑模式
- 顶部：页面标题 + `[+ 添加组件]` `[保存布局]` `[恢复默认]`
- 每个 Widget 显示 ↑↓ 排序按钮 + × 删除按钮
- 组件池面板：网格展示可用组件，已添加的置灰
- 内容区半透明，不响应点击

### 4.3 持久化
- 保存 → localStorage（key: `dashboard:workbench:{role}`）
- 恢复默认 → 清除 localStorage，重载角色预设
- 编辑模式退出不自动保存

---

## 5. 数据结构

```json
{
  "WidgetSlot": {
    "id": "string（实例 ID，如 wb-1）",
    "type": "WidgetType（注册表中的 key）",
    "size": "1 | 2 | 3（列跨度）",
    "order": "number（排序序号）",
    "config?": { "actions": ["create-order"], "moduleName": "隐患管理" }
  },
  "DashboardPreset": {
    "id": "string",
    "label": "string",
    "roleDefaults": "Record<Role, WidgetSlot[]>",
    "availableWidgets": "WidgetType[]"
  }
}
```

---

## 6. 接口

工作台无独立后端接口。所有数据复用已有模块 API。布局配置完全前端管理。

---

## 7. 非功能需求

- **性能**：首屏 ≤ 1.5s（骨架屏过渡），单 Widget ≤ 300ms
- **兼容性**：Chrome / Firefox / Edge 最新版，≥ 1024px 桌面端
- **安全**：需登录，数据按角色隔离
- **存储**：单仪表盘布局 < 5KB，localStorage 失败时静默降级
