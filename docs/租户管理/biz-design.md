## 1. 定位

租户管理是平台管理（⚙️）分组下的核心域，负责**平台内所有企业的创建、属性配置、关联关系维护**。它是平台组织模型的实现层——所有业务域（维保、工单、巡查等）的数据权限和查询过滤都依赖本域定义的企业间关系链和企业属性。

**核心职责**：
- 企业全生命周期管理（创建、配置、停用）
- 企业属性体系维护（三维度自描述：单位类别 / 行业分类 / 场所类型）
- 企业间关联关系管理（下级管理 / 相关方），相关方关联时指定"关系角色"
- 为上层业务提供数据权限和过滤查询的元数据

## 2. 平台组织模型

### 2.1 扁平企业模型

平台采用**扁平企业模型**：所有主体在系统中均为平级"企业"，管理链通过企业间关联动态建立，而非系统固化层级。

```
┌─────────────────────────────────────────────────────┐
│  企业间关系层（跨企业数据权限）                        │
│  下级管理 / 相关方                                    │
│  本质：定义"谁能看到谁的数据"                           │
└─────────────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────┐
│  企业内管理层（各企业内部自己的组织方式）                │
│  管理单元 / 管辖区域 / 项目管理                         │
│  本质：定义"数据在内部怎么分组、怎么呈现"                │
└─────────────────────────────────────────────────────┘
```

两层完全解耦。同一个企业，在不同上级眼里，按各自选择的内部管理方式来看——物业公司用项目管理看它，监管方用管辖区域看它，互不影响。

### 2.2 两种企业间关联

| | 下级管理 | 相关方 |
|---|---|---|
| **语义** | "我管你" | "我把数据分享给你" |
| **发起方** | 上级发起 | 数据持有方发起 |
| **数据流向** | 下级 → 上级 | 发起方 → 对方 |
| **权限** | 自动全量 | 手动配置 |
| **约束** | 一企业一上级 | 无数量限制 |
| **关系角色** | — | 发起方指定"对方是我的谁"（见 §2.3） |

> "上级"是描述性用语，非系统标签。谁发起"下级管理"谁就是上级，关联类型本身定义方向。

### 2.3 相关方的"关系角色"

相关方关联时，发起方（数据持有方）必须指定关系角色，回答"**对方是我的谁**"，从"我的"视角出发，避免歧义。

| 关系角色 | 含义 | 典型场景 |
|---------|------|---------|
| **我的监管方** | 对方对我有监管/检查职能 | 商户 → 应急局、街道 |
| **我的管理方** | 对方是我的上级管理单位 | 商户 → 物业公司、商业街管理方 |
| **我的服务商** | 对方为我提供服务 | 物业 → 维保公司、检测机构 |
| **我的客户** | 我向对方提供服务 | 维保公司 → 物业 |
| **我的协作方** | 双方平等协作、信息互通 | 物业 ↔ 相邻物业、商户 ↔ 商户 |

> **设计原则**：角色在关联中定义，而非企业固有属性。同一家企业，对 A 可能是"我的服务商"，对 B 可能是"我的协作方"。角色随关系而变。

### 2.4 关联链与数据透传

```
链的形成（上级逐级发起"下级管理"）：

应急局 ──下级管理→ 街道 ──下级管理→ 阳光物业 ──下级管理→ 阳光物业某项目
                                                 ──下级管理→ 蓝盾消防（作为关联服务方纳入管理）

数据透传方向（沿链向上）：

应急局 ← 街道 ← 阳光物业 ← 阳光物业某项目
                          ← 蓝盾消防
```

- 数据权限沿链自动向上透传
- 一企业一上级，天然形成树状结构
- 层级按需创建，不强制完整

## 3. 企业属性体系

每个企业由**三个独立维度**描述自身，各自引用不同的标准体系，互不推导、互不覆盖。

### 3.1 维度概览

| 维度 | 名称 | 来源 | 用途 |
|------|------|------|------|
| **B** | 单位类别 | XF/T 3016.1-2022 §5.26 / 公安部令第61号 | 分类标签；命中重点单位类别时自动标记"消防安全重点单位" |
| **C** | 国民经济行业分类 | GB/T 4754-2017 国标 | 通用行业分析报表 |
| **D** | 场所/建筑类型 | XF/T 3016.1-2022 §5.88/§5.89 | 建筑级属性 |

> 原维度 A（平台管理角色）已从企业属性中移除，其值域迁移至相关方关联的"关系角色"字段（见 §2.3）。企业不再有固定的平台角色——角色在关联关系中定义。

### 3.2 维度 B：单位类别

**定义**：社会单位按使用性质和经营业态的分类。该字段是一个**通用分类标签**，不直接等同于"消防安全重点单位"——重点单位是依据法规按规模阈值判定的**法定身份**。

**来源**：

| 规范 | 说明 |
|------|------|
| **XF/T 3016.1-2022** §5.26 | 《消防信息代码 第 1 部分：基础业务信息》——消防安全重点单位类别代码，定义了标准化的场所类别枚举 |
| **公安部令第61号** | 《机关、团体、企业、事业单位消防安全管理规定》第十三条——将消防安全重点单位归纳为 12 大类，是全国消防救援机构每年核定重点单位的法律依据 |

**值域**（平台从 XF/T 3016.1-2022 §5.26 摘录，按需扩展）：

| 类别 | 说明 | 对应 61号令 类别 |
|------|------|:---:|
| 商场市场 | 商场、超市、集贸市场、批发市场 | 第1类 |
| 宾馆饭店 | 宾馆、酒店、饭店 | 第1类 |
| 公共娱乐场所 | 影院、KTV、网吧、剧本杀、密室逃脱 | 第1类 |
| 餐饮场所 | 独立餐饮门店 | 第1类 |
| 医院 | 医院、卫生院 | 第2类 |
| 学校 | 学校、幼儿园、托儿所 | 第2类 |
| 养老福利机构 | 养老院、福利院、日间照料中心 | 第2类 |
| 易燃易爆场所 | 化工厂、加油站、燃气站、充装站 | 第8类 |
| 高层/地下建筑 | 高层公共建筑、地下建筑 | 第11类 |
| 大型综合体 | 商业综合体（总建筑面积 ≥ 2万㎡） | 第11类 |
| 仓储物流 | 仓库、物流中心 | 第11类 |

> **扩展原则**：字典按 XF/T 3016.1-2022 §5.26 完整码表维护，上表仅列常用项。体育场馆、交通枢纽、文博单位、发电厂、劳动密集型企业等 30+ 类别按需从标准引用。

#### 3.2.1 消防安全重点单位自动标记

**设计原则**：单位类别是属性，消防安全重点单位是法定身份。平台**不替代消防机构核定重点单位**，但当企业选择的单位类别落入 61号令第1–12类范畴时，自动为企业打上「消防安全重点单位」标签，辅助平台运营方识别关注对象。

**触发规则**：
- 维度 B 选中上表中任一命中类别 → 企业标签自动追加 `消防安全重点单位`
- 维度 B 清空或改为未命中类别 → 自动移除该标签
- 用户可手动增删该标签（手动操作不被自动规则覆盖）

**61号令 12 大类对照**（供后续规则引擎参考）：

| 类别 | 61号令对应场所 | 规模阈值示例 |
|------|-------------|-------------|
| 第1类 | 商场(市场)、宾馆(饭店)、体育场馆、会堂、公共娱乐场所 | 经营可燃物品且总面积 > 3000㎡ |
| 第2类 | 医院、养老院、福利院、学校、托儿所、幼儿园 | 住院床位 ≥ 50张 |
| 第3类 | 国家机关 | 县级以上 |
| 第4类 | 广播、电视、邮政、通信枢纽 | — |
| 第5类 | 客运车站、码头、民用机场 | — |
| 第6类 | 公共图书馆、展览馆、博物馆、档案馆、文物保护单位 | 藏书 ≥ 50万册 |
| 第7类 | 发电厂（站）、储能电站、电网经营企业 | — |
| 第8类 | 易燃易爆化学物品单位 | — |
| 第9类 | 劳动密集型生产、加工企业 | 车间员工 > 100人 |
| 第10类 | 重要科研单位 | 省部属 |
| 第11类 | 高层公共建筑、地下铁道、物资仓库、物流仓库 | 一类高层 / 国家储备粮库 ≥ 1万吨 |
| 第12类 | 其他发生火灾可能性较大或可能造成重大人员伤亡/财产损失的单位 | 锂电池厂房、电化学储能电站等 |

> **注意**：第1–12类的规模阈值仅作参考，平台不据此自动判定。未来可在企业详情中增加"是否经消防机构核定为重点单位"的独立标识字段。

**定义**：企业的通用行业标签。

**来源**：引用 GB/T 4754-2017《国民经济行业分类》。

**值域**：国标 97 个大类（2 位码），平台取大类即可。摘录常见类别：

| 代码 | 行业 | 典型示例 |
|------|------|---------|
| 47 | 房屋建筑业 | 建筑公司 |
| 52 | 零售业 | 便利店、超市 |
| 62 | 餐饮业 | 餐馆、小吃店 |
| 80 | 居民服务业 | 理发店、洗衣店 |
| 85 | 教育 | 学校、培训机构 |
| 86 | 卫生 | 医院、诊所 |
| 91 | 国家机构 | 行政单位 |

> 推荐对接工商数据自动带出，减少手工填写。

### 3.4 维度 D：场所/建筑类型

**定义**：从消防安全角度对场所的分类。

**来源**：引用各省消防安全重点单位界定标准的场所分类框架。

**值域**：

| 类型 | 说明 |
|------|------|
| 人员密集场所 | 宾馆、商场、医院、学校、娱乐场所等 |
| 高层建筑 | 高层公共建筑、高层住宅 |
| 地下建筑 | 地下商场、地下车库 |
| 易燃易爆场所 | 化工厂、油库、气站 |
| 文物古建筑 | 文物保护单位、历史建筑 |
| 大型综合体 | 综合商业体 |
| 工业建筑 | 厂房、仓库 |
| 普通商铺 | 沿街小商铺（非重点单位） |
| ⋯ | 可扩展 |

### 3.5 各维度适用性

| | B 单位类别 | C 行业分类 | D 场所类型 |
|---|---|---|---|
| **适用企业** | 所有企业 | 所有企业 | 所有企业 |
| **是否必填** | 否（建议填写） | 否（推荐对接工商数据） | 否（建议填写） |
| **用途** | 消防单位分类标签 / 重点单位自动标记 | 通用行业分析报表 | 建筑级安全属性 |

**原则**：
- 三维度均为所有企业可选填
- B 和 C、D 建议填写，用于消防统计和风险评估
- 维度 C 建议对接工商数据自动带出
- B 命中重点单位类别时自动打标签

## 4. 关联关系与企业属性

### 4.1 核心原则

企业间关联的类型由**管理意图**决定：
- 想纳管某企业 → "下级管理"
- 想把数据分享给某企业 → "相关方" + 指定关系角色

企业自身的属性（B/C/D）描述"它是什么"，不影响能否建立某种关联。

### 4.2 关系角色与数据权限

相关方关联时指定的关系角色，当前为**标签性质**——帮助双方理解关联意图，不自动绑定数据权限。数据授权仍通过管理单元 + 操作权限开关手动配置（见 §6.3）。

未来可根据关系角色提供默认权限模板（如"我的服务商"默认勾选维保相关模块）。

### 4.3 查询过滤

| 做什么 | 怎么判断 |
|--------|--------|
| 找"我管辖的所有企业" | 沿下级管理链向下遍历 |
| 找"我的所有相关方" | 查相关方关联表，可按关系角色筛选 |
| 找"我的服务商" | 相关方列表筛关系角色 = 我的服务商 |
| 按消防类别统计 | 按维度 B 分组聚合 |
| 按行业出报表 | 按维度 C 分组聚合 |
| 决定谁可以看谁的数据 | 沿下级管理链逐级透传（不看 B/C/D） |

## 5. 典型部署场景

### 5.1 物业维保场景（四级）

```
区应急局（C=国家机构）
  │
某街道（C=国家机构）
  │
阳光物业（C=物业管理, D=高层建筑）
  │
  ├── 阳光花园项目（企业内部按管理单元组织）
  │     ├── 底商101 便利店    （B=商场市场, C=零售业, D=普通商铺）
  │     ├── 底商102 理发店    （B=..., C=居民服务业, D=普通商铺）
  │     └── ...
  │
  ├── 蓝盾消防（下级管理纳入监管）
  │
  └── XX快捷酒店（B=宾馆饭店, C=住宿业, D=人员密集场所）
```

### 5.2 集团管理场景

连锁企业总部统管所有门店的安全标准：

```
湘味源总部（C=餐饮业）
  ├── 湘味源中山路店（B=餐饮场所, C=餐饮业, D=普通商铺）
  ├── 湘味源解放路店（B=餐饮场所, C=餐饮业, D=普通商铺）
  └── 湘味源新区店  （B=餐饮场所, C=餐饮业, D=普通商铺）
```

### 5.3 混合部署

集团管理方和空间管理方可共存于同一链上：

```
某街道（C=国家机构）
  │
  ├── 阳光物业（C=物业管理）
  │     ├── 便利店A（B=商场市场, C=零售业, D=普通商铺）
  │     └── 理发店B（B=..., C=居民服务业, D=普通商铺）
  │
  └── 湘味源总部（C=餐饮业）
        ├── 湘味源中山路店（B=餐饮场所, C=餐饮业, D=普通商铺）
        └── 湘味源解放路店（B=餐饮场所, C=餐饮业, D=普通商铺）
```

## 6. 配置流程

### 6.1 企业创建

```
第一步：创建企业
  平台运营方在后台创建企业，填写：
  - 基本信息（名称、信用代码、联系人姓名、联系人手机号）
  - 维度 B/C/D 按 §3.5 的适用规则选填
  - 上级企业（可选）：仅支持检索/选择已有企业，不支持新建

第二步（自动触发）：初始化企业管理员账号
  提交创建时，系统自动执行以下原子操作：
  a. 创建企业记录，生成企业唯一码 + 二维码
  b. 以联系人手机号检索 User 表：
     - 已存在 → 匹配已有 User，不重复创建账号
     - 不存在 → 新建 User（phone=contactPhone, name=contactName, 初始密码=admin123!@#）
  c. 写入 UserEnterprise 关联（userId, enterpriseId, position=企业管理员, status=正常）
     - "企业管理员"为平台统一通用岗位（key=org-admin），不区分企业类型
  d. 若选了上级企业：
     - 创建企业间关联（上级 ──下级管理→ 新企业）
     - 校验：一企业一上级约束 + 环检测
     - 上下级数据权限沿链自动透传

第三步：各企业内部自行组织
  - 监管方按"管辖区域"组织
  - 管理方按"管理单元"对下级分组
  - 企业无内部嵌套
  - 企业管理员可在用户管理中做管理员移交
```

> **设计约束**：
> - 编辑企业时，修改联系人信息**不自动**同步 User 记录或 UserEnterprise 关系。更换联系人 ≠ 更换管理员。
> - 企业管理员移交（更换管理员账号）走用户管理模块的独立流程。
> - 上级企业只支持检索/选择已有企业——如需创建新上级，先创建该企业再回来选择。

### 6.2 相关方关联与关系角色

```
操作路径：企业详情 → 相关方管理 Tab → [关联相关方]

表单字段：
  - 企业选择器（多选远程搜索）
  - 关系角色（必选，下拉）：我的监管方 / 我的管理方 / 我的服务商 / 我的客户 / 我的协作方
  - 数据授权（可选，默认不授权）：
      - 管理单元选择器
      - 操作权限开关（允许操作 / 不允许操作）

提交后，关联关系携带关系角色，相关方列表可按角色筛选。
```

### 6.3 企业内管理视图

各企业可按需选用不同的内部管理视图：

| 视图 | 谁用 | 组织方式 | 核心诉求 |
|------|------|---------|---------|
| **管理单元** | 企业自己 | 树形分组 | 管理自己的设备/点位/人员 |
| **监管视图** | 监管部门 | 管辖区域 → 下级企业 | 看辖区的风险/履责情况 |
| **项目视图** | 运营企业 | 区域/片区 | 按区域看项目进度 |

三种视图互不干扰，各企业按需选用。

### 6.4 企业二维码

**生成规则**：
- 企业创建成功后，系统自动生成唯一的企业二维码
- 二维码编码内容：企业 H5 端入口 URL，携带企业唯一码参数（如 `https://platform.com/h5?qy=QY1013...`）
- 生成时机：创建企业时自动触发，不可手动创建

**展示位置**：
- 企业详情页（Tab 1 企业详情）显著位置，含二维码图片 + 企业名称 + 唯一码
- 支持下载二维码（PNG 格式），用于打印张贴（如履责卡、设备标签）

**容错机制**：
- 二维码图片生成失败时，支持手动"重新生成"按钮
- 企业唯一码不变时，二维码内容不变（确定性编码，非随机）

**应用场景**：

| 场景 | 说明 |
|------|------|
| 履责卡扫码 | 商户扫码直达 H5 端安全档案，完成每日打卡 |
| 设备关联 | 扫码将设备绑定到企业名下 |
| 巡查入口 | 检查人员扫码查看企业安全档案 |
| 信息快速定位 | 管理端扫码直达企业详情 |

### 6.5 统一入口

导航上合并为一个"组织管理"菜单，内部按权限展示可用子项：

```
导航栏
└── 组织管理              ← 唯一入口
    ├── 管理单元           我自己的，管企业内部设备和点位
    ├── 监管管理           我看别人的，沿下级管理链查看下级
    └── 项目管理           我看交付的，按区域跟踪项目进度
```

- 用户只有一个权限时直接展开，无需选择
- 每个子项带适用场景说明

## 7. 与现有平台的映射

### 7.1 数据权限集成

租户管理定义的关联链（含关系角色）和属性，是以下业务域数据权限的基础：

| 业务域 | 依赖的元数据 |
|--------|------------|
| 工单管理 | 下级管理链（上级看下级工单）、关系角色（如"我的服务商"可被分配工单） |
| 维保管理 | 下级管理链（物业看维保服务商的维保记录）、关系角色（"我的服务商"身份识别） |
| 巡查检查 | 下级管理链（监管方看辖区巡查记录）、维度 B/D（检查清单模板匹配） |
| 数据可视化 | 维度 B/C/D（大屏统计分类维度） |
| 远程值守 | 下级管理链（上级看下级告警） |

### 7.2 与旧版维度 A 的对比

| | 旧设计（v1.x） | 新设计（v2.0） |
|---|---|---|
| 角色定义位置 | 企业固有属性（维度 A） | 相关方关联时指定（关系角色） |
| 角色是否可变 | 固定（编辑企业属性才可变） | 随关联关系而变，不同相关方看同一企业可有不同角色 |
| "我是谁" | 企业自描述 | 不关心"我是谁"，关心"在别人眼里我是谁" |
| 列表筛选 | 可按角色筛 | 不可按角色筛（无固定角色） |

## 8. 设计决策记录

| # | 决策 | 结论 |
|---|------|------|
| 1 | 企业分类是否单一字段 | 拆为 B/C/D 三个独立维度，各引用不同标准 |
| 2 | ~~维度 A（平台管理角色）的值域~~ | **v2.0 已废弃**，角色迁移至相关方关联的"关系角色"字段 |
| 3 | 维度 B（单位类别）引用标准 | XF/T 3016.1-2022 第 5.26 条 + 公安部令第61号 |
| 4 | 维度 C（行业分类）引用标准 | GB/T 4754-2017 |
| 5 | 维度 D（场所类型）引用标准 | 各省消防安全重点单位界定标准 |
| 6 | 管理链与属性是否相关 | 正交。关联类型看管理意图，不看企业属性 |
| 7 | ~~链位置是否用于推断角色~~ | **v2.0 已废弃**，角色不再由属性或链位置推断，由关联关系定义 |
| 8 | 各维度适用性 | B/C/D 所有企业可选填，非必填 |
| 9 | 关联关系方向判定 | 谁发起"下级管理"谁就是上级，关联类型本身定义方向 |
| 10 | 企业间关系与企业内管理是否解耦 | 完全解耦。两层独立运作，互不干扰 |
| 11 | 企业二维码生成规则 | 创建企业时自动生成，编码 H5 入口 URL + 企业唯一码；唯一码不变则二维码不变 |
| 12 | **v2.0** 角色从属性剥离 | 企业属性去维度 A；维度 A 值域 → 相关方关联的"关系角色"字段（"我的监管方/管理方/服务商/客户/协作方"）。角色由关联定义，非企业固有。 |
| 13 | 消防安全重点单位标记触发条件 | **v2.0 简化**：仅由维度 B 是否命中 61号令类别触发，不再依赖维度 A |
| 14 | 创建企业时自动初始化管理员账号 | **v2.1 新增**：以联系人手机号检索/创建 User → 统一分配"企业管理员"岗位 → 写入 UserEnterprise。若选了上级企业则自动建立下级管理关联。编辑企业时不同步修改 User/关联。管理员移交走用户管理独立流程。 |
| 15 | 企业管理员岗位统一 | **v2.1 新增**：平台统一"企业管理员"岗位（key=`org-admin`），不区分物业/服务/监管方。现有 4 变体保留给特殊场景手动分配。 |
