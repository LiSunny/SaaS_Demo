## 1. 定位

租户管理是平台管理（⚙️）分组下的核心域，负责**平台内所有企业的创建、属性配置、关联关系维护**。它是平台组织模型的实现层——所有业务域（维保、工单、巡查等）的数据权限和查询过滤都依赖本域定义的企业间关系链和企业属性。

**核心职责**：
- 企业全生命周期管理（创建、配置、停用）
- 企业属性体系维护（四维度自描述）
- 企业间关联关系管理（下级管理 / 相关方）
- 为上层业务提供数据权限和过滤查询的元数据

## 2. 平台组织模型

### 2.1 扁平企业模型

平台采用**扁平企业模型**：所有主体在系统中均为平级"企业"，管理链通过企业间关联动态建立，而非系统固化层级。

```
┌─────────────────────────────────────────────────────┐
│  企业间关系层（跨企业数据权限）                        │
│  下级管理 / 相关方                                    │
│  本质：定义"谁能看到谁的数据"                           │
└─────────────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────┐
│  企业内管理层（各企业内部自己的组织方式）                │
│  管理单元 / 管辖区域 / 项目管理                         │
│  本质：定义"数据在内部怎么分组、怎么呈现"                │
└─────────────────────────────────────────────────────┘
```

两层完全解耦。同一个企业，在不同上级眼里，按各自选择的内部管理方式来看——物业公司用项目管理看它，监管方用管辖区域看它，互不影响。

### 2.2 两种企业间关联

| | 下级管理 | 相关方 |
|---|---|---|
| **语义** | "我管你" | "我把数据分享给你" |
| **发起方** | 上级发起 | 数据持有方发起 |
| **数据流向** | 下级 → 上级 | 发起方 → 对方 |
| **权限** | 自动全量 | 手动配置 |
| **约束** | 一企业一上级 | 无数量限制 |

> "上级"是描述性用语，非系统标签。谁发起"下级管理"谁就是上级，关联类型本身定义方向。

### 2.3 关联链与数据透传

```
链的形成（上级逐级发起"下级管理"）：

应急局 ──下级管理→ 街道 ──下级管理→ 阳光物业 ──下级管理→ 阳光物业某项目
                                                 ──下级管理→ 蓝盾消防（作为关联服务方纳入管理）

数据透传方向（沿链向上）：

应急局 ← 街道 ← 阳光物业 ← 阳光物业某项目
                          ← 蓝盾消防
```

- 数据权限沿链自动向上透传
- 一企业一上级，天然形成树状结构
- 层级按需创建，不强制完整

## 3. 企业属性体系

每个企业由**四个独立维度**描述自身，各自引用不同的标准体系，互不推导、互不覆盖。

### 3.1 维度概览

| 维度 | 名称 | 来源 | 用途 |
|------|------|------|------|
| **A** | 平台管理角色 | 平台自定义 | 管理链行为、数据权限、查询过滤 |
| **B** | 单位类别 | XF/T 3016.1-2022 §5.26 / 公安部令第61号 | 分类标签；命中重点单位类别时自动标记"消防安全重点单位" |
| **C** | 国民经济行业分类 | GB/T 4754-2017 国标 | 通用行业分析报表 |
| **D** | 场所/建筑类型 | XF/T 3016.1-2022 §5.88/§5.89 | 建筑级属性，在企业注册时不填写，归属建筑管理模块 |

### 3.2 维度 A：平台管理角色

**定义**：企业在平台中的管理角色，定义"你是干什么的"。

**来源**：平台自定义。

**值域**：

| 一级 | 二级 | 三级 | 说明 |
|------|------|------|------|
| **监管方** | — | 消防救援机构 | 消防支队、大队，专业消防监管 |
| | | 应急管理部门 | 市/区应急局，统筹辖区安全态势 |
| | | 属地政府 | 街道、乡镇、社区/村，基层行政管理 |
| | | 行业主管部门 | 教育局、卫健委等，行业条线监管 |
| **管理方** | **空间管理方** | 物业管理方 | 管小区底商、写字楼商户 |
| | | 园区管理方 | 管园区入驻企业 |
| | | 市场管理方 | 管批发市场、农贸市场内摊位 |
| | | 综合体管理方 | 管购物中心、大型商场内店铺 |
| | | 商业街管理方 | 管一条街的商铺 |
| | **集团管理方** | — | 管有组织隶属关系的下属单位（如连锁品牌总部管所有门店） |
| **社会单位** | — | — | 消防安全第一责任人 |
| **服务单位** | — | 消防技术服务机构 | 维保、检测、评估、工程安装等 |
| **平台运营方** | — | — | 运营本 SaaS 平台的主体 |

> 管理方按管理边界分为两类：空间管理方管一地理范围内的单位，集团管理方管有组织隶属关系的下属单位。两者共享"管理方"一级分类。

### 3.3 维度 B：单位类别

**定义**：社会单位按使用性质和经营业态的分类。该字段是一个**通用分类标签**，不直接等同于"消防安全重点单位"——重点单位是依据法规按规模阈值判定的**法定身份**。

**来源**：

| 规范 | 说明 |
|------|------|
| **XF/T 3016.1-2022** §5.26 | 《消防信息代码 第 1 部分：基础业务信息》——消防安全重点单位类别代码，定义了标准化的场所类别枚举 |
| **公安部令第61号** | 《机关、团体、企业、事业单位消防安全管理规定》第十三条——将消防安全重点单位归纳为 12 大类，是全国消防救援机构每年核定重点单位的法律依据 |

**值域**（平台从 XF/T 3016.1-2022 §5.26 摘录，按需扩展）：

| 类别 | 说明 | 对应 61号令 类别 |
|------|------|:---:|
| 商场市场 | 商场、超市、集贸市场、批发市场 | 第1类 |
| 宾馆饭店 | 宾馆、酒店、饭店 | 第1类 |
| 公共娱乐场所 | 影院、KTV、网吧、剧本杀、密室逃脱 | 第1类 |
| 餐饮场所 | 独立餐饮门店 | 第1类 |
| 医院 | 医院、卫生院 | 第2类 |
| 学校 | 学校、幼儿园、托儿所 | 第2类 |
| 养老福利机构 | 养老院、福利院、日间照料中心 | 第2类 |
| 易燃易爆场所 | 化工厂、加油站、燃气站、充装站 | 第8类 |
| 高层/地下建筑 | 高层公共建筑、地下建筑 | 第11类 |
| 大型综合体 | 商业综合体（总建筑面积 ≥ 2万㎡） | 第11类 |
| 仓储物流 | 仓库、物流中心 | 第11类 |

> **扩展原则**：字典按 XF/T 3016.1-2022 §5.26 完整码表维护，上表仅列常用项。体育场馆、交通枢纽、文博单位、发电厂、劳动密集型企业等 30+ 类别按需从标准引用。

#### 3.3.1 消防安全重点单位自动标记

**设计原则**：单位类别是属性，消防安全重点单位是法定身份。平台**不替代消防机构核定重点单位**，但当企业选择的单位类别落入 61号令第1–12类范畴时，自动为企业打上「消防安全重点单位」标签，辅助平台运营方识别关注对象。

**触发规则**：
- 维度 A 选择"社会单位" **且** 维度 B 选中上表中任一命中类别 → 企业标签自动追加 `消防安全重点单位`
- 维度 B 清空或改为未命中类别 → 自动移除该标签
- 用户可手动增删该标签（手动操作不被自动规则覆盖）

**61号令 12 大类对照**（供后续规则引擎参考）：

| 类别 | 61号令对应场所 | 规模阈值示例 |
|------|-------------|-------------|
| 第1类 | 商场(市场)、宾馆(饭店)、体育场馆、会堂、公共娱乐场所 | 经营可燃物品且总面积 > 3000㎡ |
| 第2类 | 医院、养老院、福利院、学校、托儿所、幼儿园 | 住院床位 ≥ 50张 |
| 第3类 | 国家机关 | 县级以上 |
| 第4类 | 广播、电视、邮政、通信枢纽 | — |
| 第5类 | 客运车站、码头、民用机场 | — |
| 第6类 | 公共图书馆、展览馆、博物馆、档案馆、文物保护单位 | 藏书 ≥ 50万册 |
| 第7类 | 发电厂（站）、储能电站、电网经营企业 | — |
| 第8类 | 易燃易爆化学物品单位 | — |
| 第9类 | 劳动密集型生产、加工企业 | 车间员工 > 100人 |
| 第10类 | 重要科研单位 | 省部属 |
| 第11类 | 高层公共建筑、地下铁道、物资仓库、物流仓库 | 一类高层 / 国家储备粮库 ≥ 1万吨 |
| 第12类 | 其他发生火灾可能性较大或可能造成重大人员伤亡/财产损失的单位 | 锂电池厂房、电化学储能电站等 |

> **注意**：第1–12类的规模阈值仅作参考，平台不据此自动判定。未来可在企业详情中增加"是否经消防机构核定为重点单位"的独立标识字段。

### 3.6 各角色适用性

| | 监管方 | 管理方 | 社会单位 | 服务方 | 平台运营方 |
|---|---|---|---|---|---|
| **A 平台管理角色** | ✅ 必填 | ✅ 必填 | ✅ 必填 | ✅ 必填 | ✅ 必填 |
| **B 单位类别** | — | — | ✅ 必填 | — | — |
| **C 行业分类** | ○ 可选 | ○ 可选 | ✅ 推荐 | ○ 可选 | ○ 可选 |
| **D 场所类型** | — | ○ 可选 | ✅ 必填 | — | — |

**原则**：
- A 是所有企业的必填项，定义管理链角色
- B 和 D 仅对社会单位有意义，用于消防统计和风险评估
- C 建议对接工商数据自动带出
- 管理方可选填 D，有助于管理端展示

## 4. 关联关系与属性正交

### 4.1 核心原则

关联类型的选择取决于**要建立什么管理关系**，与双方企业的平台管理角色（维度 A）无关。

- 应急局是"监管方"，街道也是"监管方"，它们之间照样用"下级管理"——因为应急局要看街道的数据
- 物业是"管理方"，商户是"社会单位"，物业纳管商户也用"下级管理"
- 物业把维保公司加为"相关方"，维保公司是"服务单位"——但关联类型是"相关方"，不是因为它是服务单位

### 4.2 决策依据

| 做什么 | 怎么判断 |
|--------|--------|
| 找"我管辖的所有物业公司" | 沿下级管理链向下遍历，筛维度 A = 管理方/物业管理方 |
| 找"我管辖的所有维保服务商" | 沿下级管理链向下遍历，筛维度 A = 服务单位/消防技术服务机构 |
| 找"我管辖的所有社会单位" | 沿下级管理链向下遍历，筛维度 A = 社会单位 |
| 按消防类别统计 | 筛维度 A = 社会单位 → 按维度 B 分组聚合 |
| 按行业出报表 | 筛维度 A = 社会单位 → 按维度 C 分组聚合 |
| 决定谁可以看谁的数据 | 沿下级管理链逐级透传，不看维度 A/B/C/D |

### 4.3 为什么不用链位置判断角色？

链位置不可靠——加一层省应急局，"顶端节点"判断失效；再加一层市应急局，"第 3 层是物业"假设也失效。

维度 A 是企业对自身的客观描述，不依赖链位置、不因链变化而改变。

## 5. 典型部署场景

### 5.1 物业维保场景（四级）

```
区应急局（A=监管方/应急管理部门, C=国家机构）
  │
某街道（A=监管方/属地政府, C=国家机构）
  │
阳光物业（A=管理方/物业管理方, C=物业管理, D=高层建筑）
  │
  ├── 阳光花园项目（A=管理方/空间管理方, 企业内部按管理单元组织）
  │     ├── 底商101 便利店    （A=社会单位, B=商场市场, C=零售业, D=普通商铺）
  │     ├── 底商102 理发店    （A=社会单位, B=..., C=居民服务业, D=普通商铺）
  │     └── ...
  │
  ├── 蓝盾消防（A=服务单位/消防技术服务机构, 下级管理纳入监管）
  │
  └── XX快捷酒店（A=社会单位, B=宾馆饭店, C=住宿业, D=人员密集场所）
```

### 5.2 集团管理场景

连锁企业总部统管所有门店的安全标准：

```
湘味源总部（A=管理方/集团管理方, C=餐饮业）
  ├── 湘味源中山路店（A=社会单位, B=餐饮场所, C=餐饮业, D=普通商铺）
  ├── 湘味源解放路店（A=社会单位, B=餐饮场所, C=餐饮业, D=普通商铺）
  └── 湘味源新区店  （A=社会单位, B=餐饮场所, C=餐饮业, D=普通商铺）
```

属性特点：
- 总部选**管理方/集团管理方**，自身不填 B/D
- 门店选**社会单位**，填 B/D 与普通商户无异
- 总部通过下级管理链看门店数据

### 5.3 混合部署

集团管理方和空间管理方可共存于同一链上：

```
某街道（A=监管方/属地政府）
  │
  ├── 阳光物业（A=管理方/空间管理方/物业管理方）
  │     ├── 便利店A（A=社会单位, ...）
  │     └── 理发店B（A=社会单位, ...）
  │
  └── 湘味源总部（A=管理方/集团管理方）
        ├── 湘味源中山路店（A=社会单位, ...）
        └── 湘味源解放路店（A=社会单位, ...）
```

## 6. 配置流程

### 6.1 企业创建

```
第一步：创建企业
  平台运营方（赵启明）在后台创建企业，填写：
  - 基本信息（名称、信用代码、联系人）
  - 维度 A 平台管理角色（必填）
  - 维度 B/C/D 按 §3.6 的适用规则选填

第二步：建立关联链
  在上级企业的"下级管理"页面：
  - 搜索已创建的目标企业
  - 添加为下级
  - 自上而下逐级建立关联

第三步：各企业内部自行组织
  - 监管方按"管辖区域"组织
  - 管理方按"管理单元"对下级分组
  - 社会单位 / 服务单位：无内部嵌套
```

### 6.2 企业内管理视图

各企业可按需选用不同的内部管理视图：

| 视图 | 谁用 | 组织方式 | 核心诉求 |
|------|------|---------|---------|
| **管理单元** | 企业自己 | 树形分组 | 管理自己的设备/点位/人员 |
| **监管视图** | 监管部门 | 管辖区域 → 下级企业 | 看辖区的风险/履责情况 |
| **项目视图** | 运营企业 | 区域/片区 | 按区域看项目进度 |

三种视图互不干扰，各企业按需选用。

### 6.4 企业二维码

**生成规则**：
- 企业创建成功后，系统自动生成唯一的企业二维码
- 二维码编码内容：企业 H5 端入口 URL，携带企业唯一码参数（如 `https://platform.com/h5?qy=QY1013...`）
- 生成时机：创建企业时自动触发，不可手动创建

**展示位置**：
- 企业详情页（Tab 1 企业详情）显著位置，含二维码图片 + 企业名称 + 唯一码
- 支持下载二维码（PNG 格式），用于打印张贴（如履责卡、设备标签）

**容错机制**：
- 二维码图片生成失败时，支持手动"重新生成"按钮
- 企业唯一码不变时，二维码内容不变（确定性编码，非随机）

**应用场景**：

| 场景 | 说明 |
|------|------|
| 履责卡扫码 | 商户扫码直达 H5 端安全档案，完成每日打卡 |
| 设备关联 | 扫码将设备绑定到企业名下 |
| 巡查入口 | 检查人员扫码查看企业安全档案 |
| 信息快速定位 | 管理端扫码直达企业详情 |

### 6.5 统一入口

导航上合并为一个"组织管理"菜单，内部按权限展示可用子项：

```
导航栏
└── 组织管理              ← 唯一入口
    ├── 管理单元           我自己的，管企业内部设备和点位
    ├── 监管管理           我看别人的，沿下级管理链查看下级
    └── 项目管理           我看交付的，按区域跟踪项目进度
```

- 用户只有一个权限时直接展开，无需选择
- 每个子项带适用场景说明

## 8. 设计决策记录

| # | 决策 | 结论 |
|---|------|------|
| 1 | 企业分类是否单一字段 | 拆为 A/B/C/D 四个独立维度，各引用不同标准 |
| 2 | 维度 A（平台管理角色）的值域 | 三级结构：监管方 / 管理方 / 社会单位 / 服务单位 / 平台运营方 |
| 3 | 维度 B（单位类别）引用标准 | XF/T 3016.1-2022 第 5.26 条 + 公安部令第61号 |
| 4 | 维度 C（行业分类）引用标准 | GB/T 4754-2017 |
| 5 | 维度 D（场所类型）引用标准 | 各省消防安全重点单位界定标准 |
| 6 | 管理链与属性是否相关 | 正交。关联类型看管理意图，不看双方属性 |
| 7 | 链位置是否用于推断角色 | 否。角色由维度 A 自描述，不靠链位置推断 |
| 8 | 各维度适用性 | A 全员必填；B/D 仅社会单位必填；C 推荐对接工商数据 |
| 9 | 关联关系方向判定 | 谁发起"下级管理"谁就是上级，关联类型本身定义方向 |
| 10 | 企业间关系与企业内管理是否解耦 | 完全解耦。两层独立运作，互不干扰 |
| 11 | 企业二维码生成规则 | 创建企业时自动生成，编码 H5 入口 URL + 企业唯一码；唯一码不变则二维码不变 |
