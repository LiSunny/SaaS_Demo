## 一、页面元信息

| 项目 | 内容 |
|------|------|
| 功能名称 | `相关方管理` |
| 所属模块 | `租户管理 > 企业详情 > Tab: 相关方管理` |
| 功能类型 | `列表管理 + 关联操作 + 数据授权` |

### 功能描述

在企业详情页的相关方管理 Tab 中，管理当前企业与外部企业的**数据共享关系**。核心操作：
- **关联相关方**：选择目标企业 + 指定关系角色（从"我的"视角），建立关联
- **数据授权**：为每个相关方配置管理单元范围 + 操作权限开关
- **取消关联**：解除数据共享关系
- 列表支持按企业名称、标签、关系角色筛选

## 三、数据模型

### 3.1 相关方实体 (PartnerItem)

| 字段名 | 中文名 | 类型 | 说明 |
|--------|--------|------|------|
| `id` | 关联 ID | `string` | 关联关系唯一标识 |
| `enterpriseId` | 相关方企业 ID | `string` | 对方企业 ID |
| `enterpriseName` | 相关方企业名称 | `string` | — |
| `role` | 关系角色 | `PartnerRole` | **必填**，关联时指定，见 §3.2 |
| `tags` | 企业标签 | `string[]` | 对方企业的标签列表 |
| `contactName` | 负责人 | `string` | — |
| `contactPhone` | 联系电话 | `string` | — |
| `relatedAt` | 关联时间 | `string` | ISO 8601 |
| `operatorName` | 操作人 | `string` | 谁执行的关联操作 |
| `authUnits` | 授权管理单元 | `string[]` | 该相关方可访问的管理单元 ID 列表 |
| `allowOperation` | 允许操作 | `boolean` | 是否允许该相关方在企业内执行操作 |

### 3.2 关系角色枚举 (PartnerRole)

**设计原则**：从发起方（数据持有方）"我的"视角定义，角色标签始终以"我的"开头避免歧义。

| 枚举值 | 标签文字 | 含义 | 典型场景 |
|--------|---------|------|---------|
| `my_supervisor` | 我的监管方 | 对方对我有监管/检查职能 | 商户 → 应急局、街道 |
| `my_manager` | 我的管理方 | 对方是我的上级管理单位 | 商户 → 物业公司 |
| `my_service_provider` | 我的服务商 | 对方为我提供服务 | 物业 → 维保公司 |
| `my_customer` | 我的客户 | 我向对方提供服务 | 维保公司 → 物业 |
| `my_collaborator` | 我的协作方 | 双方平等协作、信息互通 | 物业 ↔ 相邻物业 |

### 3.3 关系角色 StatusTag 颜色

| 角色 | 颜色类型 | el-tag type |
|------|:--:|------|
| 我的监管方 | `info` | 蓝色 |
| 我的管理方 | `warning` | 橙色 |
| 我的服务商 | 自定义 `#10B981` | 绿色 |
| 我的客户 | `normal` | 灰色 |
| 我的协作方 | 自定义 `#8B5CF6` | 紫色 |

## 四、接口定义

### 4.1 相关方列表与操作

| 操作 | 方法 | 路径 | 请求参数 | 响应类型 |
|------|------|------|---------|---------|

| 取消相关方关联 | `DELETE` | `/api/admin/enterprises/{id}/partners` | `{ids: string[]}` | — |

| 保存数据授权 | `PUT` | `/api/admin/enterprises/partners/{relationId}/auth` | `{authUnits: string[], allowOperation: boolean}` | `PartnerItem` |

## 六、业务逻辑

### 6.1 关联相关方流程

```
点击 [关联相关方]
  │
  ├── 打开关联弹窗
  │     ├── 远程搜索企业（多选，防抖 300ms）
  │     │     ├── 排除当前企业自身
  │     │     ├── 排除已是相关方的企业
  │     │     └── 排除已是下级的被管企业（避免双重关联）
  │     └── 选择关系角色（必选，单选）
  │
  └── 点击 [确定]
        ├── 校验：至少选 1 个企业 + 必须选关系角色
        ├── POST /api/admin/enterprises/{id}/partners { enterpriseIds, role }
        ├── 成功：ElMessage.success('关联成功') + 关闭弹窗 + 刷新列表
        └── 失败：ElMessage.error(后端返回的 message)
```

### 6.2 取消关联流程

```
选中行(checkbox) → 点击 [取消关联]
  │
  ├── 未选中行 → ElMessage.warning('请先选择相关方')
  │
  └── 已选中
        ├── ElMessageBox.confirm('确认取消与「{企业名称}」的相关方关联？取消后该企业将无法访问你的数据。')
        ├── [确认] → DELETE /api/admin/enterprises/{id}/partners { ids: [...] }
        ├── 成功 → ElMessage.success('已取消关联') + 刷新列表
        └── [取消] → 不做任何操作
```

### 6.3 数据授权流程

```
点击行操作 [数据授权]
  │
  ├── 打开数据授权弹窗
  │     ├── GET 接口获取当前授权状态（authUnits + allowOperation），回填表单
  │     ├── 管理单元 select：远程加载当前企业可用的管理单元列表
  │     └── 操作权限 switch：默认"不允许操作"
  │
  └── 点击 [保存]
        ├── PUT /api/admin/enterprises/partners/{relationId}/auth { authUnits, allowOperation }
        ├── 成功 → ElMessage.success('数据授权已保存') + 关闭弹窗
        └── 失败 → ElMessage.error
```

### 6.4 交互行为汇总

| 操作 | 触发条件 | 行为描述 |
|------|---------|---------|
| 查询 | 点击[查询] / 筛选条件变化 | 按当前筛选条件请求列表接口，刷新表格 |
| 重置 | 点击[重置] | 清空所有筛选条件 → 查询 |
| 关联相关方 | 点击[关联相关方] | 打开关联弹窗（见 §6.1） |
| 批量取消关联 | 选中 ≥1 行，点击[取消关联] | 走 §6.2 流程 |
| 单行取消关联 | 点击行操作[取消关联] | 自动选中该行 → 走 §6.2 流程 |
| 数据授权 | 点击行操作[数据授权] | 打开数据授权弹窗（见 §6.3） |
| 切换 Tab | 点击「相关方管理」Tab | Tab 首次进入时加载数据 |

### 6.5 特殊规则

- 相关方关联**无数量限制**，同一企业可关联无数个相关方
- **不阻止重复关联**同一企业——如果 A 已经以"我的服务商"关联了 B，用户仍然可以再次以"我的协作方"关联 B（不同角色视为不同关联）。如需限制，可在后端添加 `enterpriseId + role` 唯一约束
- 关联弹窗中的企业选择器**拉取全平台企业**（排除自身 + 已有相关方 + 已有下级关联的企业）
- 取消关联不校验数据依赖，直接解除（数据授权随之失效）
- 关系角色列展示为 StatusTag，按 §3.3 的颜色规则
- 列表默认按关联时间倒序（最近关联的在前）
- 分页器与列表页风格一致（`el-pagination` background）

## 八、与下级管理 Tab 的对照

| | 下级管理 | 相关方管理 |
|---|---|---|
| **语义** | "我管你" | "我把数据分享给你" |
| **发起方** | 上级发起 | 数据持有方发起 |
| **数据权限** | 自动全量 | 手动配置（数据授权弹窗） |

| **数量约束** | 一企业一上级 | 无限制 |

| **表格列差异** | 企业名称 + 标签 + 关联日期 + 操作人 | + 关系角色 StatusTag + 负责人 + 联系电话 + 操作([数据授权] + [取消关联]) |
