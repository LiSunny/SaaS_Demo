人工智能 + 智能安全管控平台

部署架构图 —— 一次访问要走哪几段、每段装在哪、出问题看哪里
当前规模：一台云服务器
第一段 · 用户访问用户从自己的设备打开网页，这一段不在我们服务器上
电脑浏览器（管理端日常操作） 大屏显示器（监管大屏 / 企业驾驶舱） 手机浏览器（现场拍照与巡查，规划中）
通过网址访问▼
第二段 · 接入层对外的唯一入口，所有请求都从这里进
域名与安全证书
对外统一的网址，全程加密访问；证书到期需要续期，否则浏览器会报警告。
网关（负责分流）
收到请求后只做一件事：判断这是"要页面文件"还是"要数据接口"， 前者直接返回，后者转给后端处理。
页面文件 → 直接返回
数据接口 → 转给后端
分流▼
第三段 · 应用层真正跑在服务器上的两个东西
前端页面文件
编译好的网页文件，浏览器打开页面时由网关直接给出去。它不占计算、不做判断， 所以改样式只影响这一块。
静态文件 · 不占计算
后端接口服务
整个平台唯一会"动脑筋"的地方：登录与权限判断、业务数据读写、图片附件上传、 智能助手对话。它是一个常驻进程，由进程守护工具看护，崩了会自动重启。
常驻进程 · 崩溃自动重启
平台出问题，九成先看这里
读写数据 / 调用外部▼
第四段 · 数据与外部服务数据存在哪，还要连谁
业务数据库
全部业务数据的唯一来源，随后端部署在同一台服务器上。 做法是单文件数据库，备份就是复制这个文件。
对象存储
现场照片、附件、报告文件放在云端存储，不占服务器磁盘， 也不怕服务器重装丢文件。
外部服务
智能问答与识图的大模型服务、地图服务、文字识别服务。 这些不是我们部署的，是买来调用的；对方不可用会影响对应功能，但不影响平台本身。
日常维护▼
第五段 · 运维与发布日常维护就靠这几条
一键发布：本地执行脚本，自动上传并重启 前端与后端可分开单独发布 进程守护与崩溃自动重启 访问日志与错误日志 数据库定期备份 证书到期续期
两个要知道的前提
1. 本地开发不依赖服务器：一条命令同时启动前端和后端，改完再发布。
2. 当前是单机部署（一台服务器 + 一个后端进程 + 一个数据库文件），适合现在的体量； 用户量和并发上来以后，再拆分数据库、加第二台后端并做负载均衡。
