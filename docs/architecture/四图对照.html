四种架构图对照

人工智能 + 智能安全管控平台 ｜ 同一套内容，四种画法，给四种场合用

什么时候用哪张

图 回答什么问题 给谁看 典型场合
图一 · 产品能力全景图 平台有什么能力、能支撑哪些场景 客户、领导、售前 对外介绍、售前材料、领导汇报第一页 —— 「一屏看清我们有什么」
图二 · 应用架构图 平台由哪几个应用组成、分别给谁用、共用什么 客户、产品、项目管理 讲产品结构、划功能边界、讨论「这个需求该放进哪个应用」
图三 · 部署架构图 装在哪里、请求怎么走、出问题看哪里 运维、客户技术对接 交付部署、故障定位、安全与运维评审
图四 · 分层架构图 系统怎么一层层搭起来、新功能该写哪层 研发 新人上手、代码评审、判断「这事该动哪一层」
图 一 产品能力全景图 给客户 / 领导 / 售前
自上而下四段：使用端 → 场景应用 → 平台能力中心 → 技术底座。 视觉重点是中间那句「以上全部场景，都由下面四个能力中心拼装出来」—— 想强调的是能力是资产、场景是产物。
源文件：fig1-panorama.html ｜ 导出：node docs/architecture/render.mjs fig1
图 二 应用架构图 给客户 / 产品 / 项目管理
按应用系统分栏，不按层堆叠。六个应用并排，每栏写清「给谁用」和「有哪些功能模块」； 下方是它们共用的服务与数据，最后一条链路说明一件事会在几个应用之间流转。 好处是讨论需求边界时能直接指着某一栏说「这属于哪个应用」。
源文件：fig2-application.html ｜ 导出：node docs/architecture/render.mjs fig2
图 三 部署架构图 给运维 / 客户技术对接
按一次访问经过的五段自上而下排：用户访问 → 接入层 → 应用层 → 数据与外部服务 → 运维与发布。 每段都说清「装在哪、出问题看哪里」，并标注了当前规模是一台云服务器、单进程、单数据库文件， 以及将来扩容该拆什么。
源文件：fig3-deployment.html ｜ 导出：node docs/architecture/render.mjs fig3
图 四 分层架构图（研发视角） 给研发
六层自下而上，每层三块信息：是什么 → 有什么 → 给上一层什么。 第三块是这张图的灵魂，它说明「上层凭什么能用下层」。底部还有一张扩展点表： 要做新东西时先找到该动哪一层。图面全部中文，代码位置另见说明文档。
源文件：platform-dev-architecture.html ｜ 导出：node docs/architecture/render.mjs fig4
