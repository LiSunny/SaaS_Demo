L1平台底座 谁都躲不掉的公共支撑 —— 任何一个客户、任何一种部署都要用
租户与组织
多租户隔离：一套平台服务多个单位、数据不串号；单位下面再分管理单元、建筑、重点部位。
用户与身份
账号、岗位、登录认证；一个人可归属多个单位，切换单位就换视角。
权限
三层一起管：功能模块权限（看得见哪些菜单）、数据操作权限（能不能增删改导出）、字段级权限（哪些字段可改）。
审计与留痕
谁在什么时间做了什么，可回溯、可举证 —— 这是"尽职免责"的前提。
系统配置与版本
数据字典、系统参数、主体与品牌、编号规则，以及工作日历（算"2 个工作日"要靠它）； 配置改版可灰度、可回滚，不影响正在跑的流程实例。
不算底座、但要有：设备接入 · 外部系统对接 · 开放 API —— 按需启用，有的客户一个设备也没有。  ｜  不在本图：服务器、网络、数据库、监控等部署内容，见《部署架构图》。
泛 化 公 式
1在数字台账里定义对象与关系
2用动态表单画出录入字段
3用流程编排串起节点与指派
4用规则引擎写校验与分级
5用策略执行定自动处置与升级
6用消息中心配模板与通道
7用视图层挂列表、大屏与报表
七步配完 = 一个新业务场景上线，零行代码
现 状 结 论
1泛化骨架已经存在：流程编排、动态表单、大屏模板、工作台，都是"写一次反复用"的引擎。
2卡住泛化的不是缺功能，而是三件事没配置化：台账不能配出对象、规则与策略写在页面里、列表页没有注册表。
3下一步顺序很清楚：台账元数据化 → 规则/策略声明式 → 视图注册表化；消息中心与移动端排在最后。
