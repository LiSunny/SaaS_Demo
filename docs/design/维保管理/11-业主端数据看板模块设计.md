# 业主端数据看板 — 模块设计

## 1. 概述

### 1.1 定位

业主端数据看板是**一把手的决策入口**，解决"维保是黑盒"的核心痛点。将维保服务的履约、执行、质量、问题闭环等关键信息以可视化方式聚合展示，让业主管理者**一眼看清**维保状态。

### 1.2 目标用户

业主单位管理人员（一把手视角）

### 1.3 核心命题

| 一把手的问题 | 转化为可度量指标 | 对应模块 |
|-------------|----------------|---------|
| 维保公司在履行合同吗？ | 合同状态、履约进度、到期预警 | M1 卡1 |
| 该做的维保按时做了吗？ | 本月计划状态、延期预警 | M1 卡2 |
| 设备有没有隐患？ | 设备正常/异常分布、异常明细 | M1 卡3 + M3 |
| 发现的问题修好了吗？ | 故障闭环率、待处理/超时数 | M1 卡4 + M4 |
| 维保有记录可查吗？ | 最新报告摘要、月度归档状态 | M5 |
| 维保质量在变好还是变差？ | 月度完成趋势、分级预警 | M6 |

## 2. 模块设计

### M1 履约进度概览 — 四张状态卡

**定位**：看板顶部"第一眼"，四张等高卡片并排，每张回答一个核心问题。

**统一卡片结构：**
```
┌──────────────────────────┐
│ 小标题                    │  ← 12px 灰色
│                          │
│ 大数字/状态    视觉补充   │  ← 左文右图 flex
│ 副指标行                  │  ← 12px 辅助信息
│ 预警行（条件显示）         │  ← 有问题时出现
└──────────────────────────┘
```

#### 卡 1：合同履约状态

| 项 | 内容 |
|----|------|
| **标题** | 合同履约状态 |
| **左栏** | 合同名称 + 状态标签（执行中/待确认/已到期） |
| **右栏** | 履约进度条（已履约月数/总月数） |
| **副指标** | 合同起止日期 |
| **预警** | 到期前 30 天："⚠ 合同即将到期（X 天后）" |
| **空态** | "暂无有效维保合同" |
| **跳转** | ow-contracts |

**数据来源**：`CONTRACT_LIST` 按企业过滤，取状态为"执行中"的第一条合同。履约月数 = 当前月份 - 合同开始月份。

#### 卡 2：本月计划执行

| 项 | 内容 |
|----|------|
| **标题** | 本月计划执行 |
| **左栏** | 计划名称 + 状态标签（✅已完成 / 🔵执行中 / ⚠已延期 / ⬜未开始） |
| **右栏** | 任务完成进度（已完成数/总数） |
| **副指标** | 计划类型（月检/季检/年检）+ 执行人 |
| **预警** | 计划结束日期已过且未完成："⚠ 计划已延期 X 天" |
| **空态** | "本月暂无维保计划" |
| **跳转** | ow-tasks |

**数据来源**：`PLAN_LIST` 按企业过滤，取时间范围覆盖本月的计划（排除已停用）。

#### 卡 3：本月设备检查

| 项 | 内容 |
|----|------|
| **标题** | 本月设备检查 |
| **左栏** | "已检 X/Y 台" |
| **右栏** | 正常率百分比（≥90%绿 / 70-90%橙 / <70%红） |
| **副指标** | "正常 X 台 ｜ 异常 X 台" |
| **预警** | 有异常时："⚠ X 台设备存在异常" |
| **空态** | "本月暂无检查记录" |
| **跳转** | ow-tasks |

**数据来源**：本月任务的 `deviceResults`，按设备编码去重取最新结果。

#### 卡 4：故障处理效率

| 项 | 内容 |
|----|------|
| **标题** | 故障处理效率 |
| **左栏** | 闭环率大数字 |
| **右栏** | SVG 环形图（绿色已闭环 / 红色未闭环，56×56px） |
| **副指标** | "待处理 X 项 ｜ 超时 X 项" |
| **预警** | 有超时时："⚠ X 项超时未处理" |
| **空态** | "✅ 暂无故障"，环形图全绿 100% |
| **跳转** | ow-faults |

**数据来源**：`FAULT_LIST` 按企业过滤，闭环率 = 已完成/总数。超时阈值 = 上报 ≥ 3 天且未完成。

### M2 年度维保日历

**定位**：以月为单位，一眼看清全年维保覆盖情况。

**展示方式：**
```
📅 年度维保日历                          2026 年
┌────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┐
│ 1月│ 2月│ 3月│ 4月│ 5月│ 6月│ 7月│ 8月│ 9月│10月│11月│12月│
│ — │ — │ — │ — │ 🔵 │ 🔵 │ — │ — │ — │ — │ — │ — │
│    │    │    │    │月检│月检│    │    │    │    │    │    │
└────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘
  ✅ 已完成 X 月    🔵 执行中 X 月    ⬜ 待执行 X 月
```

**业务规则：**
- 12 列 grid，当前月份蓝色边框高亮，合同开始日期月份顺延12个月
- 每格显示：状态图标 + 计划类型标签（月检/季检/年检可叠加）
- 状态由该月覆盖的计划综合判定：全部完成→✅ / 有执行中→🔵 / 有延期→⚠ / 有未启用→⬜ / 无计划→—
- 底部图例汇总已完成/执行中/待执行月数
- 已停用计划不计入日历

**数据来源**：`PLAN_LIST` 按企业过滤，排除已停用。每月匹配计划的时间范围交集。

### M3 设备健康度

**定位**：回答"设备有没有隐患？"，区分正常态/异常态展示。

**正常态（无异常设备）：**
```
🔧 设备健康度
┌──────────────────────────────────────────────┐
│  ✅ 全部设备运行正常                           │
│  共 X 台设备，覆盖 X 个消防系统                 │
│  最近检查日期：YYYY-MM-DD                      │
│                                              │
│  系统分布：                                   │
│  火灾自动报警 3台 · 消防给水 2台 · 灭火器 5台   │
└──────────────────────────────────────────────┘
```

**异常态（有异常设备）：**
```
🔧 设备健康度
┌──────────────────────────────────────────────┐
│  ⚠ 异常 X 台          正常 Y 台 | 共 Z 台      │
│                                              │
│  异常设备明细（最多 5 条）：                    │
│  ┌ XF-1-003  消防水泵  B1水泵房  05-16       ┐ │
│  │ 水泵启动异响                              │ │
│  └──────────────────────────────────────────┘ │
│                                              │
│  按系统（仅异常系统）：                        │
│  消防给水系统  1/2正常  ██████░░ 50%          │
└──────────────────────────────────────────────┘
```

**业务规则：**
- 去重：同一设备多次检查只取最新结果
- 正常态不显示进度条，仅紧凑标签罗列系统
- 异常态异常设备明细置顶（最多 5 条），系统进度条仅显示有异常的系统
- 正常率分级：≥90% 绿 / 70-90% 橙 / <70% 红

**数据来源**：所有任务的 `deviceResults`，按设备编码去重取最新。系统分组来自 `LEDGER_ITEMS.sys`。

### M4 故障清单

**定位**：回答"上报的故障处理到哪一步了？"，按状态分组展示。

**展示方式：**
```
🔁 故障清单
┌──────────────────────────────────────────────┐
│  🔴 待维修（2）                               │
│  ┌─────────────────────────────────────────┐ │
│  │ 🔴 超时7天 │ 烟感探测器故障 │ 3F走廊      │ │
│  │ 上报：05-10                              │ │
│  ├─────────────────────────────────────────┤ │
│  │ 🟡 3天 │ 消火栓按钮故障 │ 2F东侧          │ │
│  │ 上报：05-14                              │ │
│  └─────────────────────────────────────────┘ │
│                                              │
│  🔵 维修中（1）                 [收起 ▲]     │
│  ┌─────────────────────────────────────────┐ │
│  │ 🔵 │ 消防水泵故障 │ B1水泵房              │ │
│  │    │ 上报：05-08                          │ │
│  └─────────────────────────────────────────┘ │
│                                              │
│  🟢 已完成（10）                 [展开 ▼]     │
│                                              │
│  [查看全部故障 →]                             │
└──────────────────────────────────────────────┘
```

**业务规则：**
- 按状态分组：待维修 → 维修中 → 已完成
- 待维修按超时天数排序，超时标记：≤3天默认 / 3-7天🟡 / >7天🔴
- 每组可折叠/展开，已完成默认折叠
- 无故障时显示"✅ 暂无故障记录"

**数据来源**：`FAULT_LIST` 按企业过滤，按 `repairStatus` 分组。超时天数 = 当前日期 - `submitTime`。

### M5 报告档案

**定位**：回答"每次维保有记录吗？"，最新报告置顶 + 月度归档概览。

**展示方式：**
```
📄 报告档案
┌──────────────────────────────────────────────┐
│  最新报告：2026年5月月检报告                   │
│  报告编号：BG-20260518-0001 | 提交时间 | 状态  │
│  结论摘要：消防设施运行正常，未发现异常           │
│  [查看完整报告]    [历史报告列表 →]             │
│                                              │
│  月度报告归档：                               │
│  1月❌ 2月❌ 3月❌ 4月❌ 5月✅ 6月⬜ ...        │
│  ▲ 1月、2月、3月、4月 无报告                   │
└──────────────────────────────────────────────┘
```

**业务规则：**
- 最新报告置顶，显示名称、编号、时间、结论摘要
- 月度归档条：12 个月紧凑标签
  - ✅ 有已提交报告 / ❌ 缺失 / ⬜ 未到月份
- 缺失月份标注提醒
- 无任何报告时显示"暂无维保报告记录"

**数据来源**：`REPORT_LIST` 按企业过滤，状态为"已提交"的报告。月度归档按过去 12 个月检测。

### M6 维保趋势与预警

**定位**：回答"维保质量趋势 + 有什么异常信号？"，双栏布局。

**左栏 — 简化趋势表：**
```
📈 近 6 个月趋势
┌────────────────────────────────────┐
│  月份     计划完成   故障闭环        │
│  12月      —         —            │
│  01月      —         —            │
│  ...                              │
│  05月      ❌        ⚠ 0/2        │
│  06月      ⬜        ⬜            │
│                                   │
│  近 6 个月完成维保 0/6 月           │
└────────────────────────────────────┘
```

**右栏 — 三层级预警中心：**
```
⚠ 预警中心
┌────────────────────────────────────┐
│  🔴 紧急                           │
│  · 故障超 7 天未闭环                │
│                                   │
│  🟡 提醒                           │
│  · 故障超 3 天未处理               │
│  · 合同 30 天后到期                │
│  · 计划尚未启用                    │
│                                   │
│  🟢 正常                           │
│  · 所有指标正常                    │
└────────────────────────────────────┘
```

**业务规则：**
- 左栏：每月一行，计划完成 ✅/❌/⬜，故障闭环有数字则显示"✅/⚠ X/Y"否则"—"
- 未到月份显示 ⬜ 灰色
- 底部一句总结 + 故障闭环率
- 右栏三层级：🔴 紧急（超时 > 7天）> 🟡 提醒（合同到期/计划待启用/超时 3-7天）> 🟢 正常
- 每个层级无内容时显示"暂无"或"正常"

**数据来源**：
- 趋势：`TASK_LIST` + `FAULT_LIST` 按月聚合
- 预警：`FAULT_LIST` 超时检测 + `CONTRACT_LIST` 到期检测 + `PLAN_LIST` 未启用检测

## 4. 数据聚合

### 4.1 聚合函数 `computeDashboardData()`

输入：无（使用全局数据，以当前登录业主企业过滤）
输出：

```javascript
{
  curEnt: String, curMonthStr: String, curYear: Number,
  // M1
  activeContract: Object | null,       // 执行中合同
  contractProgress: { done, total },    // 已履约月数/总月数
  contractExpiring: Boolean,
  contractExpireDays: Number,
  currentMonthPlan: Object | null,      // 本月计划
  planDeviceProgress: { done, total },  // 任务完成数/总数
  planOverdueDays: Number,
  deviceCheckStats: { checked, total, normal, abnormal, normalRate },
  faultRingData: { closedRate, pending, timeout, hasTimeout, total },
  // M2
  calendarMonths: [{ month, label, key, status, plans[], isCurrent }],
  calStats: { done, doing, pending },
  // M3
  allSystems: [{ sys, total, normal, abnormal, normalRate }],
  abnormalSystems: [...],              // 仅异常系统
  hasAbnormal: Boolean,
  abnormalDevices: [{ code, name, sys, loc, faultDesc, checkedAt }],
  totalDevices: Number,
  lastCheckDate: String,
  // M4
  faultGroups: { pending[], repairing[], done[] },
  // M5
  latestReport: Object | null,
  monthArchive: [{ month, label, key, status }],
  missingMonths: [...],
  // M6
  simpleTrends: [{ month, label, planDone, taskTotal, taskDone, faultTotal, faultDone, isFuture }],
  trendDoneMonths: Number, trendTotalMonths: Number, trendFaultRate: Number,
  alertsUrgent: [String], alertsReminder: [String], alertsNormal: [String]
}
```

### 4.2 数据口径

| 范围 | 定义 |
|------|------|
| "本月" | 当前日期所在月份 |
| "近 6 个月" | 当前月往前推 6 个月（含本月） |
| "近 12 个月" | 当前月往前推 12 个月（含本月） |
| "当前企业" | 业主端登录企业名 |
| 设备检查去重 | 同一设备编码多次检查取最新 `checkedAt` |
| 故障超时 | 待维修/维修中且 `submitTime` 距今天 ≥ 3 天 |
| 合同到期预警 | 执行中合同 `endDate` 距今天 ≤ 30 天 |

## 5. MVP 边界

| 维度 | MVP 范围 | 后续可扩展 |
|------|---------|-----------|
| 数据精度 | 仅展示本企业数据 | 多企业切换 |
| 趋势图 | 简化表格（✅/❌/⬜） | 折线图/柱状图（ECharts） |
| 环形图 | SVG 纯手工实现 | ECharts 升级 |
| 交互 | 折叠/展开 + 跳转 | 钻取、筛选 |
| 预警 | 静态分层列表 | 推送通知、消息提醒 |
| 对比 | 不实现 | 同比/环比 |
| 导出 | 不实现 | 看板导出为 PDF/图片 |
