# 维保台账模块 — 详细设计

## 1. 概述

维保台账是维保服务协作平台的**基础数据核心**，职责范围限定为**设备数据的增删改查（CRUD）**——服务商为各业主单位管理消防设备清单。台账是维保三层架构（台账→计划→任务）的起点，计划从台账中选择设备编排周期，任务执行时逐台检查。

**本模块只做一件事：设备级台账数据的维护。**

**涉及角色：** 服务商端（创建和维护）、业主端（仅查看本企业相关台账）

**模块定位：**

```
维保三层架构:

  维保台账（What）        维保计划（When & Who）      维保任务（Do）
  ┌──────────────┐       ┌──────────────┐         ┌──────────────┐
  │ 维护设备清单  │──→    │ 定义何时做    │──→     │ 执行做了啥    │
  │ · 增/删/改设备│       │ 谁来做        │        │ · 检查结果   │
  │ · 批量导入   │       │ · 选择设备    │        │ · 故障上报   │
  │ · 设备详情   │       │ · 分配人员    │        │ · 完成状态   │
  │ · 保养记录   │       │ · 设置周期    │        └──────────────┘
  └──────────────┘       └──────────────┘

  约束：台账→计划→任务逐层依赖，不可跳级
```

---

## 2. 核心概念

### 2.1 什么是维保台账

维保台账是服务商为每个业主单位创建的**设备底册**，每台设备一条独立记录：

- **服务商端**：CRUD 设备记录，按系统类别或建筑区域组织
- **业主端**：查看本企业相关的维保设备清单

### 2.2 台账与消防台账的区别

| | 维保台账（本模块） | 消防台账（业主端） |
|--|-----------------|------------------|
| 维护方 | 服务商 | 业主单位 |
| 内容 | 设备维保清单（每台设备一条记录） | 设备资产（有什么设备） |
| 用途 | 用于编排维保计划、执行维保任务 | 用于管理本单位消防设备资产 |
| 数据关系 | 仅参照业主设备数据，不自动同步 | 独立管理 |

### 2.3 分值规则

分值是设备的**权重系数**，不是得分：

| 规则 | 说明 |
|------|------|
| 分值 = 权重 | 每台设备的分值代表其重要程度。如消防水泵 = 30 分、灭火器 = 10 分 |
| 台账定义 → 计划汇总 → 任务继承 | 分值在台账层设定，后续逐层继承不可修改 |
| 量化完成率 | 任务执行后按"已完成设备分值总和 ÷ 任务总分"计算 |
| MVP 阶段 | 仅记录，不产生评分统计 |

## 4. 业务规则

### 4.1 创建设备

- 设备必须绑定已关联的业主单位，未关联企业时无法创建
- **设备编码**全局唯一，创建时系统自动生成建议（{系统缩写}-{建筑}-{序号}），允许手动修改
- 支持 CSV 文件批量导入设备（参见 §5）

### 4.2 修改设备

- **可修改字段**：设备类型、安装地点、建筑、分值
- **不可修改字段**：所属企业、系统类别（需变更应删除重建）
- **设备编码**：原则上不可修改，确需修改时需确认无引用关系
- 修改后影响后续生成的计划（计划在下次选择设备时看到最新数据）
- 已有任务不受影响（继承生成时刻的快照）

### 4.3 删除设备

- 被维保计划引用的设备，删除前提示确认
- 确认删除后，计划中该条目标记为失效
- 已有任务不受影响，历史保养记录保留
- 采用软删除

### 4.4 分值规则

- 最小单位 1 分，建议 5-50 分
- 关键设备（消防水泵、报警控制器）：20-30 分
- 常规设备（灭火器、应急照明）：5-15 分
- 0 分表示不参与完成率计算

### 4.5 检查周期

检查周期不在台账（设备清单）层定义，由**维保标准库（M10）**按系统类别/设备类型统一管理。维保计划编排时，从标准库获取对应设备的检查周期。

> 参见：`docs/design/10-维保标准库模块详细设计.md`

## 5. CSV 批量导入

### 5.1 导入流程

```
选择文件 → 上传解析 → 预览确认 → 导入完成
  ①          ②          ③          ④
```

**① 选择文件：** 点击「导入 CSV」，选择 .csv 文件（UTF-8，≤ 5MB），提供模板下载

**② 上传解析：** 校验必填列（设备编码、设备类型、系统类别、安装地点、分值）和可选列（建筑）。系统类别必须存在于分类体系，分值必须为 ≥ 1 整数。设备编码重复时跳过并提示

**③ 预览确认：** 展示解析结果预览，有问题的行标红提示，确认后仅导入有效数据

**④ 导入完成：** 显示成功/失败数量，失败记录提供错误原因下载，成功设备自动生成设备编码

### 5.2 CSV 模板

| 设备编码 | 设备类型 | 系统类别 | 安装地点 | 建筑 | 分值 |
|---------|---------|---------|---------|------|------|
| HZBJ-1F-001 | 点型感烟探测器 | 火灾自动报警系统 | 1F 走廊 | 1号楼 | 15 |
| XHSB-B1-001 | 消防水泵 | 消防给水及消火栓系统 | B1 水泵房 | 1号楼 | 30 |

### 5.3 设备编码自动生成

格式：`{系统缩写}-{建筑}-{序号}`，如 `MHQ-1F-001`
- 系统类别 → 映射编码缩写（"火灾自动报警系统" → MHQ）
- 建筑 → 直接取值
- 序号 → 同一（缩写+建筑）组合下自增，从 001 开始

## 6. 系统及设备类型维护

系统类别和设备类型是设备表单下拉选项的来源配置，支撑设备 CRUD 时的数据录入。

**系统类别预置 14+1 类**（基于 DB 13/T 3035—2023 调整，详见《维保标准库模块详细设计》），支持自定义扩展。设备类型为新增设备时快速填入名称的模板配置。

**详细内容参见：** `docs/design/10-维保标准库模块详细设计.md`

## 8. 数据联动关系

| 触发动作 | 影响范围 | 效果 |
|---------|---------|------|
| 新增设备 | 维保台账列表 | 即时新增一行 |
| | 维保计划"选择设备" | 新增的设备可选 |
| 修改设备 | 维保台账列表 | 即时更新 |
| | 已有维保计划 | 下次选择设备时看到更新 |
| | 已有维保任务 | 不受影响（快照） |
| 删除设备 | 维保台账列表 | 即时移除（软删除） |
| | 引用了该设备的计划 | 提示确认，确认后计划该条目失效 |
| | 已有维保任务/保养记录 | 不受影响 |
| 关联新业主 | 设备表单"所属企业"下拉 | 新增可选企业 |
| 解除业主关联 | 设备表单"所属企业"下拉 | 移除该企业（已有设备保留） |
| 任务执行完成 | 设备保养记录 | 自动追加一条保养记录 |

## 9. 业务边界场景

| 场景 | 处理方式 |
|------|---------|
| **无已关联企业时新增设备** | 所属企业下拉为空，提示"请先关联业主单位" |
| **设备编码重复** | 保存时校验唯一性，提示"该设备编码已存在" |
| **设备被计划引用后删除** | 提示"该设备已被维保计划引用"，确认后可删，计划条目标记失效 |
| **台账列表为空** | 引导用户新增设备或导入 CSV |
| **CSV 导入部分失败** | 有效数据正常导入，失败记录提供原因下载，不整体回滚 |
| **修改分值影响已有任务** | 任务继承快照，不影响。仅影响下次任务生成的汇总总分 |
| **停用系统类别** | 已有设备不受影响，新增设备时不可选 |
