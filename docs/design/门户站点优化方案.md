# 门户站点优化方案（v3 · 行业范式对比版）

> 原则：先对齐"一个 B2B 产品门户应该长什么样"，再判断当前实现哪里对了、哪里偏了、哪里需要重构

---

## 一、行业标准：B2B 产品门户的信息架构范式

参考 Datadog / Vercel / Stripe / 飞书 / 钉钉——成功的 B2B 产品首页，信息架构遵循同一条主线：

```
问题认知 → 解决方案 → 价值证明 → 行动转化
```

拆开来看是这几个必经区域：

| 序号 | 区域 | 回答的问题 | 行业标配做法 |
|------|------|-----------|-------------|
| 1 | **Hero** | "这是干什么的？" | 价值主张一句话 + **产品界面截图或动图** + 一个 CTA |
| 2 | **信任背书条** | "有人用吗？靠谱吗？" | 客户 Logo 墙 / "已服务 X 家企业" / 关键数字 |
| 3 | **场景/角色分述** | "能解决我的问题吗？" | 按目标用户分组，每组 = 痛点 → 方案 → 产品截图 |
| 4 | **核心差异化能力** | "和竞品比有什么不同？" | 3-5 个亮点，每个配截图或示意图 |
| 5 | **客户案例/效果数据** | "效果怎么样？" | 具名客户 + 量化结果（不是"大幅提升"） |
| 6 | **如何使用/上手路径** | "下一步怎么做？" | 3 步走或试用入口 |
| 7 | **底部 CTA** | "怎么开始？" | 统一行动号召 + Footer |

**关键原则**：
- **Show, don't tell** — 能放截图的地方不放纯文字描述
- **一个页面服务一个决策** — "我该不该试用/购买这个产品"
- **信息不是越多越好** — 每个区域只回答一个问题，回答完就结束

## 二、当前页面 vs 行业范式：逐区比对

### 2.1 Hero 区

| | 行业标准 | 当前实现 | 差距 |
|---|---------|---------|------|
| 价值主张 | 一句话说清 | "人工智能 + 公共安全管理平台" | ✅ 基本够用 |
| 副标题 | 补充场景/受众 | "覆盖教育、工业、城市治理三大领域…" | ✅ 可以 |
| **产品截图** | **必须有** | **无** | 🔴 最大缺失 |
| CTA | 一个主 CTA | 两个按钮（了解场景 + 查看功能）+ 一个"去体验"在导航栏 | 🟡 三个 CTA 互相打架 |

**评价**：标题和副标题方向正确，但**没有产品截图是致命的**。用户在 Hero 区读完文字，脑子里没有任何画面。CTA 分散——"了解应用场景"和"查看功能矩阵"是两个竞争性的行动，用户不知道该点哪个。

---

### 2.2 信任背书条

| | 行业标准 | 当前实现 | 差距 |
|---|---------|---------|------|
| 客户 Logo | 至少 3-5 个 | 无 | 🔴 |
| 关键数字 | "服务 X 家企业" | 205 台设备（埋在技术区） | 🟡 数字有但放错了位置 |
| 资质/认证 | 如有则展示 | 无 | 🟡 |

**评价**：完全没有信任区。Hero 下面直接就是"平台定位"——用户连"这平台有人用过吗"都还没确认，就被拉进产品细节了。

---

### 2.3 场景/角色分述

| | 行业标准 | 当前实现 | 差距 |
|---|---------|---------|------|
| 分组方式 | 按用户角色/痛点分组 | 三类场景卡片 + 轮播 | ✅ 分组逻辑正确 |
| 每组的构成 | 痛点 → 方案 → 截图 | 受众标签 + 描述文字 + 功能标签 | 🟡 缺截图 |
| 交互 | 点击进入详情页 | 点击跳转子页面 | ✅ 子页面内容扎实 |
| 数量 | 3-4 组 | 3 组 | ✅ |

**评价**：**这是当前页面做得最好的区域**。场景分组合理，子页面（校园/工贸/小商户）内容扎实——有案例、角色、旅程图。唯一不足是缺产品截图。

---

### 2.4 核心差异化能力

| | 行业标准 | 当前实现 | 差距 |
|---|---------|---------|------|
| 数量 | 3-5 个亮点 | 4 个 AI 能力卡片 | ✅ |
| 每项的内容 | 标题 + 简短描述 | 标题 + 详细场景化描述 | ✅ 文案质量高 |
| 配图 | 截图或示意图 | 无配图 | 🟡 |
| Hover 效果 | 适度 | 整卡变蓝 + 文字反白 | 🟡 过度设计 |

**评价**：AI 能力区文案是亮点——不是空洞的"AI 赋能"，而是具体到"捕捉敏感求救词""电流波形+粉尘浓度交叉分析"。但四张白卡 hover 后整张变蓝的交互太重了，用户只是想看清楚内容，不是要被闪一下。

---

### 2.5 功能模块展示

| | 行业标准 | 当前实现 | 差距 |
|---|---------|---------|------|
| 呈现方式 | 分组精选 3-6 项 | 12 张卡片平铺 | 🔴 功能清单式枚举 |
| 状态标签 | 不展示内部开发状态 | "已上线 / 开发中"标签 | 🔴 这是内部进度不是产品信息 |
| 每项的深度 | 功能名 + 一句话 + 截图 | 功能名 + 枚举子功能 | 🟡 |

**评价**：**这是结构性问题最大的区域**。12 张卡片排成 4×3 网格，每张只有"模块名 + 三四个子功能关键词"，用户扫过去全是长得一样的方块。这是内部需求文档的写法——把系统模块罗列一遍——不是产品页的写法。而且"开发中"标签直接告诉用户"这 3 个功能还没做"。

---

### 2.6 技术特性

| | 行业标准 | 当前实现 | 差距 |
|---|---------|---------|------|
| 位置 | 通常不放首页，或放在底部做简要提及 | 独立区域，深色背景 | 🟡 |
| 面向谁 | 技术决策者 | MQTT / TCP / HTTP 协议 | 🟡 内容偏开发者文档 |
| 数据 | 实时运营数据 | 数字 count-up 动画（当前 bug 显示为 0） | 🔴 |

**评价**：MQTT 直连、TCP 直连、HTTP 订阅——这些是技术实现细节，不应该出现在产品首页。技术决策者想看的是"和现有系统能不能对接"，可以一句话说清楚，不需要列协议名。协议列表应该放在 API 文档或技术白皮书里。

---

### 2.7 客户案例/效果数据

| | 行业标准 | 当前实现 | 差距 |
|---|---------|---------|------|
| 是否存在 | 必须有 | 无 | 🔴 |

**评价**：首页完全没有客户案例或效果数据的展区。场景详情页有"真实案例"卡片，但它被埋在子页面里——首页访问者看不到。这是信任链条上最大的一环缺失。

---

### 2.8 CTA 转化

| | 行业标准 | 当前实现 | 差距 |
|---|---------|---------|------|
| Hero 区 | 一个主 CTA | 两个按钮 | 🟡 |
| 导航栏 | 无或登录 | "去体验"按钮 | ✅ |
| 底部 | 再给一次 CTA | "浏览应用场景" + "联系商务团队" | 🟡 两个按钮，后者是假的 |
| Footer 联系方式 | 真实电话/邮箱 | xxx-xxx-xxx / xxx@163.com | 🔴 |

## 三、总评：当前页面的定位偏差

| 维度 | 行业标准 | 当前页面 |
|------|---------|---------|
| **信息源头** | 从客户问题出发 | 从系统功能模块出发 |
| **叙事逻辑** | 你有一个问题 → 我们这样解决 | 我们做了这些模块 → 你看哪个能用 |
| **展示方式** | 产品截图 > 示意图 > 文字 | 100% 纯文字 + 插画 |
| **信任建立** | 数字 + Logo + 案例前置 | 没有专门信任区 |
| **功能展示** | 精选 3-6 个亮点 | 12 个模块全量罗列 |
| **内部信息** | 不对外暴露 | "开发中"标签公开展示 |

**一句话总结**：当前页面是用"内部系统设计文档的信息结构"套了一个"产品官网的壳"。

## 四、重做方案

### 4.1 重新定义信息架构

应该改为：

```
Hero（产品截图 + 一句话 + 一个CTA）
    ↓
信任条（客户数/设备数/覆盖企业数）
    ↓
场景分述 × 3（每个场景 = 痛点 → 方案 → 截图）
    ↓
AI 能力亮点 × 3（保留文案，加示意图，减弱 hover 效果）
    ↓
客户案例 × 2（从场景详情页提炼到首页）
    ↓
底部 CTA（预约演示）
```

### 4.2 具体改动（按区域）

#### Hero 区
- **加一张产品主界面截图**（Dashboard 或核心功能截图）在标题下方
- 删掉"查看功能矩阵"按钮，只保留一个 CTA："了解应用场景"或"预约演示"
- 导航栏的"去体验"保持不变

#### 信任条（新增）
- 3-4 个关键数字横向排列：如"服务 X 家企业 / 接入 Y 台设备 / 覆盖 Z 所校园"
- 从技术特性区的数据（205 台设备等）和 STATS 数组中提取，但放在 Hero 下方作为信任信号，不是放在页面底部当技术参数

#### 场景分述区
- **保留**三类场景的分组结构
- **每个场景卡片内加一张产品截图**（而非 UI 插画）——当前用的是高质量场景插画（3840×2160），但产品截图更能建立信任
- 场景详情页已经写得很扎实，首页不必重复，只提炼核心价值

#### AI 能力区
- **保留**文案（这是页面最大的亮点）
- Hover 效果从"整张卡变蓝 + 文字反白"改为**微妙上浮 + 阴影变化**——当前效果太像按钮 hover，不像内容卡片
- 每张卡片增加一个简笔示意图或 icon 装饰（当前只有数字编号）

#### 功能模块区 → **删除或重构为简短亮点**
- **删掉** 12 张功能卡片平铺网格
- 改为 3-4 个核心亮点，在 AI 能力区或场景区中自然融入
- 功能清单可以保留在 Footer 链接中（已经在了）或单独一个"功能总览"子页
- **绝对不在首页展示开发状态**

#### 技术特性区 → **删除或精简为一句话**
- 删掉 MQTT/TCP/HTTP 协议列表
- 把"多协议兼容、多端协同"压缩为一句话，放在信任条或 Footer 中
- 如果目标是技术决策者，单独写一页"技术白皮书"，不在首页铺开

#### 客户案例区（新增）
- 从场景详情页的"真实案例"中提炼 2 个，放在首页
- 格式：客户类型 + 痛点 + 解决方案 + 量化效果（如有）

#### CTA 区
- 底部 CTA 改为单一"预约演示"
- 填写真实联系方式
- "联系商务团队"可以保留为次要链接

## 五、改动量估算

| 类型 | 内容 | 工时 |
|------|------|------|
| **删** | 删除 12 功能卡片网格、开发状态标签、技术协议列表、"向下滚动"提示、"查看功能矩阵"按钮 | 0.5h |
| **增** | 加信任条、加产品截图（需准备 2-3 张截图）、加客户案例提炼 | 3h |
| **改** | Hero CTA 精简、AI 卡片 hover 效果减弱、场景卡片配图替换 | 1h |
| **修** | 数字 count-up bug、品牌名统一、Footer 联系方式 | 0.5h |
| **合计** | | **约 5h** |

一个工作日内可完成重构，产出的是一个**符合行业范式、以客户问题为叙事主线的产品首页**，而不是现在的"内部功能清单 + 产品官网皮囊"。
