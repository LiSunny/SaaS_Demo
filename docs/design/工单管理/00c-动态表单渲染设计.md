# 动态表单渲染设计

> 描述模板表单字段在工单生命周期中的渲染机制、权限控制和数据流转。
> 补充 [00-流程编排模块详细设计](00-流程编排模块详细设计.md) 的表单渲染部分。

---

## 1. 定位

解决流程编排中的核心缺口：**模板中设计的表单字段如何在运行时渲染给用户**。

```
模板设计时                         运行时
─────────                        ────────
FormDesigner 设计 FormField[]  ──→ DynamicForm 渲染表单
NodePropertyPanel 配置权限       ──→ field.mode 控制可编辑/只读/隐藏
FlowDesigner 定义节点顺序        ──→ 节点流转时切换 permissions
```

## 2. 字段权限三态

### 2.1 数据模型

```typescript
// 旧（废弃）
interface FieldPermission {
  fieldId: string
  edit?: boolean
  view?: boolean
}

// 新
type FieldMode = 'hidden' | 'readonly' | 'editable'

interface FieldPermission {
  fieldId: string
  mode: FieldMode
}
```

### 2.2 三态定义

| mode | 运行时行为 | 视觉表现 |
|------|-----------|---------|
| `hidden` | 不渲染（v-if="false"） | 不可见 |
| `readonly` | 渲染控件但 disabled + 灰色背景 | 可见，值回填，不可操作 |
| `editable` | 正常交互 | 正常输入控件 |

### 2.3 默认规则

当节点未显式配置某字段的权限时：

| 节点类型 | 不属于本节点的字段 | 属于本节点的字段 |
|---------|-----------------|----------------|
| 发起 (start) | readonly | editable |
| 指派 (assign) | readonly | — |
| 执行 (execute) | readonly | editable |
| 确认 (confirm) | readonly | editable |
| 关闭 (close) | readonly | — |

> "属于本节点"的判断：该字段在 FormDesigner 中被添加到该节点。

### 2.4 配置界面（NodePropertyPanel）

```
节点：执行
┌──────────────────────────────────────────┐
│  字段权限                                 │
│                                           │
│  字段名        隐藏      只读      可编辑   │
│  ─────────────────────────────────────    │
│  设备名称       ○        ●         ○     │
│  故障位置       ○        ●         ○     │
│  故障描述       ○        ●         ○     │
│  现场照片       ○        ○         ●     │
│  维修结果       ○        ○         ●     │
│  更换零件       ○        ○         ●     │
│  验收意见       ●        ○         ○     │
└──────────────────────────────────────────┘
```

三段式 radio，每行一个字段。表单项 `el-form-item` 带 `label="字段名"`。

## 3. DynamicForm 组件

### 3.1 组件接口

```typescript
// src/components/business/DynamicForm.vue

interface Props {
  /** 模板定义的所有字段（来自 FormDesigner.getFields()） */
  fields: FormField[]
  /** 当前节点的字段权限配置 */
  permissions: FieldPermission[]
  /** 已有表单数据（前节点已提交的值，用于回填） */
  initialData?: Record<string, any>
  /** 全局只读模式（已关闭工单查看时） */
  readonly?: boolean
}

interface Emits {
  /** 用户提交表单数据 */
  'submit': [data: Record<string, any>]
}
```

### 3.2 渲染逻辑

```
DynamicForm 渲染流程：
  1. 遍历 fields
  2. 查 permissions 中该 field 的 mode
  3. 若 readonly=true（全局只读） → 所有字段强制 readonly
  4. 若 mode=hidden → 跳过
  5. 若 mode=readonly → 渲染 disabled 控件 + 回填 initialData[fieldId]
  6. 若 mode=editable → 渲染正常控件 + 回填 initialData[fieldId]
  7. 提交时收集所有非 hidden 字段的值
```

### 3.3 字段类型 → 控件映射

| FormField.type | 渲染控件 | disabled 行为 |
|---------------|---------|--------------|
| `input` | `el-input` | 置灰不可输入 |
| `textarea` | `el-input type="textarea"` | 置灰不可输入 |
| `radio` | `el-radio-group` | 置灰不可切换 |
| `checkbox` | `el-checkbox-group` | 置灰不可勾选 |
| `select` | `el-select` | 置灰不可展开 |
| `date` | `el-date-picker` | 置灰不可选择 |
| `upload` | `el-upload` | 隐藏上传按钮 |
| `number` | `el-input-number` | 置灰不可增减 |

### 3.4 实现方式

基于已安装的 `@form-create/element-ui` v3.3.0 运行时渲染：

```typescript
import { defineComponent } from 'vue'
import formCreate from '@form-create/element-ui'

// 将 FormField[] 转为 form-create rule[]
function fieldsToRules(fields: FormField[], permissions: FieldPermission[], initialData?: Record<string, any>) {
  return fields
    .filter(f => {
      const perm = permissions.find(p => p.fieldId === f.id)
      return perm?.mode !== 'hidden'
    })
    .map(f => {
      const perm = permissions.find(p => p.fieldId === f.id)
      const disabled = perm?.mode === 'readonly'
      return {
        type: f.type,
        field: f.id,
        title: f.label,
        value: initialData?.[f.id] ?? f.defaultValue ?? '',
        props: {
          disabled,
          placeholder: disabled ? '' : `请输入${f.label}`,
          ...f.validationRules,
        },
      }
    })
}
```

## 4. 表单数据生命周期

### 4.1 数据模型

```typescript
// WorkOrderItem 新增
interface WorkOrderItem {
  // ... 现有字段 ...
  formData: Record<string, any>       // 聚合表单数据（所有节点已填值的快照）
}

// WorkOrderDetail 新增
interface WorkOrderDetail extends WorkOrderItem {
  // ... 现有字段 ...
  nodeRecords: NodeFormRecord[]       // 每个节点提交的表单记录
}

interface NodeFormRecord {
  id: number
  nodeId: string
  nodeName: string
  submittedBy: string
  submittedByOrg: string
  submittedAt: string
  data: Record<string, any>           // 本节点提交的字段值
}
```

### 4.2 数据流

```
发起节点（物业管理员，Web 弹窗）
  DynamicForm props: fields=全部, permissions=发起节点, initialData={}
  用户填写: { 设备名称: '消火栓泵', 故障描述: '压力不足' }
  提交 → nodeRecords.push({ nodeId:'start', data: {...} })
       → formData = { 设备名称: '消火栓泵', 故障描述: '压力不足' }

执行节点（工程师，独立页面）
  DynamicForm props: fields=全部, permissions=执行节点, initialData=formData
  渲染: 设备名称(只读, 回填'消火栓泵'), 故障描述(只读, 回填'压力不足'), 
         维修结果(可编辑), 现场照片(可编辑)
  用户填写: { 维修结果: '已更换密封圈', 现场照片: [...] }
  提交 → nodeRecords.push({ nodeId:'execute', data: {...} })
       → formData 合并: { ..., 维修结果: '已更换密封圈', 现场照片: [...] }

验收节点（物业管理员，独立页面）
  DynamicForm props: fields=全部, permissions=验收节点, initialData=formData
  渲染: 设备名称(只读), 故障描述(只读), 维修结果(只读), 
         现场照片(只读), 验收意见(可编辑)
  用户填写: { 验收意见: '维修合格' }
  提交 → nodeRecords.push({ nodeId:'confirm', data: {...} })
       → formData 合并 + 状态 → closed

关闭后查看（详情抽屉）
  DynamicForm props: fields=全部, permissions=最后一个节点, 
                    initialData=formData, readonly=true
  全部字段 disabled，纯展示
```

## 5. 载体选择

| 节点 | 载体 | 路由 | 端 | 原因 |
|------|------|------|-----|------|
| 发起 | `el-dialog` | 无（弹窗） | Web | 快速操作，字段少（5-8个），弹窗够用 |
| 指派 | 详情页 | `/system/order/:id` | Web | 详情页内操作区，仅需选择人员 |
| 执行 | 详情页 | `/system/order/:id` | Web / 小程序 | 详情页内操作区，表单字段在当前节点操作区渲染 |
| 确认 | 详情页 | `/system/order/:id` | Web | 同路由，详情页内操作区 |
| 关闭 | 详情页 | `/system/order/:id` | Web | 只读展示，无需新页面 |

所有节点处置统一在工单详情页完成，不再需要独立的 `/process` 路由。

## 6. 详情页中的表单展示（Figma 设计）

工单详情页（`/system/order/:id`）采用双栏布局，表单内容拆分为只读区和操作区：

### 6.1 未关闭状态布局

```
┌─ 页面头部：优先级Tag + 工单标题 + 编号/模板/发起人 ──────────────────┐
├────────────────────────────────────────────┬────────────────────────┤
│  左栏 (flex-1)                              │  右栏 (361px)          │
│  ┌─ 流程进度 ─────────────────────────┐    │  ┌─ 流转记录 ────────┐ │
│  │ 动态渲染模板 flowDefinition.nodes   │    │  │ 操作记录时间线     │ │
│  │ ①节点1 → ②节点2 → ... → Ⓝ节点N    │    │  └──────────────────┘ │
│  └────────────────────────────────────┘    │                        │
│                                            │                        │
│  ┌─ 工单信息（只读）─────────────────┐    │                        │
│  │ 聚合已完成节点 nodeRecords 数据:    │    │                        │
│  │   label: [value in gray bg]       │    │                        │
│  │   照片: thumbnail                  │    │                        │
│  │ （排除当前节点 editable/hidden     │    │                        │
│  │  字段，仅展示有数据的字段）         │    │                        │
│  └────────────────────────────────────┘    │                        │
│                                            │                        │
│  ┌─ 当前节点名称（如"执行"）─────────┐    │                        │
│  │ DynamicForm                        │    │                        │
│  │   fields = editableFormFields      │    │                        │
│  │   permissions = currentFlowNode    │    │                        │
│  │     .formFields (editable only)    │    │                        │
│  │   initialData = formData           │    │                        │
│  │ [保存] / [驳回] [通过]             │    │                        │
│  └────────────────────────────────────┘    │                        │
└────────────────────────────────────────────┴────────────────────────┘
```

### 6.2 只读区与操作区的字段拆分逻辑

```
已知:
  - currentFlowNode = templateDetail.flowDefinition.nodes
      .find(n => n.id === currentNode.id)
  - nodeRecords = detail.nodeRecords (各节点已提交数据)
  - formSchema[currentNode.id].fields = 当前节点表单字段定义

只读区字段 = nodeRecords 中有数据的所有字段
  过滤: 不在 currentFlowNode.formFields 中标记为 editable 或 hidden
  渲染: label + 只读值（灰色背景块），图片显示缩略图

操作区字段 = currentFlowNode.formFields 中 mode='editable' 的字段
  从 formSchema[currentNode.id].fields 获取完整定义
  传入 DynamicForm 进行可编辑渲染
```

### 6.3 各节点典型表现

| 阶段 | 只读区展示 | 操作区展示 |
|------|-----------|-----------|
| 当前节点=指派 | 故障描述 + 故障照片（发起节点数据） | 指派人员选择器 |
| 当前节点=执行 | 故障描述 + 故障照片（发起节点数据） | 维修结果(radio) + 维修后照片(upload) |
| 当前节点=审批 | 故障描述 + 故障照片 + 指派人员 + 维修结果 + 维修后照片 | 验收结论(radio) + 驳回/通过按钮 |

随着流程推进，只读区字段逐节点累积增多。

### 6.4 已关闭状态

已关闭工单不显示双栏布局。改为简化模式：全部字段 readonly + SLA 指标卡片。右栏流转记录隐藏（内容已在节点区块中体现）。
