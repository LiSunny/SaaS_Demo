# 企业基础管理模块 — 详细设计

## 1. 概述

企业基础管理模块是维保服务协作平台的**基础支撑模块**，提供企业信息管理、人员管理、登录认证等底层功能。该模块是其他所有模块的前置依赖——无企业信息则无法创建合同和台账，无人员则无法分配维保任务。

**涉及角色：** 服务商端（管理员/业务负责人/维保人员）、业主端（管理员/安全负责人/巡查人员）

**模块定位：**

```
┌──────────────────────────────────────────────────────────────┐
│  企业基础管理 — 基础支撑层                                      │
│                                                              │
│  ┌──────────────────┐                                        │
│  │  登录/登出         │   所有模块的操作入口，未登录不可访问      │
│  ├──────────────────┤                                        │
│  │  企业信息管理      │   服务商和业主各自维护本单位基本信息       │
│  ├──────────────────┤                                        │
│  │  人员管理 CRUD     │   企业人员维护，用于分配合同负责人、       │
│  │                  │   维保人员、项目负责人等选择来源            │
│  └──────────────────┘                                        │
│                                                              │
│  下游依赖                                                   │
│  → 合同管理（选择负责人）                                      │
│  → 服务企业管理（选择项目负责人）                                │
│  → 维保计划（分配维保人员）                                    │
│  → 维保任务（指定执行人）                                      │
│  → 故障维修（指定维修人员）                                    │
└──────────────────────────────────────────────────────────────┘
```

## 2. 核心概念

### 2.1 企业类型

平台有两类企业角色，企业信息创建时确定类型，后续不可变更：

| 企业类型 | 系统标识 | 说明 |
|---------|---------|------|
| 服务商 | `isp` | 消防维保服务公司，提供维保/检测/巡查服务 |
| 业主单位 | `enterprise` | 接收消防服务的企业单位 |

### 2.2 两端企业关系

```
┌─────────────┐                    ┌─────────────┐
│  服务商 A    │                    │  业主甲      │
│  (一家公司)  │ ←─── 服务关系 ──→  │  (多家服务商) │
│             │                    │             │
│  基本信息:   │                    │  基本信息:   │
│  · 公司名称  │                    │  · 单位名称  │
│  · 信用代码  │                    │  · 信用代码  │
│  · 地址/联系人│                   │  · 地址/联系人│
│  · 服务资质  │                    │  · 建筑信息  │
└─────────────┘                    └─────────────┘
```

两端企业信息各自独立管理，互不干涉。服务商端企业信息注册时录入（系统初始化），业主端企业信息可由服务商在关联时新建（见 M2 服务企业管理模块）。

### 2.3 人员角色体系

**服务商端角色（3 个）：**

| 角色 | 标识 | 典型用户 | 核心权限 |
|------|------|---------|---------|
| 系统管理员 | `admin` | 公司负责人/IT 管理员 | 全部权限，含人员管理和系统设置 |
| 业务负责人 | `biz_manager` | 维保业务经理 | 除系统设置外全部业务模块操作权 |
| 维保人员 | `maintainer` | 现场维保工程师 | 仅任务执行、故障上报 |

**业主端角色（3 个）：**

| 角色 | 标识 | 典型用户 | 核心权限 |
|------|------|---------|---------|
| 系统管理员 | `admin` | 单位负责人 | 全部权限，含人员管理 |
| 安全负责人 | `safety_manager` | 消防主管 | 台账查看、任务跟踪、故障跟踪、报告查阅 |
| 巡查人员 | `inspector` | 安保人员 | 执行内部巡查、上报故障 |

## 3. 业务规则

### 3.1 企业信息规则

| 规则 | 说明 |
|------|------|
| 企业类型不可变更 | 创建时确定是"服务商"还是"业主单位"，后续不可修改 |
| 企业信息各自维护 | 服务商端和业主端各自管理本单位基本信息，互相不可见对方的管理界面 |
| 统一社会信用代码唯一 | 同一信用代码不可重复注册，系统校验唯一性 |
| 企业信息初始化 | 新企业加入平台时，由系统管理员在初始化阶段录入基础信息。不在本模块提供注册入口 |

### 3.2 人员管理规则

| 规则 | 说明 |
|------|------|
| 人员归属 | 每个人只属于一个企业（服务商或业主），不可跨企业 |
| 人员基本信息 | 姓名（必填）、手机号（必填，唯一）、邮箱（可选）、部门（可选）、岗位（下拉选项：技术负责人、项目负责人、维保人员）、职业资格证书名称（下拉选项：一级注册消防工程师、消防设施操作员）、证书编号（可选）、发证日期（可选）、有效期至（可选） |
| 手机号唯一校验 | 同一企业内手机号不可重复；跨企业允许重复（不同公司的员工） |
| 人员删除 | 已关联业务数据的人员不可删除（被设为合同负责人、计划负责人等），需提示"该人员已被业务引用，请先解除关联再删除" |
| 人员停用 | 支持停用/启用人员。停用人员不可登录系统，不可被选为负责人或执行人。已有业务数据不受影响 |

### 3.3 登录规则

| 规则 | 说明 |
|------|------|
| 登录方式 | 手机号 + 密码登录 |
| 首次登录 | 系统初始化时管理员分配账号和初始密码，首次登录强制修改密码 |
| 密码规则 | 8-20 位，含字母和数字 |
| 登出 | 主动登出后跳转至登录页 |
| 未登录访问 | 未登录状态下无法访问任何业务页面，自动跳转登录页 |
| 两端隔离 | 服务商端账号和业主端账号互不通用（登陆入口不同，但系统可自动识别企业类型跳转到对应端） |

### 3.4 Demo MVP 简化规则

| 简化项 | 处理方式 |
|--------|---------|
| 注册流程 | MVP 不提供注册入口，假定企业信息已由系统初始化 |
| 密码修改 | MVP 跳过首次强制修改密码流程，直接使用初始密码 |
| 角色权限校验 | MVP 不实现细粒度权限控制，所有角色可见全部页面（仅用于演示流转） |
| 手机验证码 | MVP 不使用验证码登录，仅手机号+密码 |

### 4.1 登录页（两端通用）

**页面布局：**

```
┌─────────────────────────────────────┐

│                                     │

└─────────────────────────────────────┘
```

**规则：**
- 顶部显示平台名称
- 手机号和密码为必填项
- 底部两个入口 Tab：「服务商端入口」「业主端入口」，默认选中服务商端
- 输入账号密码后点击登录，系统校验账号所属企业类型是否与所选入口匹配
- 匹配 → 进入对应端首页（待办工作台）
- 不匹配 → 提示"账号与所选端不匹配，请确认登录入口"

**错误提示：**
- 手机号为空 → "请输入手机号"
- 密码为空 → "请输入密码"
- 账号不存在 → "账号不存在"
- 密码错误 → "密码错误"
- 人员已停用 → "该账号已停用，请联系管理员"

## 5. 数据联动关系

### 5.1 与其它模块的联动

```
人员管理 → 新增人员    → 合同"负责人"下拉选项增加
         → 删除人员    → 被引用时阻止删除，提示引用来源
         → 停用人员    → 所有下拉选择中不再出现该人员
                        （已有引用不受影响）

企业信息 → 信息变更    → 服务企业列表/详情中企业基本信息同步更新
         → 信用代码    → 关联业主单位时用于校验唯一性
```

### 5.2 联动规则矩阵

| 触发动作 | 影响范围 | 效果 |
|---------|---------|------|
| 新增人员 | 合同"负责人"下拉 | 即时新增可选人员 |
|  | 维保计划"负责人/人员"下拉 | 即时新增可选人员 |
|  | 故障"维修人员"下拉 | 即时新增可选人员 |
|  | 服务企业"项目负责人"下拉 | 即时新增可选人员 |
| 删除人员（业务引用校验） | 合同模块 | 如该人员是合同负责人，阻止删除 |
|  | 维保计划模块 | 如该人员是计划负责人或维保人员，阻止删除 |
|  | 服务企业管理 | 如该人员是项目负责人，阻止删除 |
| 停用人员 | 所有下拉选择 | 不可被新业务选择（已有业务保留记录） |
| 企业信息变更 | 服务企业详情 | 同步更新（仅企业基础信息字段） |
|  | 合同详情 | 同步更新（仅企业名称、地址等基础信息） |

## 6. 业务边界场景

| 场景 | 处理方式 |
|------|---------|
| **企业无任何人员** | 初始化后至少需新增一名管理员才能进行后续操作。人员列表为空时引导新增 |
| **手机号已存在** | 同一企业内手机号重复时保存校验不通过，提示"该手机号已被使用" |
| **删除最后一名系统管理员** | 提示"至少保留一名系统管理员" |
| **人员已被停用但想删除** | 允许删除（已停用人员不参与业务，无引用风险） |
| **企业信息所有字段为空** | 企业初始化信息应至少包含企业名称和信用代码，否则无法保存 |
| **登录时选择入口错误** | 提示"账号与所选端不匹配"，推荐正确入口 |
| **密码连续错误** | MVP 不做锁定限制（后续迭代补充），仅提示密码错误 |
| **加载中状态** | 登录提交按钮显示加载状态，禁止重复点击 |
| **人员列表超长** | 支持分页，默认每页 10 条 |
