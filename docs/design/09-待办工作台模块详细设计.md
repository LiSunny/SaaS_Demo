# 待办工作台模块 — 详细设计

## 1. 概述

待办工作台是两端用户的**统一工作入口**，聚合各模块中待处理的事项，帮助用户快速了解当前需要处理的工作并按优先级推进。每个跨模块协作节点（合同待确认、任务待执行、故障待维修等）都会在待办列表中生成对应条目。

**涉及角色：** 服务商端、业主端（两端各自聚合各自的待办）

**模块定位：**

```
┌────────────────────────────────────────────────────────────┐
│                    待办工作台                               │
│                  统一工作入口                               │
│                                                            │
│  聚合来源：                                                 │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐          │
│  │ 合同管理  │ │ 维保任务 │ │ 故障与   │ │ 报告管理  │          │
│  │         │ │         │ │ 隐患    │ │         │          │
│  │ 待确认   │ │ 待执行   │ │ 待维修   │ │ 待提交   │          │
│  │ 合同     │ │ 任务     │ │ 故障    │ │ 报告     │          │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘          │
│                                                            │
│  产出：待办列表（按模块分类 / 按优先级排序）                   │
└────────────────────────────────────────────────────────────┘
```

## 2. 核心概念

### 2.1 什么是待办事项

待办事项是系统根据业务数据状态**自动生成**的工作提醒条目，不是用户手动创建的任务列表。

| 维度 | 说明 |
|------|------|
| 生成方式 | 系统自动生成，无需手动创建 |
| 生命周期 | 条件满足时生成，业务处理完成后自动消失 |
| 两端隔离 | 服务商端和业主端各自展示本角色相关的待办 |

### 2.2 待办类型清单

**服务商端待办类型：**

| 待办类型 | 来源模块 | 生成条件 | 消失条件 | 优先级 |
|---------|---------|---------|---------|--------|
| 合同待确认 | M3 合同管理 | 业主端确认签订后，服务商端收到通知（MVP 简化：合同创建后即产生） | 合同状态变更为"已签订" | 中 |
| 计划待确认 | M5 维保计划 | 计划状态为"未确认" | 计划状态变为"已确认" | 中 |
| 任务待执行 | M6 维保任务 | 任务状态为"待执行"且当前登录用户被分配为执行人 | 任务状态变为"执行中"或"已完成" | 高 |
| 故障待受理 | M7 故障与隐患 | 业主转发故障给服务商，状态为"待受理" | 服务商受理后状态变为"维修中" | 高 |
| 报告待提交 | M8 报告管理 | 报告状态为"草稿" | 报告已提交 | 中 |

**业主端待办类型：**

| 待办类型 | 来源模块 | 生成条件 | 消失条件 | 优先级 |
|---------|---------|---------|---------|--------|
| 合同待确认 | M3 合同管理 | 服务商创建合同，状态为"待确认" | 业主确认签订或作废 | 高 |
| 故障待处理 | M7 故障与隐患 | 故障状态为"待维修"（来源=维保上报） | 业主已操作（内部维修/转发） | 高 |
| 隐患待上报 | M7 故障与隐患 | 巡查人员自查中发现隐患但未上报（MVP 不实现，预留） | — | 低 |

## 3. 业务规则

### 3.1 待办生成规则

| 规则 | 说明 |
|------|------|
| 自动生成 | 业务数据状态变更时，系统自动检查并生成对应的待办条目 |
| 不重复 | 同一业务数据在同一状态下只生成一条待办（多次操作不会重复生成） |
| 批量生成 | 任务生成后，所有被分配的执行人都会在自己的待办中看到该任务 |

### 3.2 待办消失规则

| 规则 | 说明 |
|------|------|
| 自动消失 | 对应业务数据处理完成后，待办条目自动从列表中移除 |
| 状态驱动 | 待办的存在与否完全由业务数据状态决定，不独立维护"已完成"状态 |

> 例：任务待执行 → 维保人员签到（任务状态变为"执行中"）→ 待办自动消失

### 3.3 优先级定义

| 优先级 | 标识 | 适用场景 |
|--------|------|---------|
| 高 | 🔴 | 需要立即处理的事项（待执行任务、待维修故障） |
| 中 | 🟡 | 需要尽快处理但不紧急（待确认合同、待提交报告） |
| 低 | 🟢 | 信息提醒性质 |

### 3.4 待办聚合规则（动态聚合）

待办列表从各模块的业务数据中**实时计算**生成，而非独立存储：

| 待办类型 | 来源数据 | 聚合条件 | 优先级 | 操作跳转 |
|---------|---------|---------|--------|---------|
| 合同待确认（服务商端） | CONTRACT_LIST | status = '待确认' | 中 | 合同列表 / 详情 |
| 合同待确认（业主端） | CONTRACT_LIST | status = '待确认' | 高 | 合同详情（确认/作废） |
| 计划待确认 | PLAN_LIST | status = '未确认' | 中 | 计划详情 |
| 任务待执行 | TASK_LIST | status = '待执行' | 高 | 任务执行页 |
| 故障待维修 | FAULT_LIST | status = '待维修' | 高 | 故障详情 |
| 报告待提交 | REPORT_LIST | status = '草稿' | 中 | 报告列表（编辑/提交） |

聚合时机：页面加载时、切换 Tab 时、业务操作（创建/编辑/状态变更）后主动刷新。

### 3.5 Demo MVP 简化规则

| 简化项 | 处理方式 |
|--------|---------|
| 实时推送 | MVP 不实现 WebSocket 实时推送，手动刷新页面或切换 Tab 时更新 |
| 待办数量 | MVP 仅展示列表，不实现顶部角标数字 |

## 5. 数据联动关系

### 5.1 与其它模块的联动

```
合同管理 ──创建合同（待确认）──→ 业主端生成"合同待确认"待办
         业主确认签订────────→ 该待办自动消失

维保计划 ──计划未确认────────→ 服务商端生成"计划待确认"待办
         上传确认函后──────→ 该待办自动消失

维保任务 ──生成任务（待执行）──→ 被分配执行人：服务商端生成"任务待执行"待办
         签到后────────────→ 该待办自动消失

故障隐患 ──业主转发服务商────→ 服务商端生成"故障待受理"待办
         服务商受理────────→ 该待办自动消失
         维保上报故障──────→ 业主端生成"故障待处理"待办
         业主操作（内部维修/转发）→ 该待办自动消失

报告管理 ──创建草稿────────→ 服务商端生成"报告待提交"待办
         提交报告────────→ 该待办自动消失
```

### 5.2 数据结构

每条待办记录包含以下字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| id | 唯一标识 | todo_001 |
| userId | 所属用户 | user_001 |
| type | 待办类型 | task_pending |
| sourceModule | 来源模块 | M6 维保任务 |
| sourceBizId | 关联业务 ID | task_001 |
| title | 待办标题 | 2026年5月月度维保计划_0518_1 |
| description | 补充描述 | 业主：××物业有限公司 |
| priority | 优先级 | HIGH / MEDIUM / LOW |
| status | 状态 | pending |
| actionLabel | 操作按钮文案 | 开始执行 |
| actionRoute | 跳转路由 | /maintenance/tasks/001/execute |
| createdAt | 生成时间 | 2026-05-18 09:00 |
| expiredAt | 消失时间（自动移除） | 2026-05-18 10:30（状态变更触发移除） |

## 6. 业务边界场景

| 场景 | 处理方式 |
|------|---------|
| **待办列表为空** | 展示「暂无待办事项，所有工作已处理完毕」，配完成状态图标 |
| **同一业务多条待办** | 不允许重复生成。合同/故障/报告每个业务在一种状态下只产生一条待办 |
| **用户刷新页面后待办不一致** | 进入页面时重新拉取最新待办列表（MVP 不做实时推送） |
| **待办指向的业务已被其他用户处理** | 点击跳转后正常展示业务详情（如已被他人受理，显示已处理状态） |
| **大量待办堆积** | 支持分页，默认每页 10 条。顶部快捷概览帮助快速了解各类型数量 |
| **用户无任何业务数据** | 工作台仅展示快捷概览（全部为 0）和"暂无待办"提示 |
