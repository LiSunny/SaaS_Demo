## 一、四方用户导航（已落地）

平台导航按**使用群体**组织，每种用户登录后只看到自己的业务分组。群体标签标记在**企业**上（`Enterprise.groups`），登录后按当前企业判定菜单；岗位决定组内子项可见性。

| 群体标签 | 导航分组 | 典型企业 | 登录后看到 |
|---------|---------|---------|-----------|
| `regulator` | **区域监管** | 应急局、市监局、街道办 | 态势总览 · 督办管理 · 监管检查 · 监管报告 |
| `unit` | **安全管理** | 学校、企业、集团、商户、物业 | 本企态势 · 巡查检查 · 隐患管理 · 危险作业 · 设备管理 · 食品安全 · 培训演练 · 我的工单 |
| `operator` | **项目管理** | 运营商（重点单位联网/九小场所管理） | 项目总览 · 项目列表 · 成员交付 · 项目工单 |
| `service` | **技术服务** | 维保、检测、评估机构 | 我的工单 · 维保合同 · 维保计划 · 服务报告 |
| `platform-ops` | **运营管理** | 平台运营方（系统角色） | 租户 · 用户 · 岗位 · 大屏配置 · 流程模板 · 类型注册 |
| `platform-admin` | **平台管理** | 技术管理（系统角色） | 路由配置 · 菜单管理 · 系统参数 · 升级管理 |

**判定链路**：用户登录 → 取关联企业 `groups`（无企业时按岗位 `group` 兜底）→ 侧栏按群体过滤分组 → 组内子节点按岗位 `visibleTo` 过滤。

> `platform-ops` 同时具备「运营管理 + 平台管理」两个分组（2026-08-03 决策）；`platform-admin` 仅「平台管理」。

### 一之三、与使用场景口径的对应

导航分组是**使用主体视角**（谁登录后看到什么），与 [使用场景与用户分类](使用场景与用户分类.md) 的五类使用主体一一对应，外加两个平台方系统角色分组：

| # | 使用场景（对外口径） | 主体 | 群体标签 | 导航分组 | 落地情况 |
|:--:|---|---|---|---|---|
| ① | 面向监管机构的区域联勤监管 | 监管机构 | `regulator` | 区域监管 | ◐ 监管大屏已实做，其余占位 |
| ② | 面向社会单位的消防安全自主管理 | 社会单位 | `unit` | 安全管理（+ 隐患排查治理 / 协同工作 / 单位设置） | ◐ 隐患治理与设备台账已实做 |
| ③ | 面向技术服务机构的消防维保服务 | 技术服务机构 | `service` | 技术服务 | ◐ 工单与维保计划已实做 |
| ④ | 面向运营商的消防安全托管运营 | 运营商 | `operator` | 项目管理 | ○ 整组占位 |
| ⑤ | 面向家庭用户的居家消防安全 | 家庭用户 | — | **居家安全（待建）** | ⛔ 无分组、无账号归属 |
| — | *（非使用场景）* | 平台方 | `platform-ops` / `platform-admin` | 运营管理 / 平台管理 | ✅ / ○ |

**两点注意**：

1. **平台方不是使用场景** —— 它是平台自身的运营与技术管理角色，不在对外的五类使用主体之内。导航上保留两个系统角色分组，属实现需要。
2. **家庭用户当前无导航可进** —— 家庭在设计上是运营商项目里的成员类型（不开账号、不给岗位），只存在于项目上下文；若要支持家庭自主注册，需先在底座补 `household` 分类、群体标签与账号归属。详见 [使用场景与用户分类 §4.2](使用场景与用户分类.md#42-家庭场景的底座缺口)。

> **"四方"这个名字的由来**：本文档最初只描述监管 / 单位 / 服务 / 平台四个群体，运营商与家庭用户是在 2026-08-03、2026-10-21 两次重构中分别补入的。文档标题保留"四方"是为了不改文件名（多处引用），**内容已按五类使用主体对齐**。

## 二、体验账号体系（登录页「快速体验」）

登录页提供 **5 张体验卡**，对应五个使用群体。每张卡 = **真实数据库账号一键代填登录**，走完整登录链路（`POST /api/auth/login`），登录后展示该群体的专属菜单。本质是「**选择 XX 开始体验**」。

### 2.1 账号清单

| 体验卡 | 群体 | 账号 | 密码 | 对应企业 | 岗位 | 登录后导航分组 |
|--------|------|------|------|---------|------|--------------|
| 🛡️ 监管机构 | regulator | `13000000001` | `admin123!@#` | 海港应急局 | org-admin | 区域监管 |
| 📋 社会单位 | unit | `13100001234` | `admin123!@#` | 新思维中学 | org-admin | 安全管理 |
| 📦 运营商 | operator | `18800001234` | `admin123!@#` | 安信智慧消防运营 | org-admin | 项目管理 |
| 🔧 技术服务机构 | service | `13900002222` | `admin123!@#` | 蓝盾消防 | org-admin | 技术服务 |
| ⚙️ 平台方 | platform-ops | `13800000001` | `3xkxr4` | —（系统角色） | — | 运营管理 + 平台管理 |

> 技术管理视角：`17733550542` / `3jzl8h`（platform-admin，李阳）→ 平台管理。

### 2.2 交互逻辑

```
点击体验卡
  → fillDemo(account)     代填 phone/password
  → handleLogin()         真实登录 API
  → POST /api/auth/login  bcrypt 校验 → JWT
  → userStore.setLogin()  存 token + user
  → 按 user.groups 过滤导航
```

### 2.3 三条登录路径（同一套 API）

| 路径 | 触发 | 说明 |
|------|------|------|
| 手动登录 | 输入手机号+密码 | 标准路径 |
| 体验卡一键登录 | 点击卡片 | 代填 + 自动提交 |
| URL 参数自动登录 | `/login?phone=xxx&password=yyy` | 门户「去体验」按钮带参跳转 |

### 2.4 设计要点

- **账号真实存在**：每张卡对应数据库中的 User + UserEnterprise 关联 + 企业 groups 标签，登录后菜单/权限/数据范围均由真实逻辑计算
- **演示用明文密码**：demo 场景可接受；如需收紧可移除体验卡或改为受控环境
- **dev/prod 账号一致**：`Login.vue` 的 `import.meta.env.PROD` 分支当前两边相同
- **登录后跳转**：系统角色 → 工作台；企业用户 → 默认大屏优先 → redirect → 工作台
