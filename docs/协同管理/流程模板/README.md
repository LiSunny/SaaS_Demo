```
┌─────────────────┐
│ 火灾隐患排查上报 │

         │ 涉及设施损坏
         ↓
┌─────────────────┐         ┌────────────────────┐
│ 消防设施维修申请 │         │   动火作业审批      │
│ flow-template-03 │         │  flow-template-04   │
└─────────────────┘         └────────────────────┘

┌─────────────────┐         ┌────────────────────┐
│  消防演练申请   │         │   消防培训申请     │

└─────────────────┘         └────────────────────┘
```

**联动建议**:
- 火灾隐患排查上报 → 需整改时发起"火灾隐患整改处置"
- 火灾隐患整改 → 涉及设施损坏可发起"消防设施维修申请"
- 设施维修(电焊/切割)→ 同时发起"动火作业审批"
- 消防演练/培训可独立发起，也可作为年度计划批量创建

## 三、文档结构(每份文档统一结构)

每份流程配置规范都包含以下章节,便于按章节查阅:

```
一、基础信息         → 模版名称、工单说明、SLA 配置
二、表单字段清单     → 字段表格(字段名/类型/必填/说明)
三、字段详细配置     → 每个字段的属性、验证规则、占位文本
四、form-create 规则 JSON → 可直接导入的表单 JSON
五、流程节点清单     → 节点总览(类型/处理人/SLA)
六、节点详细配置     → 每个节点的按钮/抄送/条件/超时规则
七、操作步骤         → 浏览器手动配置的逐步说明
八、校验清单         → 配置完成后自检的勾选项
附录                → 等级定义/法律依据/术语表/关联文档
```

## 五、使用方法

### 5.1 单文档使用

按需求选择对应文档,直接按章节配置:

1. 打开目标流程文档(如 `flow-template-02-火灾隐患整改处置.md`)
2. §一 基础信息 → 在平台"基础信息"页填入
3. §四 form-create JSON → 导入表单设计器
4. §五-六 节点配置 → 在流程设计器按表格配置
5. §七 操作步骤 → 浏览器手动确认配置
6. §八 校验清单 → 配置完成后逐项打勾

### 5.2 批量使用(推荐)

如果需要一次性配置 8 个流程,建议按以下顺序:

| 顺序 | 流程 | 理由 |
|:---:|------|------|
| 1 | 火灾隐患排查上报 | 最常用,先跑通主流程 |
| 2 | 火警事件处置 | 紧急流程,优先级最高 |
| 3 | 故障事件处置 | 紧急流程 |
| 4 | 消防设施维修申请 | 与隐患关联,设施整改触发 |
| 5 | 动火作业审批 | 风险作业,审批流程独立 |
| 6 | 火灾隐患整改处置 | 隐患整改闭环 |
| 7 | 消防演练申请 | 周期性工作 |
| 8 | 消防培训申请 | 周期性工作 |

## 六、配置规范要点(通用)

### 6.1 字段 ID 命名

- 使用英文驼峰: `location`、`hazardLevel`、`estimatedCost`
- 不使用拼音: ❌ `weizhi`、`yinhuanLevel`
- 不使用缩写: ❌ `loc`、`lvl`

### 6.2 必填原则

- **必填字段**(不可空):影响审批判断的核心字段(位置、类型、描述、照片)
- **条件必填**(条件成立时必填):如报警单位(是否报警=是时必填)
- **选填字段**:辅助信息、应急预案、备注

### 6.3 选人原则

- ✅ **优先按岗位**:`消防安全管理人`、`部门安全员`、`维保单位管理员`
- ✅ **按角色配置**:跨部门的统一角色(如"评估委员会")
- ❌ **避免按具体人**:`张三` —— 人员变动后流程断链

### 6.4 流程节点原则

- 节点数控制在 **3-9 个**
- 每个节点只做一件事
- 必须设置**结束节点**
- **抄送节点**单独设置(不与审批节点混)

### 6.5 验证规则原则

- 文本字段:必填 + 长度上限
- 数字字段:必填 + 范围
- 时间字段:必填 + 与当前时间关系(如 ≥ 当前 + 24h)
- 照片:必填 + 数量限制
