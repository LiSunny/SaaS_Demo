## 第一章 专题概述

### 1.1 为什么需要专题文档

消防与安全管理类流程与一般审批流(请假、采购、报销)**有显著差异**:

| 差异点 | 一般审批流 | 消防/安全流程 |
|--------|-----------|--------------|
| 时效要求 | 宽松(可等 3-5 天)| 严格(分钟级 / 小时级) |
| 现场证据 | 通常不需要 | **必须**有照片 / 视频 |
| 闭环要求 | 多数可"批了就完" | **必须**有处置 + 验收 |
| 跨单位协作 | 极少 | 常态(物业 + 维保 + 监管)|
| 失败后果 | 影响业务效率 | **可能影响人员安全** |

### 1.2 谁应该读这份专题

| 你的角色 | 重点阅读章节 |
|---------|------------|
| **消防安全管理人** | 第二章 流程清单 + 第三章 核心场景 + 第四章 最佳实践 |
| **安全员 / 巡查员** | 第三章 核心场景(应急事件、隐患排查)+ 第五章 操作卡片 |
| **部门负责人** | 第三章 核心场景(消防设施维修、故障处置、火警应急处置)+ 第四章 最佳实践 |
| **维保单位人员** | 第三章 场景 2(消防设施维修)+ 第五章 操作卡片 |
| **政府监管方(应急局)** | 第六章 流程编排避坑(监管方跨单位流程详见总纲 §5.2.1 模板 05「重大隐患挂牌督办」) |
| **系统管理员 / 流程配置员** | 第六章 流程编排避坑指南 |

### 1.3 专题与通用版的关系

- **通用版**:讲"协同模块怎么用",是通用框架
- **本专题**:讲"消防/安全场景怎么用协同模块",是场景化补充

> 建议**先读通用版**,再读本专题。

## 第三章 核心场景详细操作

### 场景 1:🔴 应急事件上报(紧急 + 高频)

#### 背景

某日凌晨 3 点,消防控制室主机报警,显示"教学楼 3 层烟感探测器报警"。

#### 流程流转示意

```
[03:05] 值班员在远程值守页面看到报警
   ↓
[03:06] 值班员通过"应急事件上报"流程提交
        - 报警位置:教学楼 3 层
        - 报警类型:烟感
        - 附件:实时截图
   ↓
[03:07] 系统自动推送"紧急"标签,优先通知:
        ① 现场值班人员(手机 App + 短信)
        ② 部门安全员
        ③ 消防安全管理人
        ④ 分管领导
   ↓
[03:10] 现场人员到达现场核查,填报:
        - 是否真实火情
        - 初步处置情况
   ↓
[03:30] 处置完成,填报闭环信息
   ↓
[03:35] 分管领导签字确认,流程归档
```

#### 操作步骤(应急事件上报流程)

| 步骤 | 操作 | 注意事项 |
|------|------|---------|
| 1 | 登录系统 → 协同工作 → 发起事项 | 选"应急事件上报"流程(别选错!选成"安全检查"就漏了紧急通道)|
| 2 | 填写报警信息 | 报警位置、报警时间、报警类型 |
| 3 | 上传现场截图/视频 | **必须有附件**,便于远程决策 |
| 4 | 选"紧急"等级 | 紧急流程走特殊审批通道,响应更快 |
| 5 | 提交 | 提交后系统自动通知所有相关人 |

#### 应急流程特别强调

- **不要等现场核实完再上报**——先上报"预警",后续补充细节
- **附件是关键**——领导远程决策全靠照片视频
- **紧急等级不要乱选**——非紧急用紧急会"狼来了",真紧急时反而没人响应

### 场景 2:🟡 消防设施故障维修闭环(高频)

#### 背景

消防泵房巡检发现"消火栓泵 2 号机无法启动"。

#### 流程闭环

```
[第1天 上午]  巡检员发起"消防设施维修申请"
              - 设备名称:2 号消火栓泵
              - 故障描述:无法启动,控制柜报警
              - 附件:现场照片
   ↓
[第1天 下午]  设施负责人审批(判断是否需要外部维保)
   ↓
[第2天]       维保单位接单,上门维修
   ↓
[第3天]       维修完成,维保单位在流程里上传:
              - 维修记录
              - 测试视频
              - 新更换配件清单
   ↓
[第3天]       部门负责人验收(测试设备正常)
   ↓
[第4天]       流程归档,自动同步到"设备档案"
```

#### 操作步骤(消防设施维修申请)

| 步骤 | 角色 | 操作 |
|------|------|------|
| 1 | 巡检员 | 协同工作 → 发起事项 → 选"消防设施维修" |
| 2 | 巡检员 | 拍 3 张照片:故障全景、铭牌、控制柜显示 |
| 3 | 设施负责人 | 收到待办 → 判断:内部修 / 外部修 / 紧急修 |
| 4 | 设施负责人 | 选对应处理方式,系统自动派单 |
| 5 | 维保单位 | 维修时在流程里**实时更新进度**(不是修完一次性填)|
| 6 | 部门负责人 | 现场验收,签字 |
| 7 | 系统 | 自动归档至设备维修档案 |

#### 闭环最佳实践

- **附件要分阶段上传**:故障照片、维修过程、验收测试,**3 段都要**
- **进度要实时更新**:不要修完一次性填,**领导看到"未更新"会催**
- **验收必须有现场照片**:避免"假验收"

### 场景 3:🟠 故障处置(报警/误报/异常现场处置)

#### 背景

凌晨 3 点,消防控制室主机弹出告警:"教学楼 3 层烟感探测器报警"。监控员在远程值守页面看到红色告警,触发"故障处置"流程。

#### 故障处置与消防设施维修的边界

| 类型 | 触发 | 流程去向 |
|------|------|---------|
| **故障处置** | 设备**触发告警**(报警/误报/异常状态) | 现场核实 → 分类处置 |
| **消防设施维修申请**(场景 2) | 设备**发现损坏**(巡检/肉眼可见) | 报修 → 维修 → 验收 |

> 一句话区分:**告警来了 → 故障处置;坏了要修 → 维修申请。**

#### 流程分流示意

```
[告警触发]
   ↓
[故障处置流程启动]
   ↓
[监控员] → 现场负责人(现场核实,≤ 30 分钟)
   ↓
[核实结果 三选一]
   ├─ 误报 → 设备复位 → 流程归档(无后续)
   ├─ 真故障 → 转"消防设施维修申请"(场景 2)→ 流程归档
   └─ 真警 → 升级为"火警应急处置"(场景 4)→ 流程归档
```

#### 操作步骤(故障处置)

| 步骤 | 角色 | 操作 | 提示 |
|------|------|------|------|
| 1 | 监控员 | 协同工作 → 发起事项 → 选"故障处置" | 别选成"应急事件上报"——本流程只处理报警/异常,不含真实事件 |
| 2 | 监控员 | 填告警信息:告警位置、设备类型、告警时间 | 系统可自动带出,人工核对 |
| 3 | 监控员 | 上传报警截图/录像 | **必填**,便于远程判断 |
| 4 | 现场负责人 | 现场核实(拍照、检测设备) | **30 分钟内必须到现场** |
| 5 | 现场负责人 | 判断结果:误报 / 真故障 / 真警 | 选错会导致流程卡死,必要时电话联系监控员 |
| 6 | 设施负责人 | 接收误报记录 / 维修申请 / 火警升级 | 自动派单,无需重复发起 |
| 7 | 系统 | 归档(分流后流程独立计数) | 误报率、设备故障率可统计 |

#### 故障处置最佳实践

- **时间窗是核心**:告警到现场 ≤ 30 分钟是硬要求,超时升级到消防安全管理人
- **分流判断要留痕**:误报必须填"误报原因"(灰尘/蒸汽/人为),便于设备维护方改进
- **误报不丢人**:误报频次是设备健康度的指标,系统可统计"误报率"
- **真警升级要快**:现场判断为真警,**立即**走火警应急处置,不要在故障处置里卡流程

### 场景 4:🔴 火警应急处置(复用应急事件上报)

#### 背景

故障处置现场核实为真实火警(教学楼 3 层烟感 + 现场看到明火),立即升级到"火警应急处置"流程。

#### 与场景 1(应急事件上报)的关系

| 维度 | 应急事件上报(场景 1) | 火警应急处置(场景 4) |
|------|--------------------|--------------------|
| 模板 | 应急事件上报 | 应急事件上报(**同一模板**) |
| 分类选择 | 火警 / 电梯困人 / 触电 / 其他 | **仅"火警"** |
| 优先级 | 普通/紧急/红色 | **默认红色** |
| 触发联动 | 默认通知 | **默认触发应急预案 + 119 联动** |
| 适用阶段 | 预警 → 处置 → 闭环 | 确认火警 → 应急启动 → 处置 → 摘牌 |

> **火警不是新流程**,是"应急事件上报"模板的**最高优先级类型**。在消防类场景单独列出,是因为它需要联动应急预案 + 119,和一般应急事件不同。

#### 火警应急流程示意

```
[故障处置 → 真警升级]
   ↓
[应急事件上报流程 · 火警类型]
   ↓
[03:07] 系统自动推送红色标签 + 紧急通道
        ① 现场值班人员(手机 App + 短信)
        ② 部门安全员
        ③ 消防安全管理人
        ④ 分管领导
        ⑤ **自动触发应急预案** → 应急疏散广播启动
        ⑥ **联动 119** → 推送火警位置 + 现场照片
   ↓
[03:10] 现场人员到达 → 初步处置 → 填报现场情况
   ↓
[03:30] 119 到达 → 配合处置 → 填报处置过程
   ↓
[xx:xx] 火情扑灭 → 现场值守 → 摘牌确认
   ↓
[24 小时内] 分管领导签字 + 事故调查报告 → 归档
```

#### 操作步骤(火警应急处置)

| 步骤 | 角色 | 操作 | 注意事项 |
|------|------|------|---------|
| 1 | 现场人员/监控员 | 协同工作 → 发起事项 → 选"应急事件上报" → 类型选"火警" | **别选其他类型**,火警走红色通道 |
| 2 | 现场人员 | 填火警信息:位置、起火物质、是否有人员被困 | 越快越好,**不要等核实完再上报** |
| 3 | 现场人员 | 上传现场照片/视频 | **至少 1 张实时图**,便于远程指挥 |
| 4 | 系统 | 自动通知 + 自动触发应急预案 + 自动拨打 119 | **不需要人工触发** |
| 5 | 部门安全员 | 5 分钟内响应,启动应急疏散 | 现场优先级最高,流程可后补 |
| 6 | 消防安全管理人 | 协调应急资源,对接 119 | 全程保持通讯 |
| 7 | 分管领导 | 24 小时内组织事故调查,填报《火灾事故调查报告》 | 调查含:起火原因、伤亡、损失、责任 |
| 8 | 系统 | 归档至"重大事件档案" | 自动同步至消防安全管理人年度报告 |

#### 火警应急最佳实践

- **先预警再核实**:不要等核实完再上报,**先发"预警"**,系统会通过红色通道通知所有相关人
- **附件要实时**:每隔 5 分钟补一张现场照片,领导远程决策全靠
- **119 联动系统做**:平台与 119 联动后,位置+平面图自动推送,不要靠人工电话
- **事故报告必填**:**24 小时内必须提交**事故调查报告,否则流程不闭环
- **预案触发要可重入**:同一火警可能反复触发预案(如有复燃),系统要支持预案重入而不是新建流程

### 场景 5:🟢 日常隐患排查上报(最低门槛、最高频)

#### 背景

巡检员发现"灭火器压力不足"。

#### 操作步骤(隐患排查上报)

| 步骤 | 操作 | 提示 |
|------|------|------|
| 1 | 协同工作 → 发起事项 → 选"隐患排查上报" | 别选成"应急上报"(紧急程度不同)|
| 2 | 选隐患类型 | 消防 / 电气 / 机械 / 危化品 / 其他 |
| 3 | 填隐患位置 | **选到具体点位**(楼栋-楼层-房间号),不要只写"教学楼" |

| 6 | 上传照片 | **至少 1 张**,最好 3 张(远景 / 中景 / 近景) |
| 7 | 提交 | 提交后系统自动派给对应整改责任人 |

## 第四章 消防/安全场景特殊最佳实践

### 4.1 🚨 应急类流程的"黄金 5 分钟"原则

> 应急事件从发现到上报,**不超过 5 分钟**。

- **不要**等现场核实完再上报——先"预警",后"详情"
- **不要**纠结走哪个流程——选最接近的,**事后再补流程**
- **紧急流程不要走标准审批链**——预设"紧急通道"(2-3 个节点即可)

**系统层面建议**:

- 应急类流程默认**短信 + App 推送 + PC 弹窗**三重通知
- 应急流程默认**24 小时未响应自动升级**(自动通知上一级领导)

---

### 4.2 📸 现场照片的"3 + 1"原则

> 所有现场相关流程,**至少 3 张照片 + 1 段视频**。

| 类型 | 要求 |
|------|------|
| **远景** | 看整体环境,让审批人知道"在哪" |
| **中景** | 看主体对象,让审批人知道"是什么" |
| **近景** | 看问题细节,让审批人知道"多严重" |
| **1 段视频**(选填) | 涉及动态过程(冒烟、漏液、报警器响)必传 |

**❌ 反例**:

- 1 张模糊的远景(看不清问题)
- 截图不是实拍(领导要看现场,不是看系统)
- 只拍"我修好了"(不拍"修之前什么样")

---

### 4.3 ⏰ 时效约束表

| 流程类型 | 期望响应时长 | 超时处置 |
|---------|------------|----------|
| 火灾报警 / 应急事件 | **≤ 15 分钟** | 自动升级到上一级 |
| 重大隐患处置 | **≤ 24 小时** | 系统提醒 + 监管员介入 |
| 消防设施故障 | **≤ 48 小时** | 影响消防验收的标记为"紧急" |
| 一般隐患整改 | **≤ 7 天** | 超期自动生成"逾期"标签 |
| 危险作业审批(动火/高空) | **≤ 2 小时** | 现场不能等 |
| 日常检查计划 | **≤ 3 天** | 仅提醒,不升级 |

**📌 提示**:逾期会有什么后果,应明确写入流程说明,告诉用户这不是"随便一填"。

---

### 4.4 🔄 闭环必填项设计(避免"形式签字")

> 所有安全类流程,**必须设计成"有闭环"**。不能"提交 → 同意 → 归档"三步就完。

**完整闭环至少包含**:

```
发现 → 上报 → 受理 → 处置(过程留痕) → 验收(现场证据) → 归档(进入档案)
```

**❌ 反例**:"消防泵故障维修"流程只设计了"申请 → 审批 → 同意"3 个节点,没有"维修记录"、"验收测试"必填项。结果:流程通过,但没人知道修没修、修得怎么样。

**✅ 正例**:维修流程节点必须包含:

- 故障描述 + 现场照片(申请时)
- 维修方案 + 配件更换清单(处置时)
- 维修前后对比照片 + 测试视频(验收时)
- 验收签字(部门负责人)

---

### 4.5 👥 角色与职责清晰

| 角色 | 在协同模块的典型操作 |
|------|---------------------|
| **安全员 / 巡查员** | 发起隐患排查 / 应急事件 / 巡检计划 → **发起方视角** |
| **部门负责人** | 审批本部门流程 / 关注本部门待办 → **审批方视角** |
| **消防安全管理人** | 监管全单位安全流程 / 处置重大隐患 → **管理方视角** |
| **分管领导** | 审批重大事项 / 签发应急预案 → **决策方视角** |
| **维保单位** | 接单维修 / 上传过程证据 → **协作方视角** |
| **政府监管方(应急局)** | 接收挂牌 / 下发整改通知 / 验收摘牌 → **监管方视角** |

**📌 手册中要分角色写**,**不要**把所有人混在一起。

## 第六章 流程编排避坑指南(管理员必读)

### 6.1 不要做的事(反模式)

| ❌ 反模式 | 后果 | ✅ 正确做法 |
|----------|------|-----------|
| 一个"大而全"的安全流程 | 节点臃肿,所有人审批,效率极低 | 按业务细分(隐患 / 应急 / 维修 / 演练分 4 个流程)|
| 审批人写"张三"具体人名 | 张三离职,流程断链 | 用"岗位"或"角色"配置审批人 |
| 没有"附件"字段 | 现场证据缺失,审批靠猜 | 所有现场相关流程**默认带附件字段** |
| 没有"闭环"字段 | 处置完了没记录,事后无据可查 | 每个流程必有"过程记录"+"验收证据"节点 |
| 应急流程也走标准审批链 | 领导不在,流程卡死 | 应急流程预设备用审批人 / 自动升级机制 |
| 流程不写"使用说明" | 用户选错流程,频繁驳回 | 每个流程填"流程说明"(何时用、何时不用) |

### 6.2 流程设计 Checklist

新设计一个安全类流程前,问自己:

- [ ] 这个流程的**紧急程度**?是否需要单独走应急通道?
- [ ] 审批人是否都是**岗位**而非具体人?
- [ ] 是否支持**附件上传**?(必须!)
- [ ] 是否有**闭环节点**?(过程记录 + 验收证据)
- [ ] 超时后**自动升级**机制是否配置?
- [ ] 流程说明是否写清楚(何时用)?
- [ ] 是否考虑过**三类用户视角**?(监管方 / 服务方 / 物业方)
- [ ] 是否设置了**流程时效阈值**?(配合监控预警)
- [ ] 抄送节点是否配置?(让发起人看到流程走到哪)
- [ ] 紧急 / 一般流程是否**分开配置**?

### 6.3 消防/安全场景的特殊配置建议

| 配置项 | 建议 |
|--------|------|
| 应急流程的通知方式 | 短信 + App + PC 弹窗三重 |
| 应急流程的超时升级 | 24 小时未响应自动升级上一级 |
| 现场流程的字段 | 默认含"附件"必填 |
| 维修流程的闭环 | 必须有"过程记录"+"验收证据"节点 |
| 跨单位流程 | 用"角色"配置审批人,避免单位变动断链 |
| 流程说明 | 每个流程必须填"何时用 / 何时不用" |

## 第七章 应急响应场景剧本(管理员参考)

> 应急流程建议设置几种"剧本模式",便于现场人员快速发起。

### 剧本 A:消防报警 → 应急响应

| 时点 | 动作 | 系统行为 |
|------|------|----------|
| T+0 | 报警触发 | 系统自动创建应急事件,通知值班员 |
| T+5min | 值班员上报 | 紧急流程提交,推送到 4 类人员 |
| T+15min | 现场核查 | 现场人员填报是否真实火情 |
| T+30min | 初步处置 | 上报处置措施和结果 |
| T+1h | 分管领导确认 | 流程归档或升级 |

### 剧本 B:重大隐患 → 整改 → 摘牌

| 时点 | 动作 | 系统行为 |
|------|------|----------|
| T+0 | 隐患上报 | 创建隐患单,派给整改责任人 |
| T+1d | 整改方案 | 整改责任人上传方案,审批 |
| T+7d | 整改进度 | 中期检查,系统提醒 |
| T+30d | 整改完成 | 上传前后对比照片 |
| T+30d | 摘牌验收 | 监管方验收,流程归档 |

### 剧本 C:动火作业 → 过程监管

| 时点 | 动作 | 系统行为 |
|------|------|----------|
| T-2h | 作业申请 | 提交审批,通知消防控制室 |
| T-1h | 审批通过 | 通知监护人 |
| T+0 | 作业开始 | 现场监护人拍照存档 |
| T+30min | 中期检查 | 监护人打卡,确认安全 |
| T+end | 作业结束 | 现场检查,确认无残留 |
