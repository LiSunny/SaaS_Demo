## 一、协同管理引擎是什么

**协同管理引擎** = 一套支撑"多人协作、逐级审批、可追溯可监控"的底层能力集合。所有需要"多人点头"的事——工单、审批、协同沟通——都跑在这个引擎上。


## 二、引擎的 4 类核心能力

| 类别 | 核心能力 | 引擎组件 |
|------|---------|---------|
| ① 流程编排 | 表单设计 + 节点配置 + 条件分支 + SLA 双计时 | 流程编排器 |
| ② 协同通讯 | 消息推送 + 任务待办 + 评论 @ + 抄送 | 协同通讯层 |
| ③ 三方协同 | 跨企业/跨部门协作 + 角色映射 + 数据隔离 | 三方协同层 |
| ④ 集成扩展 | Webhook + API + 单点登录 + 外部数据源 | 集成扩展层 |

> 💡 这 4 类能力不是孤立模块,通常是组合使用——例如"工单"同时用到 ①②③,"通知中心"主要用 ②④。

## 四、岗位与权限设计

### 4.1 平台岗位全景

协同管理引擎的"岗位"分为 3 层:

| 层级 | 来源 | 关系 |
|------|------|------|
| 系统级岗位(2 个) | 平台预置,所有企业自动获得 | 上游 |
| 企业级岗位(8 个) | 平台预置,企业继承后可直接用,也可新建 | 中游 |
| 流程节点岗位(18+) | 在 5 份流程模板中提炼的"流程角色" | 下游 |

### 4.2 详细说明

详见 `../../平台岗位设计.md`(组织视角,8 企业岗 + 2 系统角色 + 创建权限 + 继承规则)

**配套文档**:
- `../../协同管理/流程模板/平台通用岗位字典-流程视角.md`(18 流程角色 + 4 虚拟角色 + 流程×岗位矩阵)

### 4.3 协同管理引擎的"岗位使用规范"

1. **按职责选,不按人选**:配置流程节点时,选的是"消防安全管理人"而非"张三"
2. **跨流程复用**:同一岗位(如"消防安全管理人")在多个流程中使用时,配置一次即可
3. **虚拟角色与岗位分离**:虚拟角色(如"评估委员会")用于跨部门/跨人选场景
4. **"申请人"用全员即可**:不要单独建"申请人"岗位

## 五、流程模板配置

> **本节是核心完整内容**,完整保留自原《模板配置指南》§二-§八 全文。所有流程模板的"使用方式"、"操作步骤"、"原则"、"FAQ"都在这里。

### 5.1 三种使用方式

#### 5.1.1 为什么有 3 种方式?

平台预置了 5+ 个常用模板(消防/安全/通用审批),但**每个企业的组织架构、审批习惯不完全一样**。所以平台提供 3 种使用方式,在"开箱即用"和"个性化定制"之间取得平衡。

#### 5.1.2 三种方式对比

| 维度 | A. 系统预置 | B. 克隆预置自定义 | C. 完全自定义 |
|------|------------|------------------|--------------|
| 上手成本 | **最低**(配岗位即可) | 中(克隆+改) | 高(从零设计) |
| 灵活度 | 低(不能改) | **高(改字段/节点/SLA)** | 最高 |
| 平台升级跟随 | ✅ **自动** | ⚠️ 需手动合并 | ❌ 不跟随 |
| 适用场景 | 标准化业务,模板够用 | **通用业务,小幅调整**(★ 推荐) | 特殊业务,平台模板不适配 |
| 谁会操作 | 流程管理员(仅配岗位) | 流程管理员 | 流程管理员(资深) |

#### 5.1.3 决策树:该用哪种?

```
开始
  │
  ├─ 平台预置模板能直接满足需求?
  │     │
  │     ├─ 是 → 方式 A:系统预置
  │     │
  │     └─ 否 → 想小幅调整(字段/节点/SLA)
  │           │
  │           ├─ 是 → 方式 B:克隆预置自定义(★ 推荐)
  │           │
  │           └─ 否 → 平台模板完全不适配
  │                 │
  │                 └─ 方式 C:完全自定义
```

### 5.3 方式 A:启用系统预置模板

#### 5.3.1 适用场景

- 平台预置模板的字段、节点、SLA 满足本企业需求
- 不想投入配置成本,快速用起来
- 适合"先跑通、后优化"的策略

#### 5.3.2 操作步骤

**第 1 步:把人员关联到对应岗位**(必须)

每个流程节点的"处理人"在平台预置时是岗位(如"消防安全管理人"),不是具体人。**不关联到岗位,流程跑不起来**。

```
例:启用"火灾隐患排查上报"模板前
├── 部门安全员岗位 → 关联到本企业的张三人、李四人
├── 消防安全管理人岗位 → 关联到本企业的王五
├── 整改责任人岗位 → 关联到本企业的赵六(注:此岗位通常由发起人在表单中指定)
└── 验收岗位 → 关联到本企业的钱七(部门负责人)
```

**配置入口**:协同管理 → 岗位管理 → 选择岗位 → 添加成员

**第 2 步:启用流程**

协同管理 → 流程编排 → 找到目标模板 → 点"启用"

**第 3 步:测试运行**(自测一次)

用测试账号模拟一个完整流程:
1. 发起人在"我的发起"看到该模板
2. 填表提交
3. 各节点处理人在"待办任务"中收到待办
4. 流程流转 → 关闭
5. 检查每个节点的"处理人"是否正确解析到具体人

**第 4 步:通知员工使用**

- 在企业内通知公告里发一条"工单系统已上线"
- 培训关键角色(发起人/审批人)如何操作

#### 5.3.3 此方式的优势与局限

✅ 优势:上手快、平台升级自动跟随、零配置成本
❌ 局限:不能改任何字段和节点,遇到企业特殊需求(如"金额≥5000 需分管领导审批")就无法满足

### 5.4 方式 B:克隆预置并自定义(★ 推荐)

#### 5.4.1 适用场景

- 平台预置模板接近需求,但需要小幅调整
- 典型调整:加 1 个字段、改 1 个节点的审批人、调 SLA 时限、添加条件分支

#### 5.4.2 操作步骤

**第 1 步:克隆预置模板**

协同管理 → 流程编排 → 找到目标模板 → 点"克隆" → 系统生成新模板

> 克隆后,新模板会**标记父模板 ID**,后续平台升级父模板时,系统会提示你"是否合并变更"。

**第 2 步:修改新模板(按需)**

可改的东西:
- ✅ **基础信息**:模板名称(建议带企业前缀,如"XX 公司-火灾隐患排查")、工单说明
- ✅ **表单字段**:增加字段(常见如"联系方式""项目编号")、修改占位文本、调整必填
- ✅ **流程节点**:增删节点、改节点的审批人(从某岗位改为另一岗位)、添加条件分支
- ✅ **SLA**:调整各优先级的响应/解决时限
- ❌ 不能改:平台预置的关键业务规则(如 SLA 双计时机制本身)

**第 3 步:测试**

同方式 A 的测试流程。建议至少测 2 个分支(正常通过 + 条件分支触发)。

**第 4 步:发布**

点"保存并启用",模板正式生效。原预置模板不受影响。

#### 5.4.3 命名规范建议

```
格式:[企业简称]-[业务类型]-[版本号]

示例:
- XX物业-火灾隐患排查-v1.0
- XX物业-动火作业-v1.0
- YY工厂-请假申请-v1.0
```

避免命名:"流程1"、"测试"、"消防"(太通用,后期难找)

#### 5.4.4 此方式的关键决策:克隆 vs 直接改

| 决策点 | 直接改预置模板 | 克隆后改 |
|--------|--------------|---------|
| 是否影响其他企业 | ❌ 平台预置不能改 | ✅ 只影响本企业 |
| 平台升级时 | 不存在(没改) | 提示合并父模板变更 |
| 推荐度 | ❌ 不允许 | ✅ 推荐 |

> 重要提醒:**平台预置模板不允许修改**,所有自定义必须通过克隆实现。

### 5.5 方式 C:完全自定义

#### 5.5.1 适用场景

只有以下情况才需要完全自定义:

1. 平台预置没有此类业务(如企业有"特种设备年检申请"这类专项流程)
2. 平台预置的字段/节点完全不适配(如需要 5 级审批、会签规则很复杂)
3. 企业有合规要求(如必须保留某种特定表单结构)

#### 5.5.2 操作步骤

**第 1 步:创建空白模板**

协同管理 → 流程编排 → 点"新建" → 选"空白模板"(而非"从预置克隆")

**第 2 步:配置基础信息**

- 模板名称(按 5.4.3 命名规范)
- 工单说明(写清适用场景)
- 谁可发起(全员 / 限定岗位 / 限定角色)

**第 3 步:设计表单**

拖入组件 → 配置字段 → 验证规则

**第 4 步:设计流程**

添加节点 → 配置处理人 → 连线 → 配置条件分支

**第 5 步:配置 SLA**

按优先级设定响应/解决时限

**第 6 步:测试 + 发布**

> ⚠️ **强烈建议**:在"测试环境"或"草稿状态"完成至少 3 次完整流程测试后,再发布到生产。

#### 5.5.3 完全自定义的成本评估

| 项目 | 预计工时 |
|------|---------|
| 简单流程(3-5 节点) | 4-8 小时 |
| 中等流程(6-9 节点) | 1-2 天 |
| 复杂流程(10+ 节点,含条件分支、会签、子流程) | 3-5 天 |

**决策建议**:能用方式 B 解决的,**别用方式 C**。

### 5.6 配置流程的 5 条原则

#### 5.6.1 节点数控制在 3-9 个

- 太短(<3):失去审核意义
- 太长(>9):拖慢效率,容易卡单
- 经验值:5-7 个节点覆盖 80% 场景

#### 5.6.2 按岗位选人,不按人选人

✅ 推荐:`消防安全管理人`(岗位) → 系统自动找到当前担任该岗位的人
❌ 反例:`张经理`(具体人) → 张经理离职后流程断链

例外:必须按人选的场景(如"必须由王五亲自审批"),用临时指派或加签功能。

#### 5.6.3 必填字段精简

- **必填字段只放"审批必要信息"**:位置、类型、描述、照片
- **辅助信息放选填**:备注、附加说明
- 经验:必填字段 ≤ 8 个,再多就劝退了

#### 5.6.4 SLA 按优先级分级

至少分 4 档(紧急/高/普通/低),每档独立的响应/解决时限。

| 优先级 | 典型响应时限 | 典型解决时限 |
|--------|-------------|-------------|
| 紧急 | 15-30 分钟 | 24 小时 |
| 高 | 1-2 小时 | 3 天 |
| 普通 | 2-4 小时 | 7 天 |
| 低 | 4-8 小时 | 14 天 |

#### 5.6.5 重要流程必须设抄送

- 抄送发起人 → 让他能看到进度,不用反复问
- 抄送发起人上级 → 让他知情,避免失察
- 抄送相关部门 → 跨部门协同场景

### 5.7 流程模板 FAQ

#### Q1:流程被驳回了,能看到驳回原因吗?

✅ 可以。在"我的发起"中找到该单,看"审批记录"中的驳回意见。

#### Q2:我审批错了,能撤回吗?

❌ 不能直接撤回。可走"补充说明"或在流程中"加签"补审;若流程严重错误,联系平台管理员走"流程干预"。

#### Q3:克隆的流程,平台升级时怎么处理?

⚠️ 平台升级预置模板后,会提示"父模板已更新"。**系统不会自动合并**,需管理员手动评估:
- 若变更不影响你 → 忽略
- 若变更想采纳 → 手动迁移变更(目前无一键合并)

#### Q4:一个员工可以关联多个岗位吗?

✅ 可以。比如张三是"消防安全管理人",同时是"动火监护员",可以同时关联两个岗位。

#### Q5:流程可以临时换人吗?

✅ 可以,使用"转办"功能(把待办转给其他人)或"加签"功能(增加审批人)。

#### Q6:模板能恢复成系统预置的吗?

⚠️ 方式 A(预置未改):停用即可
⚠️ 方式 B(克隆版):停用并启用原预置即可
❌ 方式 C(完全自定义):没有"恢复"概念,只能重新创建一个

#### Q7:不同企业可以用同一份模板吗?

⚠️ 不能。每个企业(租户)有独立的模板空间。系统预置模板是"出厂预装",所有企业都能用,但克隆和自定义版本只在当前企业生效。

#### Q8:克隆后,平台升级把原模板删了,我的克隆版会受影响吗?

✅ 不会。克隆版是独立副本,父模板删除不影响子模板运行。但**升级带来的新功能无法同步**(参考 Q3)。

## 八、最佳实践与 FAQ

### 8.1 跨模块最佳实践

1. **岗位先行**:任何配置前先确认岗位体系(详见 §四)
2. **流程从简**:能用方式 A 解决的不用 B,能用 B 的不用 C(详见 §5.1.3 决策树)
3. **必填精简**:表单设计原则(详见 §5.6.3)
4. **测试必做**:每个新模板至少 3 次完整流程测试后再发布
5. **权限最小**:流程节点授权时,只给必要岗位

### 8.2 跨模块 FAQ

#### Q1:协同管理引擎和 AI 助手能不能联动?

✅ 可以。AI 助手可调用流程数据(如发起工单、查询待办),也可被流程节点调用(如 AI 自动分配处理人)。详见 AI 助手独立文档。

#### Q2:数据字典和岗位字典有什么区别?

- **数据字典**:业务实体(单位、设备类型、隐患类型),存于 `src/data/` 或外部 API
- **岗位字典**:组织岗位(消防安全管理人、部门负责人),存于用户管理 → 岗位管理

#### Q3:多个企业能用同一套配置吗?

⚠️ 系统预置模板所有企业共享,但每个企业的"克隆/自定义版本"独立。如需批量复制,目前需要手动操作(规划中:模板市场)。

#### Q4:流程节点能调用外部系统吗?

✅ 可以。通过 Webhook 或自定义节点,可调用任意 HTTP API。详见 §七。

#### Q5:性能瓶颈在哪里?

- 节点选人查询(岗位关联用户)
- 跨企业数据同步
- 报表聚合查询(详见 §6.5)
