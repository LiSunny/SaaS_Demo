## 第一章 模块概览

### 1.1 模块简介

协同模块是平台内置的**审批流引擎**,用于将日常业务中需要"多人协作、逐级审批"的工作(如请假、采购、报销、维修、隐患上报等)流程化、电子化、可追溯。

所有需要"多人点头"的事,都在这里处理。

### 1.2 模块构成

协同模块包含 **2 个一级菜单 + 5 个子模块**:

| 一级菜单 | 子模块 | 视角 | 典型用户 |
|---------|--------|------|----------|
| **协同管理** | 流程编排 | 管理员视角(配置) | 系统管理员、流程配置员 |
| | 协同监控 | 管理员视角(运维) | 系统管理员、部门负责人 |
| **协同工作** | 待办事项 | 用户视角(待办) | 所有用户 |
| | 已办事项 | 用户视角(历史) | 所有用户 |
| | 发起事项 | 用户视角(发起) | 所有用户 |

### 1.3 谁应该读这份手册

| 你的角色 | 重点阅读章节 |
|---------|------------|
| 系统管理员 / 流程配置员 | 第二章 协同管理 + 第四章 跨模块最佳实践 |
| 部门负责人 / 分管领导 | 第三章 协同工作 + 第四章 跨模块最佳实践 |
| 普通业务用户 | 第三章 协同工作 |
| 维保 / 协作单位人员 | 第三章 协同工作 |

### 1.4 阅读路径建议

- **新用户**:按章节顺序读完,预计 20 分钟
- **老用户**:直接定位到对应子模块章节
- **管理员**:重点看"流程编排"与"协同监控",以及"跨模块最佳实践"

## 第二章 协同管理(管理员视角)

### 2.1 流程编排

#### 2.1.1 是什么

**流程编排**是设计"审批模板"的地方。可以理解为:这里创建的每一个流程,都是一张"审批单"的样式。后续用户在"协同工作 → 发起事项"里看到的发起表单,都来自这里。

#### 2.1.2 谁会用

- **系统管理员 / 流程配置员**:设计、维护流程模板
- **部门负责人**:通常需要管理员权限才能配置本部门流程

#### 2.1.3 典型使用场景

> 通用场景示例。具体到消防/安全场景的详细示例请参见[专题文档](./协同模块使用手册-消防与安全专题.md)。

| 场景 | 流程名称示例 | 审批节点 |
|------|------------|----------|
| 请假 / 出差 | 请假申请流程 | 申请人 → 部门负责人 → 分管领导 |
| 报销 | 费用报销流程 | 申请人 → 部门负责人 → 财务 → 分管领导 |
| 采购 | 物资采购审批流程 | 申请人 → 部门负责人 → 采购 → 财务 → 领导 |
| 用车 | 公务用车审批流程 | 申请人 → 部门负责人 → 车队管理员 → 分管领导 |
| 用印 | 公章使用申请流程 | 申请人 → 部门负责人 → 办公室 → 分管领导 |
| 维修 | 设备维修审批流程 | 申请人 → 部门负责人 → 设备管理员 → 财务 |

#### 2.1.4 流程编排最佳实践

**1. 流程命名规范化**

- 使用统一前缀:`XX-业务类型-版本`,如 `[行政]-请假申请-v1.0`
- 名称要一看就懂业务,**不要**写"流程1"、"测试流程"
- 同一类业务只维护一个流程,**避免**重复流程

**2. 节点设计原则**

- **节点数控制在 3-6 个**:太短失去审核意义,太长拖慢效率
- **每节点只做一件事**:审批、签字、知会(抄送)**分开建节点**
- **必经节点写明条件**:如"金额 ≥ 5000 元需分管领导审批",用条件分支而非硬塞节点
- **必须设置结束节点**:避免流程卡住无人收尾

**3. 审批人配置原则**

- **优先按"岗位"选人**,而不是按具体人——岗位稳定,人流动
- **分管领导节点**用"角色"配置,不要写"张三"(除非岗位无对应)
- **会签节点**(多部门意见)单独建,不要和审批节点混在一起
- **抄送节点不要漏**——让发起人能看到流程走到哪了

**4. 字段设计原则**

- **必填字段尽量少**(只放审批必要信息)
- **金额、日期**用专用控件,不要用普通文本框
- **附件字段保留**——给用户提供上传佐证材料的位置
- **业务字段命名要让用户看懂**(如"用车时间"而非"datetime")

**5. 版本管理**

- 流程上线后**不要直接修改正在使用的版本**
- 改流程 → 新建 v2 版本,灰度上线(几个部门先试)→ 全量替换

#### 2.1.5 常见错误

- ❌ 把所有业务都做成"一个大而全的流程",导致节点臃肿、谁都要审批
- ❌ 审批人写具体人名,人员变动后流程断链
- ❌ 没有抄送节点,发起人反复来问"我那个申请到哪了"
- ❌ 流程上线后频繁改字段,历史数据错乱

### 2.2 协同监控

#### 2.2.1 是什么

流程"上线后"的全局运行仪表盘。**看所有流程跑得怎么样**——谁卡住了、谁超时了、谁驳回了。

#### 2.2.2 谁会用

- **系统管理员**:排查流程问题
- **部门负责人 / 分管领导**:看本部门流程执行情况

#### 2.2.3 典型使用场景

| 场景 | 看什么 | 怎么用 |
|------|--------|--------|
| 例行检查(每天/每周) | 待办积压、超时流程 | 发现问题流程,催办或修复 |
| 流程卡住 | 单据停留在某节点超过 X 小时 | 找到卡单人,直接沟通或代为处理 |
| 月度复盘 | 各流程平均耗时、驳回率 | 评估流程是否合理,优化节点 |
| 审计前 | 历史流程数据导出 | 导出给审计部门 |

#### 2.2.4 协同监控最佳实践

**1. 设定"超时常识"**

- 普通审批:超过 **24 小时** = 黄灯预警
- 领导审批:超过 **48 小时** = 黄灯预警
- 紧急流程:超过 **4 小时** = 红灯
- 在系统里配阈值,**不要**靠人脑记

**2. 每日 5 分钟巡检**

- 早上打开监控页,**只看 3 个数字**:今日新增 / 进行中 / 超时
- 超时 > 5 条才需要介入,**不要**逐条看

**3. 按"业务类型"分视图**

- 监控页默认展示**所有流程**(信息过载)
- 建议用筛选条件:`流程类型 + 时间范围 + 状态`
- 每周固定看一类(如"只看采购类")

**4. 处理卡单的标准动作**

- 找到卡单人 → 微信/电话提醒
- 若卡单人休假 → 联系其上级临时指派
- **不要**在监控里直接改流程状态(留痕问题)

#### 2.2.5 常见错误

- ❌ 监控页打开就关,从不看 — 失去了监控的意义
- ❌ 只看"已办数量" — 不看耗时和驳回率,发现不了真问题
- ❌ 管理员直接在监控页改流程状态 — 应走"重新发起"或"管理员干预"专用入口

## 第三章 协同工作(业务用户视角)

### 3.1 待办事项

#### 3.1.1 是什么

**你**当前需要处理的审批 / 签字 / 查阅任务。所有需要你点头的事,都在这里。

#### 3.1.2 典型使用场景

| 场景 | 你的身份 | 你要做什么 |
|------|----------|-----------|
| 早上 9 点打开电脑 | 部门负责人 | 批量审批下属提交的请假、采购 |
| 收到新单据提醒 | 业务管理员 | 审核某类业务申请,判断是否要现场核查 |
| 处理紧急文件 | 分管领导 | 优先处理标"紧急"的事项 |
| 跨部门会签 | 多个部门负责人 | 依次在节点上签字 |

#### 3.1.3 待办处理最佳实践

**1. 每天固定 2 个时段处理待办**

- 上午 10:00、下午 15:00 各一次,**不要**被通知打断节奏
- 每次集中处理,避免反复切换任务

**2. 按"轻重缓急"排序处理**

- 🔴 紧急(系统标红)→ 立刻处理
- 🟡 超时未办 → 第二优先(可能造成业务停滞)
- 🟢 普通待办 → 按提交时间顺序

**3. 审批意见要"有用"**

- ❌ 不要只写"同意"(后人看不懂为什么同意)
- ✅ 写具体判断:`同意,金额合规,建议从安全专项预算列支`
- 需要补充材料的 → 退回并写明**退回原因**(让发起人知道怎么改)

**4. 善用"快速动作"**

- 同意 → 直接点同意按钮
- 驳回 → 写明原因再驳回
- 加签 / 转办 → 用专门的按钮,不要直接转发给别人处理

**5. 不能"只读不回"**

- 看完了不操作 → 流程会卡在这里
- 不属于你处理 → 用**转办**功能转给正确的人(不是退给发起人)

#### 3.1.4 常见错误

- ❌ 同意 / 驳回之前不看附件 → 容易出现"瞎批"
- ❌ 驳回时只点按钮不写原因 → 发起人反复来问,效率低
- ❌ 把待办拖到最后一刻 → 流程超时,影响业务
- ❌ 自己不该处理的单子 → 退回给发起人让他重发(应**转办**给正确的人)

---

### 3.2 已办事项

#### 3.2.1 是什么

**你**已经处理完的历史单据。用于"事后查询 / 证明 / 复盘"。

#### 3.2.2 典型使用场景

| 场景 | 怎么用 |
|------|--------|
| 半年后问"我那个采购批了吗" | 在已办里搜,看当时的审批意见 |
| 月底做工作汇报 | 导出本月已办清单 |
| 有人来问"我报的那个事儿处理得怎样" | 看从你这里审批后流转到了谁 |
| 审计 / 巡察 | 导出一段时间内的已办数据 |

#### 3.2.3 已办查询最佳实践

**1. 养成"留痕"习惯**

- 重要事项的审批意见写完整(谁看了都懂)
- 不是你的单子 → 也认真写一句"已转 XX 处理"

**2. 善用筛选**

- **时间范围** + **流程类型** + **审批结果(同意/驳回)** 三件套
- 找具体单子 → 用关键字搜索(单号 / 标题)

**3. 定期导出归档**

- 个人工作记录,建议**每月导出一次**到本地
- 系统数据保留期有限,关键事项自己留底

---

### 3.3 发起事项

#### 3.3.1 是什么

**你**提交的申请单列表。包含:待审批中、已通过、已驳回、已撤回。

#### 3.3.2 典型使用场景

| 场景 | 你要做什么 |
|------|-----------|
| 提交申请 | 选对应流程,填单提交 |
| 自己撤回错了的单子 | 在发起列表找这条 → 撤回 |
| 跟进单子进度 | 在列表看当前节点,不用催审批人 |
| 月底盘点自己提了多少单 | 导出本月发起清单 |

#### 3.3.3 发起事项最佳实践

**1. 发起前确认选对流程**

- 流程多的时候,**先看流程说明**再选
- 选错了流程 → 容易被驳回重发,浪费时间

**2. 填单要"完整且精炼"**

- **必填项不能漏**(否则提交失败)
- **非必填但重要的字段**也建议填(如"紧急程度"、"背景说明")
- **附件能传就传**(让审批人有据可依,大幅减少被打回的概率)

**3. 学会"催办"和"撤回"**

- 单子卡了 2 天没动 → 用**催办**功能(不是反复找审批人)
- 提交后发现填错了 → **立即撤回**,不要等审批人来驳回
- 撤回后 → 修改 → 重新提交(流程版本可能变了,要核对)

**4. 关注流程状态变化**

- 通过 → 归档即可
- 驳回 → 看驳回意见 → 修改后**重新发起**(不是"原地改")
- 撤回 → 同上

#### 3.3.4 常见错误

- ❌ 标题写"申请"、"上报",审批人看到一堆分不清谁是谁
- ❌ 填一半就提交(必填项没填,审批人没法判断)
- ❌ 被驳回后原地再点"发起"(用了同一单据重新提交 → 实际是新建,历史混乱)
- ❌ 单子卡住不去催 → 等审批人想起来 → 业务停滞

## 第四章 跨模块最佳实践

### 4.1 日历式使用节奏(建议)

| 时段 | 在哪里 | 做什么 |
|------|--------|--------|
| 09:00 - 09:10 | 协同工作 → 待办 | 看今天有几条,心里有数 |
| 10:00 / 15:00 | 协同工作 → 待办 | 集中处理待办(各 30 分钟) |
| 用到的时候 | 协同工作 → 发起 | 填单发起新申请 |
| 每天 5 分钟 | 协同监控(管理员) | 巡检全局流程健康度 |
| 每周五 | 协同工作 → 已办 / 发起 | 复盘本周处理量,导出归档 |
| 每月 1 号 | 协同监控(管理员) | 复盘上月流程数据,优化流程设计 |

### 4.2 三条铁律

> 适用于所有用户,无论角色。

1. **管理员**:设计流程时考虑"最坏的使用者",字段要让最不熟的人也能填对。
2. **审批人**:看完内容再点同意——意见留痕是对自己的保护。
3. **发起人**:填单子像写邮件——**标题规范、内容完整、附件齐全**,被驳回的概率降一半。

### 4.3 跨模块协作建议

| 协作场景 | 建议做法 |
|---------|---------|
| 你发起 + 别人审批 | 在发起后主动通知对方("系统已发,请查收"),不要干等 |
| 你审批 + 别人发起 | 处理完及时反馈,不要拖到对方来催 |
| 你撤回 + 别人已签 | 撤回前先和已签人沟通,避免留下"白签"记录 |
| 你转办 + 别人接手 | 在意见栏写明转办原因,接手人才能快速理解 |

### 附录 B:常见问题 FAQ

**Q1:流程被驳回了,我能看到驳回原因吗?**

A:可以。在"协同工作 → 发起事项"中找到该单,查看"审批记录"。

**Q2:我能不能看到流程现在走到哪了?**

A:可以。在"协同工作 → 待办"或"已办"中点击单据查看流转轨迹。

**Q3:我审批错了,能撤回吗?**

A:不能直接撤回。但可以走"补充说明"或联系管理员走"流程干预"。

**Q4:我休长假,待办会不会堆积?**

A:建议休假前用"转办"功能把待办转给同事,或配置"代理审批人"。

**Q5:附件上传有大小限制吗?**

A:有,单附件一般不超过 XX MB(以系统实际限制为准)。超过请压缩或分批上传。
