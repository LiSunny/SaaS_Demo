# 报告管理模块 — 详细设计

## 1. 概述

报告管理模块处理维保服务成果的**提交与归档**。服务商在维保任务完成后创建检测/评估报告，提交给业主端查阅和下载，完成服务交付的最终闭环。

**涉及角色：** 服务商端（创建+提交）、业主端（查阅+下载）

**模块定位：**

```
维保任务完成
      │
      ▼
┌──────────────────────┐
│  系统自动生成草案      │
│  （状态：待审核）      │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  技术负责人审核报告    │
│  - 查看任务执行记录    │
│  - 填写审核意见       │
└──────────┬───────────┘
           │
     ┌─────┴─────┐
     ▼           ▼
┌────────┐  ┌────────┐
│ 合格   │  │ 不合格  │
│ 提交业主│  │ 任务打回│
└────────┘  └────────┘
```

---

## 2. 核心概念

### 2.1 什么是报告

报告是维保服务的**成果文件**，记录维保任务的执行情况和结论：

| 维度 | 说明 |
|------|------|
| 用途 | 向业主单位证明维保工作已按要求完成 |
| 形式 | MVP 阶段为简版结构化报告（非 PDF 文件），后续可扩展为完整 PDF 报告 |
| 关联 | 一个报告从维保任务生成，关联任务中的检查结果和故障记录 |

### 2.2 报告状态机

**状态定义：**

| 状态 | 含义 | 是否终态 |
|------|------|---------|
| 待审核 | 系统自动生成草案，等待技术负责人审核 | 否 |
| 已驳回 | 审核不通过，任务打回执行中重新执行 | 否 |
| 已提交 | 审核通过，业主可查阅 | 是（MVP） |

> MVP 简化：业主端无"确认签收"操作，提交即完成。

**状态流转图：**

```
维保任务完成 → 自动生成草案 → 待审核 → 提交 → 已提交
                              ↘ 驳回 → 任务打回执行中
```

## 3. 业务规则

### 3.1 报告包含的信息

| 信息类别 | 字段 | 必填 | 数据来源 | 说明 |
|---------|------|------|---------|------|
| **基本信息** | 报告编号 | 系统自动生成 | 规则生成 | 格式：`BG-YYYYMMDD-NNNN` |
| | 报告名称 | 系统自动生成 | 任务名称 | `{计划名称}_维保报告`，可手动修改 |
| | 所属企业（业主） | 自动带出 | `task.enterprise` | 从关联任务继承 |
| | 关联任务 | 自动带出 | `task.id` + `task.name` | 创建报告时关联的任务 |
| | 维保公司 | 自动带出 | 当前登录企业 | — |
| | 报告类型 | 手动选择 / 自动推断 | 计划周期 | 月检报告 / 季检报告 / 年检报告 / 维保报告；自动生成时从计划 `cycle` 字段推断 |
| **结论** | 维保结论 | 人工填写 | — | 总体评价文字描述 |
| | 完成率 | 自动带出 | `task.rate` | 关联任务的完成率 |
| | 故障汇总 | 自动带出 | `task.faultReportIds` | 关联任务中上报的故障数量和状态 |
| **检查结果** | 逐台设备检查结果 | 自动带出 | `task.deviceResults` | 按系统类别分组，每台设备的结果（正常/异常）、异常描述、检查人、检查时间（详见 3.5 节数据映射） |
| **审核信息** | 审核人 | 自动记录 | 技术负责人 | 点击提交的操作人 |
| | 审核时间 | 自动记录 | 系统时间 | 审核的时刻 |
| | 审核结论 | 人工选择 | — | 合格 / 不合格 |
| | 审核意见 | 人工填写 | — | 技术负责人填写的审核意见 |
| **提交信息** | 提交人 | 自动记录 | 操作人 | 点击提交的操作人 |
| | 提交时间 | 自动记录 | 系统时间 | 提交的时刻 |

### 3.2 报告编号规则

**格式：** `BG-YYYYMMDD-NNNN`

| 段 | 含义 | 示例 |
|---|------|------|
| `BG` | 固定前缀 | BG |
| `YYYYMMDD` | 创建日期 | 20260518 |
| `NNNN` | 当日自增，从 0001 起 | 0001 |

### 3.3 报告生成方式

报告采用**自动生成草案 + 手动提交**的方式：

| 步骤 | 说明 |
|------|------|
| 1. 自动生成 | 维保任务完成后，系统自动创建一份报告草案（状态为"草稿"），继承任务名称、所属企业、检查结果等基本信息 |
| 2. 补充结论 | 服务商在报告列表中找到该草案，点击"编辑"填写维保结论和备注 |
| 3. 手动提交 | 服务商点击"提交"，报告状态变为"已提交"，推送至业主端可查阅 |

**自动生成的规则：**

| 条件 | 说明 |
|------|------|
| 前置条件 | 维保任务状态为"已完成" |
| 报告与任务的关系 | 一个已完成的任务自动生成一份报告；一份报告仅关联一个任务 |
| 重复生成 | 同一任务不会重复生成（已有报告的任务不再自动创建） |
| 报告名称 | 自动生成，格式同 3.1 节 |
| 初始状态 | 待审核，等待技术负责人确认 |

**手动创建作为兜底：**
- 保留手动"创建报告"入口，用于需要手动创建报告的场景（如补录历史数据）
- 手动创建同样需选择已完成的任务，同一任务不可重复创建

### 3.4 Demo MVP 简化规则

| 简化项 | 处理方式 |
|--------|---------|
| 报告格式 | MVP 为网页版结构化报告，已支持 PDF 导出（html2pdf.js 实现）。PDF 文件名格式：`{报告名称}_{报告编号}.pdf` |
| 业主签收 | MVP 不实现业主"确认签收"操作，提交即视为送达 |
| 多任务汇总报告 | MVP 仅支持单任务生成报告，不支持多个任务汇总到一份报告 |

### 3.5 任务数据 → 报告数据映射

报告的核心内容（检查结果、故障汇总、完成率）全部来自任务执行数据，无需重复录入。

```
任务数据                            →  报告章节
─────────────────────────────────────────────────────
task.name                          →  关联任务名称
task.enterprise                    →  所属企业
task.planId → plan.name           →  关联计划
task.planId → plan.cycle          →  报告类型（月检/季检/年检）
task.staff                         →  执行人
task.rate                          →  完成率
task.signinTime / completeTime     →  报告正文"本次维保日期"
task.deviceResults                 →  报告"检查结果"章节（设备级逐项）
task.faultReportIds → FAULT_LIST  →  报告"本次不合格项" + "故障汇总"
task.reportDraftId                 →  关联的报告草案 ID
```

**deviceResults → 报告"检查结果"映射：**

| 报告展示 | 数据来源 |
|---------|---------|
| 系统类别分组 | `LEDGER_ITEMS[code].sys` |
| 设备编码 | `deviceResults` 的 key（设备编码） |
| 设备类型 | `LEDGER_ITEMS[code].name` |
| 安装地点 | `LEDGER_ITEMS[code].loc` |
| 检查结果 | `deviceResults[code].result`（正常/异常） |
| 异常描述 | `deviceResults[code].faultDesc` |
| 检查人 | `deviceResults[code].checkedBy` |
| 检查时间 | `deviceResults[code].checkedAt` |

> **设计参考**：上述数据结构能够支撑生成北京市标准《建筑消防设施维护保养报告书》中"详细记录"章节（P6-P20）的核心内容。标准报告中要求的"检查方法和要求"文本、"实测数量"、"测量值"等补充信息，可在后续 M10 维保标准库完善后关联补全，不影响当前数据采集设计。

**规则：**
- 纯只读视角，无任何写操作入口
- 列：报告编号、报告名称、维保公司、提交时间、类型、操作（查看/下载）
- 报告详情内容与服务商端一致
- 点击「下载」触发浏览器下载（MVP 下载网页版内容）
- 空状态：「暂无维保报告」

## 5. 数据联动关系

### 5.1 与其它模块的联动

```
维保任务 ──任务完成────→ 自动创建报告草案（状态：待审核）
         任务已完成────→ "创建报告"操作入口在任务详情页展示

报告 ──审核合格──────→ 状态变为"已提交"，推送给业主端
    ──审核不合格────→ 任务打回"执行中"，维保人员需重新执行

待办工作台 ──待审核报告──→ 待审核状态的报告在待办中展示（技术负责人待办）
            报告已提交──→ 移出待办列表
```

### 5.2 联动规则矩阵

| 触发动作 | 影响范围 | 效果 |
|---------|---------|------|
| 任务完成 | 报告创建 | 自动创建报告草案（状态：待审核） |
|  | 待办工作台 | 新增一条"待审核报告"待办（技术负责人视角） |
| 任务已创建报告 | 报告创建入口 | 该任务不可再选择（防止重复） |
| 审核合格 → 提交 | 报告状态 | 待审核 → 已提交 |
|  | 关联任务 | 状态保持"已完成" |
|  | 业主端报告列表 | 即时出现该报告 |
|  | 待办工作台 | 移除该待办 |
| 审核不合格 → 驳回 | 报告状态 | 待审核 → 已驳回 |
|  | 关联任务 | 已完成 → 执行中（打回重新执行） |
|  | 待办工作台 | 任务重新出现在维保人员待办中 |
| 驳回后重新执行完成 | 报告状态 | 已驳回 → 待审核（重新审核） |
| 删除报告（待审核/已驳回） | 关联任务 | 解除关联，任务可重新生成报告 |
| 提交报告（已提交） | 报告状态 | 不可修改，业主端只读 |

## 6. 业务边界场景

| 场景 | 处理方式 |
|------|---------|
| **无可完成的任务** | 创建报告时任务下拉为空，提示"暂无已完成的任务，请先执行维保任务" |
| **创建报告后任务被删除** | 报告保留，关联任务信息快照不受影响 |
| **提交后想修改报告** | 已提交不可修改。如需修改可创建新报告（关联同一任务需特殊处理——MVP 暂不支持重新创建） |
| **草稿状态删除** | 允许删除，弹窗确认「确认删除此报告草稿？」 |
| **报告列表为空** | 展示「暂无报告。维保任务完成后，可创建并提交维保报告」 |
| **业主下载报告** | MVP 下载为网页版（HTML），后续可扩展为 PDF |
