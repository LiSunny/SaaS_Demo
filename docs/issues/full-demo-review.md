## 业务逻辑走查

### P0 阻塞问题

1. **企业名称含乱码后缀 "3"**  
   - 位置：Mock 数据 `MOCK_ENTERPRISES[0]` 名称为 "尼特智能科技股份有限公司**3**"  
   - 影响：所有引用该企业的地方（合同列表、台账列表、计划列表、企业详情等）都显示错误名称  
   - 建议：去掉多余的 "3"

2. **服务商端顶部栏显示乱码 "ntznkjgfyxgs3"**  
   - 位置：第 800 行  
   - 影响：用户第一眼看到的是乱码，严重损害专业感  
   - 建议：替换为服务商企业名称 "尼特消防维保公司"

3. **服务商端待办工作台完全为空**  
   - 位置：`page-sp-todo`  
   - 问题：页面上无任何内容（非空态提示，而是完全空白），核心入口不可用  
   - 建议：至少显示一个带数据的空态提示，或展示当前待办统计

4. **台账检查项列表为静态 HTML 而非动态渲染**  
   - 位置：`page-sp-ledger` 表格行  
   - 问题：编辑/删除/详情链接均无绑定 JS 事件，点击无响应；新增检查项保存后不刷新表格  
   - 建议：将表格行改为 JS 动态渲染，新增/编辑/删除后刷新数据

5. **合同状态机缺少创建后初始状态** ✅ 已处理（见决策 #1）  
   - 问题：新建合同后状态机从"待确认"开始，但创建操作是服务商端主动发起的，"业主确认/作废"由业主端操作。spActions 中"待确认"状态无任何操作按钮，导致服务商创建合同后在该合同上无后续操作入口  
   - 决策：服务商在"待确认"状态下可编辑合同内容（业主单位、期限、负责人等），编辑后保留同一编号和状态  
   - 影响范围：`biz-design.md` 添加业务规则#6、更新状态流转图；`03-合同管理模块详细设计.md` 更新操作表和流转图；Demo 添加"编辑"操作入口

### P1 体验问题

6. **台账新增抽屉中 "所属企业" 选择为空**  
   - 位置：`sp-ledger-drawer`  
   - 问题：表单包含 "所属企业" 字段，但未关联实际数据（服务商可能管理多个业主），新增的检查项不知道该归属哪个企业  
   - 建议：新增关联企业下拉选择

7. **台账区域视图无数据**  
   - 位置：`ledger-area-view`  
   - 问题：选中区域后右侧显示"选择左侧区域查看该区域的检查项"，无任何实际数据  
   - 建议：Mock 几组区域数据并关联检查项

8. **任务执行页签到无交互**  
   - 位置：`sp-task-execute`  
   - 问题：签到按钮为静态 badge，"签到"按钮调用 alert 但无实际签到记录  
   - 建议：点击签到后更新状态为已签到，显示签到时间

9. **任务执行页检查项为硬编码**  
   - 位置：`sp-task-execute`  
   - 问题：8 个检查项为静态 HTML，未从计划/台账继承（业务规则要求分值快照不可修改）  
   - 建议：使用 JS 渲染，展示从计划继承的检查项和分值

10. **故障详情弹窗中维修按钮仅弹 alert**  
    - 位置：`sp-fault-detail-modal` / `ow-fault-detail-modal`  
    - 问题：无法实际推进维修状态（待维修→维修中→已完成）

11. **报告管理无创建和提交入口**  
    - 位置：`sp-reports`

## 用户体验评估

### 做得好的

- **企业关联弹窗**：搜索 + 选择 + 无结果自动新建 + 重复校验，流程完整，反馈明确
- **维保计划创建**：自动命名 + 台账项选择 + 分值汇总 + 人员分配，一气呵成
- **计划状态流转按钮**：按不同状态动态显示可用操作，用户不会看到不可用的按钮
- **18 类分类体系参考弹窗**：内容详实专业，展示了团队对消防维保领域的理解
- **台账标签配色**：状态标签（待确认/已签订/已启用）用色清晰一致
- **业主端合同确认流程**：服务商和业主端操作按钮分离，符合业务设计

### 需要改进的

- **顶部栏乱码**：最显眼的位置展示乱码，降低专业可信度
- **待办页空白**：作为默认首页完全无内容，用户进入后无所适从
- **静态数据过多**：台账/任务/报告列表为静态 HTML，无法演示 CRUD 和数据联动
- **交互反馈单一**：几乎所有操作反馈都是 `alert()`，演示场景显得粗糙
- **空态/缺省态缺失**：大部分页面无数据时展示空白，而非引导性空态提示
