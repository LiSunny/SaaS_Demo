# 工单监控 产品需求文档

> 版本：v1.0 | 日期：2026-06-01 | 状态：草稿

## 1. 背景与目标

### 1.1 业务背景

本平台已实现流程模板编排功能（`/workflow/template`），允许管理员定义工单模板（节点、字段、流转规则、SLA 配置）。模板发布后，业务人员按模板创建流程实例——即"工单"。工单监控模块是流程引擎的**运行时管控中心**，让平台运营方和服务商管理层能够实时掌握所有进行中的工单状态，及时发现 SLA 超时风险并干预。

当前项目中"工单监控"侧边栏菜单为占位符，点击后跳转到模板列表页，缺少真正的工单监控能力。

### 1.2 模块目标

- **用户目标**：运营管理员能在一页内查看所有工单实例的运行状态，快速定位超时、卡单等异常，并执行必要的干预操作
- **业务目标**：保障工单 SLA 达标率 ≥ 95%，异常工单 5 分钟内被发现

### 1.3 适用范围

| 角色 | 可见范围 | 可执行操作 |
|------|---------|-----------|
| 平台运营方 | 全平台工单 | 查看全部、手动取消、强制改派 |
| 服务商管理员 | 本企业相关的工单 | 查看、内部改派 |
| 服务商执行人 | 分配给自己或本企业公海池的工单 | 查看 |
| 业主单位 | 本企业发起的工单 | 查看进度 |

#### 功能 3：SLA 三色预警

**用户故事**：作为平台运营方，我希望在列表中直观看到每个工单的 SLA 状态，以便优先处理即将超时或已超时的工单。

**SLA 状态定义**：

| 状态 | 颜色 | 条件 | 含义 |
|------|------|------|------|
| 正常 | 🟢 绿色 `#52C41A` | 进度 < 80% | 时间充裕 |
| 预警 | 🟡 黄色 `#FAAD14` | 80% ≤ 进度 < 100% | 即将超时，需关注 |
| 超时 | 🔴 红色 `#FF4D4F` | 进度 ≥ 100% | 已超时，需立即处理 |

> **进度计算**：`进度 = 已用时间 / SLA时限 × 100%`
>
> 有指派节点的工单：TTR（任务到达→接单）+ TTS（接单→关闭）
>
> 无指派节点的工单：仅 TTS（任务到达→关闭），TTS 起点下沉为执行节点到达

**展示方式**：
- 列表"SLA 状态"列展示三色圆点 + 剩余时间文案（如"剩余 1h23m"、"已超时 15m"）
- 超时行添加浅红色背景高亮

**交互说明**：
1. 鼠标悬浮 SLA 状态列时，Tooltip 展示详细 SLA 信息（TTR/TTS 各自进度、时限值、黄灯阈值）
2. 超时工单自动置顶

**业务规则**：
- 草稿和已关闭状态的工单不展示 SLA 状态（显示"—"）
- 驳回不重置 TTS，TTS 继续累计
- 转单不重置 TTS，TTS 继续累计

**验收标准（AC）**：
- [ ] AC8：SLA 状态根据 Mock 数据的进度值正确展示绿/黄/红
- [ ] AC9：超时工单行有红色背景高亮
- [ ] AC10：草稿和已关闭状态的工单 SLA 列显示"—"

#### 功能 5：操作干预（P1）

**用户故事**：作为平台运营方，当发现工单异常（卡单、处理人离职等），我希望能够手动取消工单或强制改派处理人，以便保障业务连续性。

**5.1 取消工单**
- 触发条件：工单非"已关闭"状态，且当前用户为平台运营方
- 交互流程：
  1. 点击"取消工单"按钮
  2. 弹出确认对话框，提示"确认取消工单 WOxxx？取消后工单将进入已关闭状态，且不触发归档回调。"
  3. 必填取消原因（文本域，最多 200 字）
  4. 确认 → 调用取消接口 → 刷新列表

**5.2 强制改派**
- 触发条件：工单处于"进行中"状态，且当前用户为平台运营方
- 交互流程：
  1. 点击"强制改派"按钮
  2. 弹出人员选择器，限定本企业人员或关联企业联系人
  3. 选择目标处理人 → 确认 → 调用改派接口 → 刷新详情
  4. SLA 继续累计，不重置

**业务规则**：
- 取消和改派操作均记录到操作日志，含操作人、时间、原因
- 已关闭工单不可取消

**验收标准（AC）**：
- [ ] AC15：取消工单需要二次确认 + 填写原因，确认后列表状态更新
- [ ] AC16：强制改派后当前处理人更新，SLA 继续计时

## 3. 数据结构

### 3.1 核心实体

```json
{
  "WorkOrderInstance": {
    "id": "number | 主键",
    "orderNo": "string | 工单编号，如 WO20260601-001",
    "templateId": "number | 关联模板 ID",
    "templateName": "string | 模板名称（冗余）",
    "templateVersion": "number | 模板版本号",
    "status": "enum | 实例状态：draft / active / closed",
    "priority": "enum | 优先级：urgent / high / normal / low",
    "currentNodeId": "number | 当前节点 ID",
    "currentNodeName": "string | 当前节点名称",
    "currentNodeIndex": "number | 当前节点序号（从 1 开始）",
    "totalNodes": "number | 流程节点总数",
    "currentNodeType": "enum | 当前节点类型：start / assign / execute / confirm / close / custom",
    "currentAssigneeId": "number | null | 当前处理人 ID",
    "currentAssigneeName": "string | null | 当前处理人姓名",
    "creatorId": "number | 发起人 ID",
    "creatorName": "string | 发起人姓名",
    "creatorOrgId": "number | 发起人所属企业 ID",
    "creatorOrgName": "string | 发起人所属企业名称",
    "parentOrderId": "number | null | 父工单 ID（跨企业场景）",
    "createdAt": "datetime | 创建时间",
    "updatedAt": "datetime | 最后更新时间",
    "closedAt": "datetime | null | 关闭时间",
    "closedBy": "string | null | 关闭操作人",

    "sla": {
      "ttrMinutes": "number | null | TTR 时限（分钟），无指派节点时为 null",
      "ttsMinutes": "number | TTS 时限（分钟）",
      "ttrStartedAt": "datetime | null | TTR 开始时间",
      "ttrEndedAt": "datetime | null | TTR 结束时间（接单时间）",
      "ttsStartedAt": "datetime | TTS 开始时间",
      "ttsPausedAt": "datetime | null | TTS 暂停时间（当前为验收中时）",
      "yellowThreshold": "number | 黄灯阈值，默认 0.8",
      "ttrProgress": "number | null | TTR 进度 0-1+",
      "ttsProgress": "number | TTS 进度 0-1+",
      "slaStatus": "enum | normal / warning / timeout"
    }
  }

```

### 3.2 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `id` | number | 是 | 主键 | 自增 |
| `orderNo` | string | 是 | 工单编号 | 唯一，格式 `WO{YYYYMMDD}-{序号}` |
| `templateId` | number | 是 | 模板 ID | 外键关联模板表 |
| `status` | enum | 是 | 实例状态（详见 §3.3 状态机） | 见状态机 |
| `priority` | enum | 是 | 优先级 | urgent/high/normal/low |
| `currentNodeIndex` | number | 是 | 当前节点序号 | 从 1 开始，用于显示工单进度（如 `3/5`） |
| `totalNodes` | number | 是 | 流程节点总数 | 模板节点数量，与 `currentNodeIndex` 组合显示进度 |
| `sla.ttrMinutes` | number\|null | 否 | TTR 时限 | 无指派节点时为 null |
| `sla.ttsMinutes` | number | 是 | TTS 时限 | > 0 |
| `sla.slaStatus` | enum | 是 | SLA 状态 | 实时计算，不可存储 |

### 3.3 实例状态机

实例状态（`InstanceStatus`）简化为 3 个固定值，由节点状态计算得出，与模板配置解耦。

#### 3.3.1 状态枚举

| 值 | 中文 | 判定逻辑 | 说明 |
|----|------|---------|------|
| `draft` | 草稿 | 所有节点均为 `pending` | 实例已创建，发起人尚未提交 |
| `active` | 进行中 | 部分节点已开始但非全部完成 | 工单在流转中 |
| `closed` | 已关闭 | 所有节点均为 `completed` 或 `skipped` | 流程终结（正常关闭 / 手动取消） |

> **判定公式**：
> - `draft` = `nodes.every(n => n.status === 'pending')`
> - `closed` = `nodes.every(n => n.status === 'completed' || n.status === 'skipped')`
> - `active` = 既非 draft 也非 closed

#### 3.3.2 状态转换表

| 当前状态 | 触发动作 | 目标状态 | 说明 |
|---------|---------|---------|------|
| — | 创建实例 | `draft` | 初始状态 |
| `draft` | 提交 | `active` | 进入流转 |
| `draft` | 取消 | `closed` | 发起人操作 |
| `active` | 取消 | `closed` | 管理员操作 |
| `active` | 所有节点完成 | `closed` | 正常流转结束 |

#### 3.3.3 进行中的具体阶段：由当前节点体现

工单处于 `active` 状态时，具体处于哪个阶段不再通过独立的状态枚举区分，而是通过 **当前活跃节点的名称**（`currentNodeName`）和 **类型**（`currentNodeType`）来展示：

| 模板配置 | 进行中工单的 currentNodeName 示例 |
|---------|-------------------------------|
| 模板含指派节点 | "指派维修人员"（assign） |
| 模板含处置节点 | "现场处置"（execute） |
| 模板含验收节点 | "物业验收"（confirm） |
| 模板无指派节点 | 直接从 execute 开始，"现场处置" |

> **说明**：
> - `condition`（条件判断）和 `external`（跨企业协同）节点不改变实例状态，仅作路由/转发。
> - 驳回不重置 TTS，TTS 继续累计。
> - 转单不重置 TTS，TTS 继续累计。
> - 3 状态设计使模板可自由配置节点，无需修改状态枚举。

> 详细接口见 docs/api/工单监控.md

| 接口名称 | 方法 | 路径 | 说明 |
|---------|------|------|------|
| 获取工单实例列表 | GET | `/api/v1/work-order/instances` | 分页 + 筛选 |
| 获取工单实例详情 | GET | `/api/v1/work-order/instances/:id` | 含节点链路和处理记录 |
| 获取工单统计卡片 | GET | `/api/v1/work-order/instances/stats` | 按状态分组计数 |
| 取消工单 | POST | `/api/v1/work-order/instances/:id/cancel` | 需填写取消原因 |
| 强制改派 | POST | `/api/v1/work-order/instances/:id/reassign` | 需选择目标处理人 |

> **说明**：`/api/v1/work-order/instances/stats` 返回全量计数（`all` + 3 种 `InstanceStatus`），即使某状态当前计数为 0 也以 `0` 返回。前端据此动态渲染 4 张统计卡片，不得硬编码卡片列表为固定子集。详见 §3.3 状态机。

## 5. 非功能需求

- **性能**：列表页首屏加载时间 < 2s（1000 条工单内）；筛选响应 < 500ms
- **兼容性**：支持 Chrome、Edge、Safari 最新两个版本
- **安全**：需登录后访问；操作按钮按角色权限控制；取消/改派操作需记录操作日志
- **SLA 刷新**：SLA 进度每 30 秒自动刷新一次（前端轮询或 WebSocket）
