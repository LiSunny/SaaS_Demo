# 流程编排 产品需求文档

> 版本：v1.0 | 日期：2026-06-01 | 状态：草稿

## 1. 背景与目标

### 1.1 业务背景

本平台是一个维保服务协作平台，连接维保公司（服务商）与业主单位。随着业务发展，需要一套可泛化的流程编排框架，支撑以下典型场景：

- **工单场景**：设备维修工单从发起到关闭的全生命周期管理
- **督办场景**：监管方（如消防支队）向预警方（如物业公司）下达督办，跨企业流转
- **审批场景**：报告审核、合同确认等需要审批节点的流程

流程编排模块是整个平台的**基础设施**，为上层业务模块（维保任务、故障与隐患、报告管理等）提供统一的流程引擎能力。

### 1.2 模块目标

- **用户目标**：管理员通过可视化方式定义流程模板（节点、表单、流转规则、SLA），业务人员按模板创建并执行工单
- **业务目标**：一套流程引擎覆盖 90% 以上的流程场景（工单/督办/审批），避免为每种业务单独开发流程逻辑
- **技术目标**：模板与实例分离，支持模板版本管理；v1 覆盖核心流程能力，v2 扩展高级流程模式

### 1.3 适用范围

| 角色 | 可见范围 | 可执行操作 |
|------|---------|-----------|
| 平台管理员 | 全部模板 | 创建/编辑/发布/停用/删除模板 |
| 业务人员 | 已发布模板 | 按模板创建工单实例 |
| 服务商管理员 | 本企业模板 | 创建/编辑本企业模板 |
| 业主单位 | 查看工单进度 | 确认/驳回（按节点权限） |

## 2. 核心概念

| 概念 | 说明 | 举例 |
| --- | --- | --- |
| **模板 (Template)** | 流程蓝图，定义节点和流转规则 | "设备维修工单模板 v1" |
| **节点 (Node)** | 流程中的一个步骤，包含表单字段、指派规则、SLA、可执行操作 | "执行节点" |
| **字段 (Field)** | 节点上需填写/展示的数据项 | "故障描述"、"现场照片" |
| **实例 (Instance)** | 按模板创建的一次具体运行 | "20260525-001 号工单" |
| **任务 (Task)** | 某个节点分配给某人的待办 | "张三需要执行的维修任务" |
| **流转规则 (Transition)** | 节点间的跳转条件 | "通过→关闭节点，驳回→执行节点" |

## 3. 功能需求

### 3.1 模板管理

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 模板列表 | 按名称/状态查询、分页展示 | P0 |
| 新建模板 | 进入三步配置（基础设置 → 表单设计 → 流程设计） | P0 |
| 编辑模板 | 修改已有模板，生成新版本 | P0 |
| 删除模板 | 删除未启用模板，进行中实例关联时禁止删除 | P0 |
| 发布模板 | 模板从"待生效"发布为"执行中" | P0 |
| 停用/启用 | 控制模板可用状态 | P0 |
| 复制模板 | 基于现有模板创建副本 | P1 |

### 3.2 模板配置（三步向导）

| 步骤 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| 基础设置 | 基本信息 | 模板名称、编号、工单说明、发起人范围 | P0 |
| 基础设置 | SLA 默认配置 | 优先级、TTR、TTS、黄灯阈值 | P0 |
| 表单设计 | 拖拽设计 | 可视化拖拽组件构建表单 | P0 |
| 表单设计 | 字段来源 | 手动/自动/继承/回调 | P0 |
| 流程设计 | 节点编排 | 可视化添加/删除/排序节点 | P0 |
| 流程设计 | 节点配置 | 指派策略、表单字段权限、SLA 覆盖、消息通知 | P0 |
| 流程设计 | 流转规则 | 节点间连线，操作结果分支 | P0 |

### 3.3 节点类型

| 类型 | 标识 | 核心能力 | 优先级 |
|------|------|---------|--------|
| 发起 | `start` | 手动录入/自动填充/外部回调 | P0 |
| 指派 | `assign` | 指派处理人 + 接单确认（可选） | P0 |
| 执行 | `execute` | 到场校验/填写表单/采集证据 | P0 |
| 确认 | `confirm` | 通过/驳回/转审 | P0 |
| 关闭 | `close` | 归档/回调通知 | P0 |
| 自定义 | `custom` | 自由定义操作按钮和流转 | P0 |
| 条件分支 | `condition` | 基于操作结果/组织属性的分支 | P0 |

> **指派节点（`assign`）的行为由 `multipleMode` 决定**：
>
> | multipleMode | 含义 | "接单"动作 | 任务状态路径 |
> |-------------|------|-----------|------------|
> | `anyone` | 任一人接单（抢单），先接先得 | **有** — 执行人需主动抢单/接单 | 待指派 → 待接单 → 处置中 |
> | `each` | 每人各自生成独立任务 | **无** — 直接下发到各人待办 | 待指派 → 处置中 |
>
> > 以上两种路径中，实例状态始终为 **active**（进行中）。`待指派 / 待接单 / 处置中` 是节点任务（Task）级别的状态，不影响实例级别 `draft → active → closed` 的三态流转。
>
> 此外：
> - **单人静态指派**：无需接单确认，直接进入处理人待办（待指派 → 处置中）。
> - **指派给发起人**：运行时自动取工单发起人为节点负责人，适用于"谁发起谁处理/验收"场景。
> - **动态指派**（运行时选择处理人）：同上，无需接单确认。
> - `condition`（条件判断）和 `external`（跨企业协同）节点不改变实例状态。

### 3.4 SLA 管理

| 功能 | 描述 | 优先级 |
|------|------|--------|
| TTR（响应时限） | 任务到达 → 接单，衡量响应速度 | P0 |
| TTS（解决时限） | 接单 → 关闭，端到端时效考核 | P0 |
| 三色预警 | 绿灯（正常）→ 黄灯（80%）→ 红灯（100% 超时） | P0 |
| 红灯升级 | 超时后抄送/自动转派/退回上级 | P0 |
| 优先级预设 | 紧急/高/普通/低四档，一键填充时限 | P0 |
| 节点级覆盖 | 节点可覆盖模板默认 SLA | P0 |

### 3.5 实例管理（工单监控）

流程实例的运行时管控由 [工单监控模块](工单监控.md) 负责，包括：

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 实例列表 | 查看所有进行中的工单实例 | P0 |
| SLA 监控 | 按黄灯/红灯阈值实时预警 | P0 |
| 动态干预 | 转单、强制改派（v1） | P0 |
| 实例详情 | 查看工单流转历史、节点任务状态 | P0 |

## 5. 接口设计

### 5.1 模板管理接口

| 操作 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 获取模板列表 | `GET` | `/api/template` | 分页查询 |
| 获取模板配置 | `GET` | `/api/template/{id}/detail` | 完整配置 |
| 保存草稿 | `POST` | `/api/template/draft` | 新建/编辑 |
| 发布模板 | `POST` | `/api/template/{id}/publish` | 状态→执行中 |
| 删除模板 | `DELETE` | `/api/template/{id}` | 校验关联实例 |
| 变更状态 | `PUT` | `/api/template/{id}/status` | 停用/启用 |
| 校验流程 | `POST` | `/api/template/validate` | 返回错误列表 |

### 5.2 实例管理接口

| 操作 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 获取实例列表 | `GET` | `/api/order-instance` | 分页+筛选 |
| 获取实例详情 | `GET` | `/api/order-instance/{id}` | 含节点任务 |
| 创建实例 | `POST` | `/api/order-instance` | 按模板创建 |
| 转单 | `PUT` | `/api/order-instance/{id}/transfer` | 改派执行人 |
| 取消实例 | `PUT` | `/api/order-instance/{id}/cancel` | 取消工单 |
