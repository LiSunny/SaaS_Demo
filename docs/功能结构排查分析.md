# 平台功能结构排查分析报告

> 基于平台定位（语雀《平台概述》2026-07-31 最新版）与代码现状（maintenance-demo）的全面对照分析。
> 生成日期：2026-08-03

## 一、平台定位基线（应然）

### 1.1 一句话定位

**人工智能+公共安全管理平台**：以"大安全"为核心管理能力，聚焦消防与应急管理深度融合。

### 1.2 三大应用场景

| # | 场景 | 说明 |
|---|------|------|
| ① | **大安全自主管理** | 面向单个项目/企业，消防设施、应急预案、风险隐患实时监测与动态管理，被动应对→主动预防 |
| ② | **区域联勤联动** | 以监管部门为核心，打通区域内单位/部门信息壁垒，统一指挥、快速响应、多方协同应急联动 |
| ③ | **垂直穿透管控** | 面向大型集团，集团级安全管理中枢，对下属各级子公司统一监管与调度 |

### 1.3 架构

三层业务闭环：**监管端 — 数据中枢 — 执行端**（终端感知 → 数据中枢 → 监管决策）

### 1.4 核心用户（四方）

| 用户 | 典型角色 | 渠道 |
|------|---------|------|
| **监管机构** | 教育局/应急局/市监局/街道办 | Web 大屏 |
| **社会单位** | ① 普通单位：学校/企业/商户/物业；② **运营商**：项目管理方（重点单位联网项目、九小场所管理等） | Web + 移动端 |
| **技术服务机构** | 维保/检测/评估公司 | Web + 移动端 |
| **社会民众** | 公众/员工/家长/学生（**后续再说**，当前暂缓） | 移动端 |

> **运营商定位补充（用户确认 2026-08-03）**：社会单位中含一种特殊形态——**运营商**，以"项目管理"方式组织被管单位，典型项目形态：重点单位联网项目、九小场所管理等。对应数据模型中的相关方角色 `my_operator`（我的运营方）与导航占位节点"项目管理（项目列表/任务管理）"。

### 1.5 业务覆盖：3 行业 + 2 跨行业共享 = 14 业务场景

| 行业/场景 | 场景数 | 场景清单 |
|----------|:---:|---------|
| 🏫 校园安全管理 | 3 | 食品安全全链条、AI 防欺凌、宿舍安全应急 |
| 🏭 工贸企业安全管理 | 5 | 设备台账保养、巡查检查、隐患整改闭环、危险作业管控、告警与值守 |
| 🏪 小商户安全监管 | 2 | 商户安全自查、巡查与隐患处置 |
| 🔥 动火作业管理（共享） | 1 | 15 步 × 4 阶段审批 |
| 🔄 复工复产管理（共享） | 3 | 培训排查交底、多车间并行复工、尽职免责证据链 |

## 二、现状盘点（实然，代码事实）

### 2.1 导航结构（`src/config/navigation.ts`，2026-08-03 已重构）

**已按使用群体重构为四方视角**：6+1 分组（工作台固定），群体标签标在企业（`Enterprise.groups`），岗位决定组内子项。12 个真实路由 vs 56 个占位节点。

| 导航分组 | 群体 | 组内节点 | 真实落地 | 状态 |
|---------|------|---------|---------|------|
| 区域监管 | regulator | 态势总览 / 督办管理 / 监管检查 / 监管报告 | 监管大屏 | ⚠️ 督办/检查/报告占位 |
| 安全管理 | unit | 本企态势 / 巡查检查 / 隐患管理 / 危险作业 / 设备管理 / 食品安全 / 培训演练 / 我的工单 | 企业驾驶舱、设备列表、工单 | ❌ 巡查/隐患/危险作业/食品/培训占位 |
| 项目管理 | operator | 项目总览 / 项目列表 / 成员交付 / 项目工单 | 无 | ❌ 全部占位（新域） |
| 技术服务 | service | 我的工单 / 维保合同 / 维保计划 / 服务报告 | 工单、维保计划 | ⚠️ 合同/报告占位 |
| 运营管理 | platform-ops | 租户 / 用户 / 岗位 / 大屏 / 流程 / 类型注册 | 6 项全部实现 | ✅ |
| 平台管理 | platform-admin | 路由 / 菜单 / 参数 / 升级 | 无 | ❌ 全部占位 |

> 各群体分组尾部挂「系统管理」子项（企业级：成员/岗位/日志，org-admin 可见）。
> 详见 `docs/四方用户导航与体验账号设计.md`。

### 2.2 路由落地页面（`src/router/index.ts`）

- **门户**：`/portal`、`/portal/campus|industry|merchant|hotwork`、`/portal/case/:slug`、`/portal/preview/:type`
- **大屏**：`/landing`、`/landing/street-detail`、`/landing/fire-control`、`/landing/campus`、`/landing/ebike`、`/gongmao`、`/enterprise-cockpit`、`/resumption-bigscreen`
- **工作台**：`/workbench`
- **业务**：`/system/dashboard|monitor|order/:id|template`（工单）、`/maintenance/plans`（维保）、`/device/list`、`/resumption`（复工）
- **管理**：`/admin/*`（租户/用户/岗位/大屏）、`/enterprise/members|positions`

### 2.3 大屏类型（`src/config/bigscreen-templates.ts`）

仅 5 类：`landing`（监管态势）/ `gongmao`（工贸）/ `enterprise-cockpit`（企业驾驶舱）/ `campus`（校园）/ `ebike`（电单车）。

### 2.4 门户（`src/views/portal/PortalPage.vue`）

- 定位章节：3 个悬浮标注（企业自主管理 / 区域联勤联动 / 垂直穿透管控）✅
- **场景轮播仅 3 个**：校园 / 工贸 / 小商户（动火、复工未进轮播，仅案例区有）
- AI 能力 3 项；案例 8 个（5 已发布 + 3 coming）

## 三、差距分析（应然 × 实然）

### 🔴 Gap-1：核心用户四方，文档口径三处不一致

| 来源 | 用户分类 | 问题 |

| 语雀《核心用户群体》 | 监管机构、社会单位、技术服务机构、**社会民众** | 唯一含"社会民众"的版本 |
| 本地《平台岗位设计.md》 | 物业方、服务方、监管方、平台方 | 无"社会民众"；**无"运营商"** |
| 本地《用户管理/biz-design.md》 | 管理方、服务单位、监管机构、社会单位、平台运营方 | 五类，亦无"社会民众" |

**修正（用户确认 2026-08-03）**：
- **社会单位 = 普通单位 + 运营商（项目管理）**。运营商以项目组织被管单位，典型形态：重点单位联网项目、九小场所管理等
- 数据模型层已有呼应：相关方角色 `my_operator`（我的运营方，v1.1 已入枚举）✅
- **导航已按群体重构**：运营商有专属「项目管理」分组入口（2026-08-03 落地）✅，但页面仍为占位，待项目管理域填充
- **社会民众端暂缓**（用户明确"后续再说"），当前不列入功能结构

## 四、完善建议（功能结构重构方向）

### 4.1 核心思路

按 **"四方用户 × 三大场景"** 重构导航与门户，使定位可落点：

```
工作台（全员）
├── 监管端（监管机构：教育局/应急局/市监局）
│    区域态势大屏 · 督办管理 · 红黑榜考核 · 政务管理 · 监管报告
├── 单位端（社会单位）
│    ├── 普通单位（学校/企业/商户/物业）
│    │    巡查检查 · 隐患管理 · 危险作业 · 设备管理 · 食品安全 · 培训演练
│    └── 运营商（项目管理）← 导航已就位，页面待填充
│         项目列表 · 项目任务 · 重点单位联网项目 · 九小场所管理
├── 服务端（技术服务机构：维保/检测/评估）
│    维保合同 · 维保任务 · 工单接单处置 · 服务报告
└── 平台运营（平台方）
     租户 · 用户 · 岗位 · 大屏配置 · 流程模板 · 类型注册
```

> 民众端（社会民众）暂缓，待后续迭代。
> ✅ 导航重构已于 2026-08-03 落地（见 `docs/四方用户导航与体验账号设计.md`）。

### 4.2 配套动作

1. **门户场景轮播补 2 个**（动火/复工复产）→ 5 个场景对齐 14 场景
2. **门户新增"核心用户"章节**（四方用户卡片，含运营商项目管理定位）
3. **补齐运营商"项目管理"页面**（项目列表/项目任务/重点单位联网项目/九小场所管理），与 `my_operator` 角色闭环
4. **统一四方用户文档口径**（语雀为准：监管机构/社会单位/技术服务机构/社会民众；社会单位注明含运营商）— 本地已新增四方导航设计文档
5. **分批填充占位导航节点**为真实页面（先动火审批 → 巡查 → 隐患 → 政务 → 培训 → 食品）
6. **新增垂直穿透（集团）大屏类型**并注册模板
