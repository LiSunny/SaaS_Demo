# 复工复产管理 — 产品需求分析报告

> 分析日期：2026-07-20 | 来源：PDF《工贸企业复工复产平台APP建议书》+ WebSearch 交叉核验 | 分析人：/prd-analyze

---

## 一、需求概述

工厂企业在节后/停产检修/临时停工后，以车间为履责主体，按"六个一"要求完成复工筹备（建组→签责→培训→排查→体检→整改→验收→复工令）→ 试产观察（值班+验收）→ 资料归档的全流程闭环管理。

### 2.3 管理刚需

| 管理者痛点 | 系统解决方式 |
|-----------|-------------|
| 车间口头说"都查过了"，厂长无法验证 | 每步留痕 + 实时进度看板，厂长随时查看各车间状态 |
| 出事故后厂长需自证"已尽责" | 全流程签字记录 = 法律上的履职免责证据链 |

| 老员工离职，新主任不熟悉流程 | 系统内嵌 SOP 引导，不依赖个人经验传承 |
| 监管突击检查，翻不出完整档案 | 一键导出全套归档材料，满足检查溯源要求 |

### 2.5 利益相关方分析

> 厂长有购买动机 ≠ 系统会成功。下面的人不用，系统就是摆设。

| 利益相关方 | 态度 | 关键诉求 | 潜在阻力 |
|-----------|:---:|----------|----------|
| 厂长/法人 | 😊 积极 | 合规免责，出事能自证尽责 | —（购买决策者，动机最强） |
| 车间主任 | 😐 中立 | 不要大幅增加工作量；能看到各班组进度更好 | "又多了一套系统要填"，如果操作繁琐会抵触 |
| 车间安全员 | 😊 积极 | 以前催人填表靠吼，系统能自动催办、汇总报表 | —（受益者，愿意用） |
| 班组长 | 😟 可能抵触 | 别让我每步都拍照签字，别比微信麻烦 | **最大阻力点**——"以前一句话的事，现在要填表"。需把操作简化到比微信随手拍更简单 |
| 一线工人 | 😐 无所谓 | 别让我多装一个复杂的 App | 如果培训签到、隐患上报操作超过 3 步，就不愿用 |
| 设备管理员 | 😐 中立 | 扫码体检如果能替代手工填表就愿意 | 如果扫码后还要手动输一堆数据，就是负担 |

> **关键发现**：购买决策者（厂长）和使用者（班组长、工人）之间有明显的动机落差。系统设计的核心挑战不是功能齐全，而是**让班组长的操作比微信随手拍还简单**——否则厂长买了系统，车间还是用微信群。

## 三、解决思路

### 3.1 核心解法

系统的解法逻辑是将**法规强制要求**转化为**不可跳过的串行步骤**，每一步自动留痕，最终形成可追溯的合规证据链：

```
法规要求"六个一"全流程   →  串行强制步骤，上一步未完下一步锁死  →  检查时一键导出完整材料

厂长怕出事说不清楚       →  每步电子签+时间戳+操作日志         →  法律上的履职免责证据，"我尽责了"可自证

多车间同时复工不可见     →  一屏状态看板，异常自动标红          →  管理层实时掌控全局，不用打电话问进度

新主任不懂流程           →  系统内嵌 SOP，每一步提示该做什么    →  不依赖个人经验，换人也能跑通
```

### 3.2 关差分析

| 环节 | 现行方式 | 系统方式 | 核心差异 |
|------|----------|----------|----------|
| 流程执行 | 口头通知 + 微信群里喊话 | 串行步骤，上一步未完成下一步锁死 | **从"靠人盯"到"系统强制"** |
| 签字/确认 | 纸质签，容易丢失或补签 | 电子签 + 时间戳，不可篡改 | **从"事后补"到"现场签"** |
| 进度可见 | 车间主任自己知道，厂长靠汇报 | 一屏看全局，哪个车间卡在哪一步一目了然 | **从"黑盒"到"透明"** |
| 隐患整改 | 纸质台账，整改完才登记 | 随手拍上报 → 指派责任人 → 限时整改 → 验收销号 | **从"事后记"到"全程追踪"** |
| 设备检查 | 看运气，靠经验 | 扫码拉台账 → 逐项打钩 → 异常拍照标记 → 生成体检报告 | **从"走过场"到"逐项确认"** |
| 档案归档 | 纸盒子里翻，检查时找不全 | 全流程自动归档，一键导出 PDF 套件 | **从"找证据"到"随时查"** |

### 3.3 核心价值主张

> **让你过得了检查、说得清责任。** 节后复工不再是"凭感觉开工"，而是每一步有据可查、每一关有人签字、出了事能自证尽责——既保护工人的命，也保护厂长的自由。

## 四、产品形态判定

| 判定维度 | 结论 | 依据 |
|----------|:---:|------|
| 有独立业务闭环 | ✅ | 从建组到归档，不依赖其他模块也能独立完成 |
| 可跨行业复用 | ✅ | 矿山/化工/建筑/工贸的核心流程一致，仅检查表不同 |
| 可独立销售 | ✅ | 客户可单独为"节后复工安全管理"付费，决策链短 |
| 涉及多个子场景 | ❌ | 单一流程（筹备→试产→归档），不是多场景集合 |

**判定**：跨行业共享场景

### 5.2 差距分析

| 法规要求（省级以上来源） | PDF 是否覆盖 | 说明 |
|----------|:---:|------|
| 召开安全专题会议 | ❌ | "六个一"第 1 条要求由主要负责人主持公司级会议，PDF 只从车间级开始 |

| 全厂性安全检查（公司级） | ❌ | PDF 聚焦车间级排查，缺少公司级（厂长视角）的安全检查 |

> **关键发现**：PDF 以车间为视角是正确的，但遗漏了"六个一"中属于公司级（厂长）的三项要求 + 技术交底 + 应急方案。设计系统时需补上，否则省级检查会暴露合规缺口。

### 5.3 合规边界
