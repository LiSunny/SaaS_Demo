# ai-spec：复工流程详情

> 页面路由：`/resumption/:id` | 页面类型：详情展示（单一父容器 + 4 阶段 + 7 个步骤组件） | 深度：🔵 light | 最后更新：2026-07-21

## 2. 阶段定义

| 阶段 | 标签 | 子步骤 | 编辑规则 |
|------|------|--------|------|
| 复工准备 | 复工准备 | ①-⑦ | prepare 阶段步骤 1-8 可编辑 |
| 复工审核 | 复工审核 | ⑧-⑨ | 验收后前序锁定，仅编辑当前 |
| 试产观察 | 试产观察 | ⑩ | 仅编辑步骤 10 |
| 正式复产 | 正式复产 | ⑪ | 全部只读 |

## 3. 摘要卡片结构

| 区域 | 内容 | 宽度 |
|------|------|:---:|
| 场所信息 | 场所名（20px）+ StatusTag + 开始时间 + 结束时间 | 自适应 |
| 竖分隔线 | 1px solid，78px 高 | 0 |
| 排查设备 | unit.svg（56px 容器）+ 统计数字 | 自适应 |
| 排查隐患 | connect.svg + 统计数字 | 自适应 |
| 已闭环 | 无图标，统计数字 | 自适应 |
| 未闭环 | 无图标，统计数字 | 自适应 |
| QR 码 | 78×78 占位符 | 78px |

> 统计数字当前为静态 Mock 数据（25/365/365/365），standard 阶段接入真实数据。

## 4. 编辑交互

- **内联编辑**：点击"录入"/"编辑"按钮后，步骤详情区原地切换为编辑表单，保存/取消按钮在同一位置
- **步骤类型分发**：根据 `selectedStep.stepType` 动态渲染对应步骤组件
- **步骤 1 特殊处理**：保存时同时更新小组成员（`updateTeamMembers`）
- **保存数据**：`completedBy` + `remark` + `status: 'done'` + `formData`（步骤专属）

## 5. 数据流

```
useResumptionStore.fetchDetail(planId)
    │
    ├── detail → summary-card + stage-bar
    ├── selectedStage → currentStageSteps（按 stage.stepOrders 过滤）
    │   └── step-nav 渲染子步骤
    ├── selectedStepId → selectedStep → stepComponent
    │   └── 动态组件（stepType → 专属组件）
    ├── stageState(stage) → done/active/pending
    │   ├── done = 所有子步骤完成 → 绿色 ✓
    │   ├── active = 部分完成 → 蓝色 + 动画
    │   └── pending = 全部待执行 → 灰色
    ├── doneLineWidth → 蓝色连线动态宽度
    └── canEdit(step)
        ├── prepare → stepOrder ≤ 8 可编辑
        ├── review/trial → 仅第一个未完成步骤可编辑
        └── production → 不可编辑
```

## 6. 边界条件

| 场景 | 处理 |
|------|------|
| 阶段无子步骤 | stage-content 不渲染 |
| 所有步骤完成 | 选中 production 阶段 + 最后步骤 |
| plan 不存在 | empty-wrap |
| 路由参数变化 | watch route.params.id 重新 loadPlan |
| 编辑中切换步骤 | 不允许（editing 时 switchStep 直接 return） |
