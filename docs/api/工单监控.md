## 1. 获取工单实例列表

**描述**：分页查询工单实例列表，支持多维度筛选
**方法**：GET
**路径**：`/api/v1/work-order/instances`
**权限**：需要登录

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `page` | number | 否 | 页码，默认 1 |
| `pageSize` | number | 否 | 每页条数，默认 20，最大 100 |
| `keyword` | string | 否 | 关键词，模糊匹配工单编号、发起人姓名 |
| `status` | string | 否 | 实例状态，多选用逗号分隔。可选值：draft / active / closed |
| `templateId` | number | 否 | 模板 ID，精确匹配 |
| `priority` | string | 否 | 优先级：urgent / high / normal / low |
| `slaStatus` | string | 否 | SLA 状态：normal / warning / timeout |
| `startDate` | string | 否 | 创建时间起始，格式 YYYY-MM-DD |
| `endDate` | string | 否 | 创建时间截止，格式 YYYY-MM-DD |
| `sortBy` | string | 否 | 排序字段，默认 createdAt |
| `sortOrder` | string | 否 | 排序方向，asc / desc，默认 desc |

### 请求示例

```
GET /api/v1/work-order/instances?page=1&pageSize=20&status=active&slaStatus=warning&startDate=2026-05-01&endDate=2026-06-01
```

## 3. 获取工单统计卡片

**描述**：获取按实例状态分组的统计计数，用于顶部统计卡片
**方法**：GET
**路径**：`/api/v1/work-order/instances/stats`
**权限**：需要登录

### 请求参数

无额外参数（自动根据当前用户角色过滤可见范围）。

### 请求示例

```
GET /api/v1/work-order/instances/stats
```

### 响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "all": 128,
    "draft": 3,
    "active": 83,
    "closed": 42
  }
}
```

### 错误码

| code | 说明 | 处理建议 |
|------|------|---------|
| 1002 | 无权限访问 | 确认登录状态和角色权限 |

## 4. 取消工单

**描述**：手动取消工单实例，取消后进入"已关闭"状态但不触发归档回调
**方法**：POST
**路径**：`/api/v1/work-order/instances/:id/cancel`
**权限**：需要平台运营方角色

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `reason` | string | 是 | 取消原因，最多 200 字 |

### 请求示例

```json
{
  "reason": "工单重复创建，需取消"
}
```

### 响应结构

```json
{
  "code": 0,
  "message": "工单 WO20260601-001 已取消",
  "data": {
    "id": 1,
    "orderNo": "WO20260601-001",
    "status": "closed",
    "closedAt": "2026-06-01 14:30:00",
    "closedBy": "平台管理员"
  }
}
```

### 错误码

| code | 说明 | 处理建议 |
|------|------|---------|
| 3001 | 工单实例不存在 | 检查 ID 是否正确 |
| 3002 | 工单已关闭，不可取消 | 提示用户工单已关闭 |
| 3003 | 无操作权限 | 仅平台运营方可取消 |
| 3004 | 取消原因不能为空 | 提示用户填写原因 |

## 5. 强制改派

**描述**：平台运营方强制更改工单当前节点的处理人
**方法**：POST
**路径**：`/api/v1/work-order/instances/:id/reassign`
**权限**：需要平台运营方角色

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `targetAssigneeId` | number | 是 | 目标处理人 ID |
| `reason` | string | 是 | 改派原因，最多 200 字 |

### 请求示例

```json
{
  "targetAssigneeId": 20,
  "reason": "原处理人李四请假，改派给王五"
}
```

### 响应结构

```json
{
  "code": 0,
  "message": "工单 WO20260601-001 已改派给王五",
  "data": {
    "id": 1,
    "orderNo": "WO20260601-001",
    "previousAssigneeId": 15,
    "previousAssigneeName": "李四",
    "currentAssigneeId": 20,
    "currentAssigneeName": "王五",
    "updatedAt": "2026-06-01 14:35:00"
  }
}
```

### 错误码

| code | 说明 | 处理建议 |
|------|------|---------|
| 4001 | 工单实例不存在 | 检查 ID 是否正确 |
| 4002 | 工单已关闭，不可改派 | 提示用户工单已关闭 |
| 4003 | 无操作权限 | 仅平台运营方可强制改派 |
| 4004 | 目标处理人不存在 | 检查人员 ID 是否正确 |
| 4005 | 改派原因不能为空 | 提示用户填写原因 |

## 附：Mock 数据设计要点

1. **Mock 列表**至少包含 15-20 条工单，覆盖所有状态和 SLA 三色情况
2. **状态分布**建议：进行中 > 已关闭 > 草稿
3. **SLA 分布**建议：至少包含 2 条超时（红）、3 条预警（黄）
4. **优先级分布**建议：普通 50%、紧急 20%、高 15%、低 15%
5. **时间戳**使用相对当前时间计算，确保 SLA 进度动态变化可展示
