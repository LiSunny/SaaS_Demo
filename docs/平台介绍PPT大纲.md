**副标题**：从被动响应，到主动智治

### 第 2 页 · 一组数字背后，是同一个问题

**标题**：事故不是天灾，是人祸——而且每个环节都在事前被反复忽略

**核心信息**：
> 绝大多数重大安全事故，不是"不知道"，而是"没人盯"。

**数据冲击区**（用大号数字 + 简短标注）：

| 数字 | 说明 |
|:---:|------|
| **31 人** | 银川烧烤店燃气爆炸（2023.6）——爆炸前一个月消防刚检查过，"检查了，但没查出来" |
| **13 名儿童** | 河南方城学校宿舍火灾（2024.1）——消火栓没水、烟感没电、56㎡ 住 34 人 |
| **923 万元** | 吉首工贸城火灾（2023.12）——消控室无人值班，自动报警未开 |
| **24 人被追责** | 同上一起事故——从值班员到企业负责人，连带追责 |

**视觉建议**：
- 四个数字分四栏并排，大号红色字体
- 每个数字下方一行事故简述

**讲解要点**（1.5 分钟）：
先念四个数字，停顿。"这四个事件，每一个事后调查都发现同一个规律：出事的链条上，每一个环节都有人在事前发现过问题、口头说过、但最后不了了之。不是没人管，是没有一个系统在管。"

### 第 3 页 · 传统安全管理的 5 个断裂

**标题**：每一个环节都靠人自觉——而人的自觉，在侥幸心理面前不堪一击

**核心信息**：
> 把五个断裂连成一条线，就是事故的完整路径。

**五段流程图**（横向瀑布式）：

```
设备底数不清 ──→ 巡查走过场 ──→ 隐患口头传 ──→ 危险作业靠胆子 ──→ 告警没人应
    │                 │               │               │                │
Excel/纸质台账     人到不到都打钩   说了就＝改了    无证也能上      蜂鸣器响了没人接

**视觉建议**：

- 每个卡片一上一下：上一行是"现象"（红字），下一行是"后果"（灰字）

**讲解要点**（1.5 分钟）：
逐一念五个卡片，每个一句话。最后说："这五个断裂拼起来，就是同一条事故链。要打断这条链子，唯一的办法是把每一个'信得过'变成'看得见'。"

### 第 5 页 · 三层业务架构

**标题**：数据从一线自动产生，管理层看到的是"势"

**核心信息**：
> 自下而上三层：感知 → 分析 → 决策。

**三层架构图**：

```
┌──────────────────────────────────────────────┐
│  监管/决策层                                 │
│  大屏态势总览 · 一键督办 · 合规报告 · 应急联动  │
├──────────────────────────────────────────────┤
│  数据中枢层                                  │
│  AI 智能助手 · 风险预警引擎 · 流程引擎    │
├──────────────────────────────────────────────┤
│  终端感知层                                  │
│  IoT 设备 · 扫码打卡 · 拍照留痕 · AI 声音识别 │
└──────────────────────────────────────────────┘
```

**关键概念——"由事转势"**：
- 一线看到的是"事"：3 号宿舍烟感响了、2 号车间除尘器堵了
- 管理方看到的是"势"："该校本月电气预警上升 30%""这家企业隐患闭环率低于 60%"
- 每一层自动聚合，不需要人工汇总

**视觉建议**：
- 三层堆叠矩形，用箭头向上表示数据流
- 左侧标注"事 → 势"的转化箭头
- 右侧列出对应的使用者层级

**讲解要点**（1.5 分钟）：
先说清"由事转势"这个概念。"校长关心什么？不是每间教室门把手坏没坏，而是'我的学校今天安不安全'。局长关心什么？不是某一个学校某一间宿舍，而是'全区哪几所学校最近在恶化'。这就是从'事'到'势'的转化。信息在每一层自动聚合，不需要中间人汇总、写报告、做 Excel。"

### 第 6 页 · 不是给领导看的大屏

**标题**：从一线操作到顶层决策，是同一套数据

**核心信息**：
> 这不是一个"给领导看"的大屏——每一行数据都能下钻到源头。

**下钻演示链**（从左到右）：

```
局级大屏                   校/企大屏                一线操作记录
"该校告警上升30%"  → 点击 → 具体告警列表 → 点击 → 某间宿舍烟感触发时间、
                                              值班员几点确认、
                                              保安几点到场、
                                              处置照片
```

**对比传统做法**：
- 传统：领导要数据 → 层层打电话 → 手动填 Excel → 半天后拿到 → 数据可能已经变了
- 平台：领导大屏上点一下 → 实时看到源头记录 → 几秒钟

**视觉建议**：
- 三步渐进点击 → 展开的效果，可用 GIF 动图或分步展示
- 顶部大字："**从'宏观怀疑'到'微观确认'，一步下钻**"

**讲解要点**（1.5 分钟）：
强调数据链的完整性。"这条链路的重要意义是什么？局长在大屏看到一所学校告警异常，他点击这所学校，直接弹窗看到——不是看到一份报告，而是看到那间宿舍的原始记录：几点烟感响了、谁确认的、几点处置的。不需要打电话问人。从发现问题到确认原因，层层下钻，几秒钟。"

### 🏫 校园安全管理

### 第 10 页 · 校园安全：出不起事

**标题**：一个学生的安全背后，是一个家庭的完整

**核心信息**：
> 三起真实事件，同一条根子——信息在采集时就不完整，传递时层层衰减。

**三个案例冲击**（卡片式，每个配现场照片或新闻截图）：

| | 事件 | 真相 | 后果 |
|---|------|------|------|
| 🥩 | **昆明长丰学校"臭肉案"**（2024.10） | 猪肉常温堆放几小时变质发臭，承包食堂的物业公司无餐饮资质。校长一问三不知 | 校长免职，企业罚 578 万 |
| 👊 | **长沙刘婷被欺凌近一年**（2024.4） | 高跟鞋砸头缝针、凌晨入室施暴、被扒衣威胁。持续近一年，直到轻伤才曝光 | 没有一个系统发现过 |
| 🔥 | **河南方城学校宿舍火灾**（2024.1） | 8 岁孩子打火机烧被子——消火栓没水、烟感没电、56㎡ 住 34 人、宿管没有第一时间报警 | **13 名儿童遇难** |

**根因链**：
> 巡检员发现消防栓没水 → 写在纸上 → 队长月底汇总为"部分消防设施故障" → 总务主任学期总结写"消防设备需加强维护" → 校长看到的只剩"总体良好，个别已整改"。而教育局连"个别"两个字都看不到。

**视觉建议**：
- 三个卡片横向排列，每个配对应的新闻关键词
- 底部放大根因链（箭头递进式衰减）

**讲解要点**（2 分钟）：
"这三个事件，不是'意外'。每一起事件背后，都是同一件事：信息在传递过程中被压缩、被美化、被模糊了。校长真的是坏人吗？不是。但他能看到的只有别人汇总给他的——而每一次汇总，就失真一次。这就是我们要解决的问题。"

### 第 11 页 · 双层架构：局端看势，校端做事

**标题**：信息自动聚合，校长比教育局更早知道自己的问题

**核心信息**：
> "教育局（区域级）+ 学校（校级）"双层架构。校级关注具体事务，局级提取宏观态势。

**双层联动图**：

```
┌─────────────────────────────────────────┐
│  区域级：教育局（宏观监管）                │
│  ┌─────────────────────────────────┐   │
│  │ 全区安全热力图 · 红黑榜排名考核       │   │
│  │ 一键下发督办 · 跨校风险横向对比       │   │
│  └──────────┬──────────────────────┘   │
│             │  由事转势 ↑                │
│             │  下钻 ↓    │  督办 ↓        │
│  ┌──────────┴──────────────────────┐   │
│  │  校级：学校（微观执行）              │   │
│  │  日常扫码打卡 · 拍照留痕 · 自动汇聚  │   │
│  │  学校大屏："我的学校现在安不安全"     │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

**4 项联动衔接机制**：

| 机制 | 说明 | 举例 |
|------|------|------|
| **由事转势** | 学校端关注具体事件，局端抽象为趋势 | "该校本月电气预警上升 30%" |
| **宏观→微观下钻** | 局端点击异常指标，弹窗看校级可视化页面 | 点击某校 → 看到该校实时大屏 |
| **督办响应闭环** | 局端识别高风险学校，一键下发督办 | 指令触达校级平台，系统监控时效 |
| **资源调度中心** | 突发时查看消防/医疗/警务与学校的距离 | 一键呼叫校方负责人 |

**分级分类：寄宿制 vs 非寄宿制**：

| 维度 | 寄宿制学校 | 非寄宿制学校 |
|------|-----------|------------|

### 第 15 页 · 场景三连：设备→巡查→隐患

**标题**：从设备上线到隐患关闭——三个场景串成一条闭环

**核心信息**：
> 设备台账（一机一码）→ 巡查检查（扫码打卡）→ 隐患整改（不可跳过的闭环）。

**三连流程图**：

```
设备台账                 巡查检查                  隐患整改闭环
                        
一机一码，扫码看         计划→任务推送            上报→分派→整改
全生命周期              →扫码打卡→逐项           →前后对比照→验收
                       检查→异常上报            →关闭归档
    │                      │                        │
    │ 保养周期到期          │ 发现异常                │ 超时未改
    │ ↓                    │ ↓                      │ ↓
    │ 自动生成保养任务      │ 自动生成隐患流          │ 系统亮红灯
    │ 推到维保工程师手机     │ 推送整改责任人          │ 提醒管理人
```

**每个场景的"以前 vs 现在"**：

| 场景 | 以前 | 现在 |
|------|------|------|
| **设备台账** | 几百台设备哪台该保养，全在"老张"脑子里。老张一请假，所有人翻抽屉 | 扫码看到设备全生命周期。保养计划自动生成任务推送到手机 |
| **巡查检查** | 人到不到都能打钩，照片可以事后补 | 扫码打卡验位置，检查清单逐项引导，异常自动生成隐患流 |
| **隐患整改** | "跟老王说过了"→"知道了"→"忘了" | 上报→分派→整改前后对比照→验收确认→关闭。每步时间戳 |

**线下无网络场景**：
> 地下水泵房、顶层设备间无网络？离线模式支持断网执行，回到有网络的地方自动同步。

**视觉建议**：
- 三个场景横向排列，每个内部用"以前 vs 现在"左右对比
- 箭头连接三个场景，形成闭环

**讲解要点**（2 分钟）：
"为什么叫'三连'？因为这三个场景在现场是连在一起的。一台消防水泵，先要有台账——它是什么时候买的、谁在维保。然后要有巡查——每个月有人去扫码检查它运行正不正常。如果发现异常——隐患整改流程启动。它的价值在于：不是三个孤立的功能，而是一条完整的链。从设备台账到隐患整改，每一步都有时间戳。"

### 第 16 页 · 告警与值守：最后一道防线

**标题**：不让一个碳火炉烧掉 1.8 万平米

| 事件 | 细节 |
|------|------|
| 纸片卡消音键 | 北京昌平养老社区，值班员用纸片卡住消音键，系统静音，延误 57 分钟，2 人被行拘 |

**平台的四步改造**：

```

│                │                │                 │
各类告警统一接    系统按告警类别      从大屏调取对应      同类型误报可

           火警→立即处置   看是真告警还是      不用每条单独点
           故障→按时处理   误报
           一般→记录归档

**吉首工贸城对比**：
> 如果那天晚上消控室有人坐在大屏前，烟感触发的第一时间大屏弹窗，值班员一键调取摄像头确认——一个碳火炉不会烧掉 1.8 万平米。

### 第 17 页 · 小商户：数千万家的"看不见"

**标题**：一个漏气罐可以掀翻半栋楼——而辖区有几千家这样的店

**核心信息**：
> 小商户的安全管理难度不在于"一家店的灭火器有没有过期"，而在于"当几千家店同时存在同一个辖区，你怎么知道谁的灭火器过期了"。

**两个惨烈案例**：

| | 银川烧烤店（2023.6） | 江西新余（2024.1） |
|---|---|---|
| **起因** | 员工误将液化气调压器接到液相阀，大量泄漏 | 违规建冷库，聚氨酯泡沫释放易燃气体 |
| **致命点** | 员工慌张反向开大阀门，遇上明火→爆炸。楼梯被炸毁，二楼窗户防盗网+广告牌封死 | 地下一层和一层无防火分隔，浓烟直冲二楼培训机构。教室窗户防盗网+广告牌封死 |
| **后果** | **31 人死亡**，7 人受伤 | **39 人遇难**（多为孩子） |
| **讽刺** | 爆炸前一个月消防刚检查过 | 冷库是违规建的，没有人在出事前发现 |

**小商户特有的 5 个管理死结**：

| 死结 | 为什么特别难 |
|------|------------|
| 数量巨大 | 一个街道办辖区可能几千家店，靠几个人跑不完 |
| 业态差异大 | 早餐店、五金铺、理发店——安全风险完全不同 |
| 店主安全意识弱 | "半年没出事，应该没问题" |
| 场所条件先天不足 | 液化气罐、老旧电线、下店上宅 |
| 巡查深度不够 | 走一圈签个字，里面的东西根本没看 |

**视觉建议**：
- 两个案例分两栏，交叉引用：**同样被防盗网+广告牌封死**（两个案例的共同致命点）
- 5 个死结用 icon + 一句话

**讲解要点**（1.5 分钟）：
"小商户和大企业不一样。大企业至少有专职安全员。小商户的老板自己就是安全员——同时他还要炒菜、收银、进货。你让他每月做一次安全检查，他签个字完事。所以小商户不能用管大企业的办法来管，必须更轻、更简单。"

**角色拆解**：

| 角色 | 做什么 | 频次 | 端 |
|------|--------|------|:---:|
| **商户经营者** | 手机打卡，自动适配检查清单。餐饮→燃气+烟感，零售→电气线路 | 每天 1 分钟 | 📱 |
| **物业巡查/街道办** | 到店扫码→拍照上报→系统推送整改 | 按辖区频次 | 📱 |
| **管理方** | 大屏看履责率/整改率/处置率，只去找需要关注的 | 随时 | 🖥 |

**对比**：

| 以前的管理方式 | 现在的平台方式 |
|--------------|--------------|
| 安全宣传栏贴告示"每月检查一次灭火器" | 系统每天推送检查项，漏打自动提醒 |
| 人员不够，几千家店靠几个人跑 | 大屏看履责率，只去关注漏打卡和高风险店 |
| 发现了隐患："赶紧弄一下"——"好好好" | 拍照上报→系统推送→整改后拍照回传→闭环 |
| 出了事翻出潦草的 A4 纸 | 每步时间戳和证据可追溯 |

**讲解要点**（1.5 分钟）：
"小商户的方案，核心就一个字——轻。商户每天花 1 分钟手机打卡。检查项不用他自己想——系统按他的店是什么类型自动适配。早餐店侧重燃气和烟感，五金铺侧重电气线路。物业巡查走到店门口扫码即到——不需要填表，拍照上报隐患，系统自动推送到商户手机上。管理方打开大屏，三个数字：今天履责率多少、隐患整改率多少、告警处置率多少——三秒看清辖区。不是打电话问、不是等人报，是大屏扫一眼就知道。"

### 第 19 页 · 动火作业：一次动火，十五道关

**标题**：把侥幸关在制度笼子里

**核心信息**：
> 违规动火占工贸火灾三成以上。15 步 × 4 阶段全流程管控——每步拍照/签名/定位，不通过不能下一步。

**事故冲击**（快速列举 4 起）：

| 时间 | 地点 | 事故 | 真相 |
|------|------|------|------|
| 2023.3 | 河北沧州 | 4 死 | 未重开动火票，角磨机火花引爆储罐 |
| 2023.4 | 浙江武义 | 11 死 | 电焊工违章，焊渣引燃拉丝调制漆 |
| 2024.4 | 海南三亚 | 3 死 | 动火票系伪造——签名代签、审批在作业前标"已完成" |
| 2024.5 | 云南大理 | 全毁 | 未审批、柴油未移走，切割火花引燃油料 |

**传统做法的 5 个坑**：

| 坑 | 传统做法 | 致命后果 |
|----|---------|---------|
| 审批走过场 | 纸质动火票，签字靠关系 | 无证也能上，事故后找不到责任人 |
| 现场无证据 | 无影像留存 | 说不清谁在现场、做了什么 |
| 监护缺位 | "安排了监火人"= 口头说了一句 | 起火第一时间无人发现 |
| 审核靠经验 | 安全员凭"感觉"判断 | 前序步骤没看全就放行 |
| 闭环靠自觉 | 动火结束就算完 | 余火复燃、次日清晨发现火灾 |

**讲解要点**（1.5 分钟）：
"四起动火事故——分布在不同的时间、不同的地点、不同的企业，剧本一模一样。原因就一个：流程依赖人的自觉。'老王是老员工了，信得过'——一份动火票就签了。我们的回答是把动火作业拆成 15 步、4 个阶段，每一步都要拍照、签名、定位——你不拍照，系统不让你进下一步。不是人管人，是流程管人。"

### 第 20 页 · 动火作业：典型一天全流程

**标题**：从"发起"到"归档"——比微信随手拍更简单

**核心信息**：
> 移动端做——拍照/签字/审批，每步在现场完成。Web 端看——管理台账 + 合规报告一键导出 PDF。

**15 步全流程时间线**：

```
阶段一：发起部署          阶段二：准备准入        阶段三：授权作业
│                        │                      │
08:30 发起申请           10:10 监火人三项承诺    10:30 签票、会商、自律书
08:50 车间部署，指派监火人 10:10 安全管理员终审    11:00 指令下达，作业开始
09:10 证照备案（4张照）                         13:00 作业实录
09:30 技术交底+三方合影                          │
09:50 环护方案与应急预案                         阶段四：闭环归档
                                                  │
                                                 14:30 清理交接，三方签名
                                                 15:00 观察期满，关闭动火票
                                                 16:00 合规报告，一键导出PDF
```

**关键机制**：

| 机制 | 说明 | 不可伪造 |
|------|------|:---:|
| 📸 **强制留痕** | 动火前环境全景 + 防护设施近景 + 三方现场合影 | ✅ 照片带时间戳+GPS |
| ✍️ **手写签名** | 每一步关键节点手写签名，系统存档 | ✅ 不可复制，事后可追责 |
| 🚫 **过期拦截** | 特种作业证过期 → 系统直接阻止流程 | ✅ 不是建议，是不通过不能继续 |
| 🔒 **顺序锁定** | 前序步骤未完成，后续步骤不可操作 | ✅ 不能先干活后补票 |

**合规报告**（Web 端）：
> 报告内容：作业概况 + 15 步详细判定（每步"符合/不符合"）+ 6 方责任主体签章确认 + 影像附件存证。**一键导出 PDF，用于迎检或事故调查。**

**讲解要点**（1.5 分钟）：
"这个流程看起来很长——15 步——但实际上操作比微信随手拍更简单。移动端每一步打开就是拍照、签名、点确认。关键不是复杂，是关键节点不可跳过。比如证照过期——系统直接拦住，不让你下一步。三方合影——证明三个人在同一时间同一地点碰头了。最后 Web 端一键导出合规报告，A4 格式，上级检查直接打印。"

### 第 21 页 · 为什么动火作业是共享场景

**标题**：同样的流程，不同的行业都在用——只维护一套

**核心信息**：
> 动火作业——工厂管道焊接在用，学校食堂维修也在用。同一套 15 步审批，各自引用，不重复维护。

**共享逻辑图**：

```
              ┌──────────────────┐
              │  动火作业管理      │
              │  15步 × 4阶段     │
              │  合规报告导出PDF   │
              └───┬──────────┬───┘
                  │ 引用      │ 引用
          ┌───────┴──┐  ┌────┴──────┐
          │ 工贸企业  │  │ 校园安全   │
          │ 管道焊接  │  │ 食堂维修   │
          │ 设备改造  │  │ 实验室改造 │
          └──────────┘  └───────────┘
```

**为什么这样设计**：
- 需求一样，流程一样 → 只写一次，不复制粘贴
- 修改动火流程 → 所有引用方同步生效
- 每个行业在自己的综述文档里引用共享场景，不需要重复写

**讲解要点**（30 秒）：
"动火作业，工厂管道焊接在用、学校食堂维修也在用。如果为每个行业单独做一个动火模块，维护成本翻几倍。所以它独立作为一个'共享场景'——同一套流程，工贸综述和校园综述各自引用，不重复。"

### 第 23 页 · 平台差异化优势

**标题**：不是"做功能"，是"做闭环"

**核心信息**：
> 市场上不缺少做安全管理的软件。缺少的是：每一步不可跳过、不可伪造、从一线到顶层完整贯通。

**四大差异化**：

| | 我们的做法 | 市面常见做法 |
|---|---|---|
| 🔒 **不可跳过的闭环** | 每一步拍照/签名/定位，不通过 → 不能继续 | 检查表打钩，打没打都能交 |
| 🔗 **数据不衰减** | 一线操作自动汇聚到管理大屏，没有中间汇总人 | 层层上报 → 层层压缩 → 信息失真 |
| 🧠 **AI 补盲区** | 声音识别（防欺凌）、用电指纹（违规电器）、证照有效期自动校验 | 纯靠人看、人记、人判断 |
| 📐 **轻量适配** | 规上精细化 / 规下轻量化 / 寄宿vs非寄宿差异化 | 一刀切，所有客户同一套模板 |

**三个"不是"**：
- 不是给领导看的大屏——每一行数据都能下钻到操作人
- 不是替代人——是把人的经验固化为系统规则
- 不是功能堆砌——是从一线操作到顶层决策的完整数据链

**视觉建议**：
- 左右对比表（我们的做法 vs 市面做法）
- 底部三个"不是"，用引用块

**讲解要点**（1 分钟）：
"你可能会问：市面上安全管理的软件不少，你们有什么不一样？四个字：不可跳过。大多数软件本质是电子表单——填不填、真填还是随便填，完全看人。我们的核心设计是：每一步必须拍照/签名/定位，系统验证通过才能下一步。这就从根本上断了侥幸心理。另外一点更重要——轻量适配。管大厂和管小作坊不能用同一套系统。"
