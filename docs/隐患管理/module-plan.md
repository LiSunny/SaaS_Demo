## 编写说明

### 跨端适配约定

每条子功能都要标一个「端平台」,表示它落到哪个端实现。本节讲怎么标。

#### 2 种端

| 标注 | 在哪运行 | 谁用 |
|---|---|---|
| **Web** | PC 浏览器(Chrome/Edge) | 监管方/管理方 |
| **移动端** | 手机/平板(uni-app 单代码库出 Web + 小程序) | 巡查员/维保工程师/监管员现场 |

> **本版本只覆盖 Web 和移动端 2 种端**。原生 App 不在本期规划;移动端内部是 uni-app 一份代码同时跑 Web 和小程序,不再细分运行环境。

#### 3 步决策

1. **要不要在移动端操作?** 否 → **Web**
2. **需不需要拍照/扫码/定位?** 是 → **移动端**(uni-app 1 份代码出 2 端)
3. **平台能力差异怎么办?** 在该条末尾括号写降级方案,如 `Web 端降级为下拉选择`

#### 标注示例

```
M1-1 隐患上报
  核心功能点:
  - [移动端] 扫码定位(支持管理单元选择,Web 端降级为下拉选择)
  - [移动端] 拍照 3 张+视频(Web 端降级为文件选择,最多 3 张)
  - [移动端] 选类型/等级
  - [移动端] 描述+建议整改期限
  - [移动端] 提交
  子功能级平台:移动端
```

## 模块清单

### 总体颗粒度

- **4 个一级模块**(M1-M4),沿用 §1 划分,**不变**
- **MVP 29 个子功能** 展开为 **~85 个核心功能点**(平均每个子功能 3 个点)
- **P0(必须做)**:8 个核心功能点群,涉及所有 4 个模块
- **P1(应该做)**:大部分菜单可见页面 + 监管方功能
- **P2(延后)**:v2 增强项 + 平台运营管理配置

### 模块依赖关系

```
M3 制度与计划 ──生成排查任务──→ M1 隐患排查(发现)
                                       │
                                       ▼
                                M2 隐患整改(闭环)
                                       │
                                       ▼
                                M4 报表与统计(月/年报 + 监管报送)
                                       │
                                       ▼
                                  监管方/平台

横向依赖:
- M1 流程接入:火灾隐患排查上报流程模板(已有流程模板01)
- M2 流程接入:火灾隐患整改处置流程模板(已有流程模板02)
- M4 依赖 M1/M2 数据(写报表/看板)
- 全模块依赖平台四方权限(消防安全责任人/消防安全管理人/巡查员/维保工程师/安全监管员)
- 跨场景(消防/安全生产)复用同一套模块结构,§1 边界声明已确认
```
