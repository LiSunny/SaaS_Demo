## 一、产品定位

### 1.1 一句话定位

**为多业态经营单位的隐患管理提供覆盖排查→整改→验收→销号→督办→报表全场景的闭环能力,系统自动按法规调度、不依赖人盯不靠 Excel 记,让消防安全管理人省出时间处理真正难的问题。**

### 1.2 三大产品边界(详见 §3.1 范围切分)

| 维度 | 在做 | 不做 |
|---|---|---|
| 业务范围 | 隐患全生命周期(制度、排查、整改、报表) | AI 自动识别、跨企业分派、视频证据 |
| 用户范围 | 社会单位/服务机构/监管机构/运营管理四类 | 终端消费者、政府执法处罚 |
| 法规范围 | 国家法律 ★★★ + 部门规章 ★★ + 地方法规 ★ + 推荐国标 ★ | 团体/企业标准(留行业插件扩展) |

### 1.3 与平台其他模块的边界切割

| 与谁 | 关系 | 说明 |
|---|---|---|
| 巡查检查(同分组) | 上游 | 巡查任务是入口之一,但隐患独立存在(可任意渠道上报) |
| 设备管理(M7 故障隐患) | 关联 | 设备异常被判定为安全风险时进入本域,字段复用 |
| 危险作业(动火) | 关联 | 动火作业中的隐患进入本域闭环 |
| 协同管理(工单) | 承载 | 流程由 fire-hazard-report / fire-hazard-rectify 模板承载 |
| 监控与值守 | 不混合 | 告警/事件处置不进入本域 |
| 数据可视化/工作台 | 下游 | 提供统计、待办入口,不重复功能 |
| 平台运营管理 | 配置 | 制度模板、SLA、字段字典由平台运营配置,**不归本域** |

## 二、核心用户与价值

### 2.1 五种四方角色

| 角色 | 所属方 | 一句话职责 | 使用端 | 频次 |
|---|---|---|---|---|
| **消防安全责任人** | 社会单位 | 法定负责人,大屏查看闭环率、签发月报 | Web | 每日查看 |
| **消防安全管理人** | 社会单位 | 日常管理,审核分派、组织验收、签发月报 | Web | 每日高频 |
| **消控值班员 / 巡查员** | 社会单位 | 自查上报、紧急工单、接收整改通知、上传对比照片 | PC + 移动端 | 每日连续 |
| **维保工程师** | 服务机构 | 接收被指派整改任务、现场整改、上传证据 | 移动端 | 按合同 |
| **安全监管员** | 监管机构 | 查看辖区闭环率、超期清单、督办建议 | Web | 每日查看 |

> **脚注 1** :本域"巡查员"实际包含两个子场景 — **物业巡查员**(社会单位内部,负责自查上报)和 **商户员工**(商户侧,负责接收整改通知 + 拍对比照)。两者使用同一移动端入口但权限边界不同:物业巡查员看本企业全量台账,商户员工仅可见本商户点位的整改任务。后续 §2 单独评审时再决定是否拆为独立角色。

## 三、模块全景(4 个模块)

### 3.1 范围切分(做/不做/延后)

> 从原 §1.4 迁出,与"产品定位"主题分离,放在模块全景章节作铺垫。

| # | 必做(MVP) | 不做 | 延后(v2) |
|---|---|---|---|
| 1 | 隐患全生命周期闭环 | AI 自动识别(图片→类型/等级) | 举报奖励发放 |
| 2 | 重大隐患挂牌督办 + 五定 + 销号 | 智慧消防告警自动隐患 | 第三方评估机构对接 |

## 四、关键业务流程

> 本章用 mermaid 画图(按你 memory 偏好:图表一律 mermaid,节点文本禁英文双引号)。

### 4.1 主流程 — 隐患全闭环(从发现到销号)

```mermaid
flowchart TD
    Start([巡查员到店/员工自查/举报]) --> M3Exec[执行排查任务 M3-3]
    M3Exec -->|发现隐患| M1Report[隐患上报 M1-1]
    M1Report -->|提交| Judge{重大隐患? 判定助手 M1-2}

    Judge -->|否 一般| Review[安全员审核 M1-3]
    Judge -->|是 重大| HeavyReview[消防安全管理人审批 自动加抄送责任人]

    Review --> Assign[分派:责任人+期限 M1-4 详情]
    HeavyReview --> HeavyAssign[五定方案 M1-6 临时管控 M1-7 内部公示 M1-8]

    Assign --> M2Rect[整改执行 M2-1 前后对比 M2-2]
    HeavyAssign --> M2Rect

    M2Rect --> M2Verify{验收 M2-3}
    M2Verify -->|不通过| M2Rect
    M2Verify -->|通过 一般| Closed[已闭环]
    M2Verify -->|通过 重大| Evaluate{自评/委托? M2-4 销号}
    Evaluate --> Closed

    Closed --> End([结束])
```

**关键节点说明**:

| 节点 | 处理人 | 时限 | 法规依据 |
|---|---|---|---|
| 隐患上报 | 任意员工 | 即时 | R-03 ★★ §3 |
| 审核定级 | 安全员 | 4h | F-03 ★★ |
| 分派 | 消防安全管理人 | 1d | F-03 ★★ |
| 五定方案(仅重大) | 消防安全管理人 | 1d | F-16 ★ |
| 内部公示(仅重大) | 系统自动 | 即时 | F-13 ★★★ |
| 整改执行 | 责任人 | 期限由分派定 | F-19 ★ |
| 验收 | 部门负责人 | 1d | F-19 ★ |
| 销号(仅重大) | 消防安全管理人 | 自评/委托评估 | F-20 ★★ |

### 4.2 异常流程

```mermaid
flowchart TD
    Normal[主流程进行中] --> OverdueCheck{超期检查 每 N 小时触发}

    OverdueCheck -->|未超期| Normal
    OverdueCheck -->|已超期| RedFlag[隐患标红 看板亮红 推送整改责任人+消防安全管理人]

    RedFlag --> Supervisor[监管方看到超期清单 M2-8]
    Supervisor --> SuperviseAction{监管动作}
    SuperviseAction -->|督办建议| NotifyOwner[通知企业消防安全管理人]
    SuperviseAction -->|挂牌督办| Mark[挂牌标记 F-23]

    Normal --> VerifyReject{验收不通过}
    VerifyReject -->|退回| Retry[回到整改执行 M2-1 重新计时]

    Normal --> DupReport{同一位置 N 天内重复上报?}
    DupReport -->|否| NewOne[新隐患工单]
    DupReport -->|是| Hint[提示「该位置近期有 X 条类似记录」 不合并 人工判断]

    Normal --> Aggravate{整改期间 隐患恶化?}
    Aggravate -->|是| FireEvent[转入火警事件处置流程 隐患工单挂起]

    Normal --> Resign{整改责任人 离职/不可用?}
    Resign -->|是| Reassign[改派 M2-1 内置改派按钮 安全员指定新责任人]

    RedFlag -.->|超期 N 天仍未动| Escalate[升级 推送消防安全责任人]
```

**异常覆盖**:
- **超期** — 系统自动检测、自动亮红、自动通知(不依赖人)
- **验收不通过** — 退回整改环节,重新计时
- **重复上报** — 不合并,只提示(避免系统误判)
- **隐患恶化** — 转入火警事件处置流程
- **责任人不可用** — 支持改派
- **监管督办** — 单独流程,F-23 挂牌标记

### 4.3 状态机

#### 4.3.1 隐患状态机

```mermaid
stateDiagram-v2
    [*] --> 待审核 : 上报
    待审核 --> 已分派 : 一般隐患审核通过
    待审核 --> 待定级 : 待审核(待人工二次确认)
    待审核 --> 已驳回 : 审核驳回
    已驳回 --> [*]

    待定级 --> 已分派 : 定级为一般
    待定级 --> 重大公示 : 定级为重大(自动触发内部公示)

    已分派 --> 整改中 : 责任人接单
    重大公示 --> 整改中 : 五定方案确认 + 责任人接单

    整改中 --> 待验收 : 整改人提交
    整改中 --> 超期未整改 : 期限到达
    超期未整改 --> 整改中 : 责任人补交整改

    待验收 --> 整改中 : 验收不通过
    待验收 --> 已闭环 : 一般隐患验收通过
    待验收 --> 待销号 : 重大隐患验收通过

    待销号 --> 已闭环 : 销号完成(自评/委托评估)
    待销号 --> 整改中 : 评估不通过,重整

    已闭环 --> [*]
```

**状态数 = 10**:待审核、待定级、已驳回、已分派、重大公示、整改中、超期未整改、待验收、待销号、已闭环。

stateDiagram-v2
